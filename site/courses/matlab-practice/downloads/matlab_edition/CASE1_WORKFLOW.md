## 先看全程｜從感測資料到一份說得清楚的分類報告

### 這個案例要完成什麼？

我們用虛構設備的溫度、振動與電流，判斷設備是「正常」還是「需要檢查」。你要走完的流程是：看懂資料 → 分開練習與測試資料 → 訓練一個分類模型 → 檢查判斷結果 → 把做法與證據整理成報告。

本案例是「助教實作方式」。正式題一從題目列出的四個資料集中選一個，選用一種分類方法，以 80% 訓練、20% 測試，並以測試正確率 90% 為目標。以下先用合成設備資料練習完整流程，再將方法帶回自己選的正式資料。

### 從頭到尾，依序做這 8 件事

1. **先備妥檔案，確認程式從哪裡執行。** 把教材解壓縮，進入 `matlab_edition`，開啟 `case1_sensor_classifier_matlab.m`。先讀以下段落，再依後面的四階段提示詞逐步建立自己的版本。完整參考版可在 Command Window 輸入 `s = case1_sensor_classifier_matlab;`。產物放在 `matlab_artifacts/case1`；每次重跑會更新同名範例輸出。
2. **先說清楚，一列資料代表什麼。** 打開 `synthetic_sensor_data.csv`，確認一列是一台虛構設備，總共 240 筆；`deviceID` 是識別碼，溫度、振動與電流是用來判斷的三個特徵，`label` 是已知答案。用自己的話寫下「我要判斷什麼、靠哪些資訊判斷」，這就是報告分析邏輯的起點。
3. **選出特徵，說明選擇理由。** 本例使用三個感測數值，識別碼用來追蹤資料，答案欄用來訓練與核對。報告要交代每個特徵的意思，以及它和分類問題的關係；換成正式資料時，重新確認欄位、單位、缺值與答案定義。
4. **先分好資料，再準備模型的輸入。** 程式依類別分層，取 192 筆訓練、48 筆測試。只用訓練資料算平均值與標準差，再用同一組數值轉換測試資料。到 `summary.json` 核對筆數、比例、`trainIDs`、`testIDs` 與 `trainTestOverlap`；交集應為空。這一步就像先把練習題和最後要考的題目分開。
5. **用訓練資料，讓一個模型學會分類。** 本例採教學用簡化羅吉斯分類器，依三個特徵調整權重，產生判為「需要檢查」的模型估計，再依門檻轉成類別。閱讀訓練段落時，弄清楚特徵、答案、權重各自扮演的角色；把選用這個方法的理由寫進分析邏輯。
6. **拿測試資料驗算，找出模型判錯的地方。** 打開 `test_predictions.csv`，逐筆對照真實答案與預測；再看 `summary.json` 的正確率、混淆矩陣與正類召回率。本機參考結果為正確率 93.75%，需檢查設備找出 2／4 筆、召回率 50%。報告同時呈現兩者，說明整體答對比例與漏判情況；自己的報告填入自己實際跑出的數字。
7. **把過程留下來，讓別人能跟著核對。** 保存程式、資料、摘要與預測檔，截取特徵選取、80／20 切分、訓練及測試結果的相關程式畫面。可執行 `run_matlab_tests` 檢查教材參考版；自己改過的程式，另核對欄位、資料切分與結果是否對得起來。
8. **依正式題目的四個部分組成 PDF。** 依序寫「分析邏輯、特徵選取、程式碼截圖、測試結果」，可用 `CASE1_REPORT_TEMPLATE.md` 作為整理骨架。90% 是目標，結果照實呈現，並說明表現與可改善處。最後開啟匯出的 PDF，確認圖片清楚、數字與輸出檔一致，再依課程指定方式交件；正式資料與繳交管道以題目及課務公告為準。

### 做完時，你手上應該有什麼？

- 練習過程：一支能執行的 `.m`、合成資料 CSV、逐筆預測 CSV、`summary.json`。
- 報告證據：特徵選擇理由、80／20 切分說明、程式截圖、真實測試結果與錯誤解讀。
- 正式交件：以自己選定的正式資料完成上述流程，再整理成題目指定的四部分 PDF。合成練習檔保留作為方法參考。
