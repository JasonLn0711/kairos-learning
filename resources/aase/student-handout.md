# 10 小時工作坊｜學員手冊

你將建立本機、單人、使用合成資料的收件完整性檢核原型。三個必要欄位為申請編號、申請人代號與文件類型；完整只代表本課欄位規則通過，不代表正式受理。

先閱讀四篇先導教材，再將 templates/ 的工作表複製到 starter/。和同儕確認問題及規格後，才請 Agent 實作。reference/ 是教師參考解答，先完成自己的嘗試再比較。

## 課前檢查

能在本機開啟編輯器、終端機及瀏覽器；依 README 安裝套件並啟動 starter/app.py。選定一種已由教師實測的 Coding Agent，確認費用、帳號及工具權限。沒有可用 Agent 時，可和同儕共用教師示範，自己仍完成需求、規格、審查及驗收；這個替代安排不算個人 Agent 操作通過。

## 三次垂直切片

1. 表單：依 spec.md 建立三欄與檢查按鈕。用鍵盤完成輸入，先核對標籤及畫面。保留這次 Diff 與觀察。
2. 規則：把必要欄位與空白檢查寫成獨立函式。先寫缺漏測試，確認測試確實失敗，再實作至通過；不要刪掉失敗測試來取得綠燈。
3. 預覽及匯出：完整時顯示預覽，匯出前重驗證；輸入變更使舊結果失效。先完成、再清空欄位，確認舊完整報告不能繼續匯出。

每次請 Agent 說明修改範圍與真實命令結果。人類決定欄位規則，核對 Diff 並按同一個情境重演。不得將真實案件、病歷、員工資料、秘密或正式帳號交給練習。

## 同儕任務

給另一人一筆缺少文件類型的合成資料，請他確認能否交接、修正後匯出。先不指點，記錄卡住位置、誤解與是否保留輸入。再讓他在完整之後刪除一欄，觀察是否知道要重新檢查。記錄現象，提出一個修改假設並重試。

## 交接

交付 problem.md、四狀態 wireframe.svg、spec.md、architecture.md、app.py、tests/、README.md 與 Git 紀錄。README 必須讓同儕從乾淨環境啟動；測試紀錄寫實際版本、命令、結果及未驗證項目。使用整合評量六題說明你的取捨。沒有實作的多人授權需求，保持待實作。

## 卡關時使用階段快照

依 [切片指南](slices/README.md) 在獨立目錄啟動第一、第二階段，再與自己的程式比較。第三階段在 reference/。先指出哪一條驗收情境失敗、保留目前 Diff，再決定最小修改；不要用整份參考解答覆蓋作品或把看過解答記成完成實作。
