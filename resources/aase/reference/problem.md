# 合成收件完整性檢核｜參考問題陳述

角色為收件人員，工作時機為資料交接前。教學假設是人工核對可能漏看必要欄位；這不是實際機關訪談發現。

As-Is：填寫 → 人工核對 → 交接。To-Be：填寫 → 系統檢核 → 補齊 → 預覽 → 匯出。

第一版確認申請編號、申請人代號與文件類型是否齊全，缺漏時指出欄位並阻擋完整匯出。功能證據是完整、缺漏、空白及輸入修改案例；任務證據是同儕能否自行找出缺漏並修正。尚未測量節省時間或減少補件。

不做正式受理、真實資料、多人帳號與正式部署。若要多人共用，先訪談角色、資料授權及保存需求，再規劃架構。待確認問題包括規則負責人及實際補件原因。初稿日期：2026-11-05。
