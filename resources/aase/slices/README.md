# 三次垂直切片｜教師檢查點

每個切片都讓一項使用者任務從畫面走到可觀察結果。這些快照供示範、比較及卡關時定位，學員仍需依自己的 problem.md、spec.md 實作與審查。參考程式通過測試不代表學員或指定品牌 Agent 已完成實作。

| 階段 | 程式位置 | 可觀察結果 | 尚未實作 |
| --- | --- | --- | --- |
| 一：建立表單 | slices/01-form/ | 三個具名稱的欄位、查看本次輸入；明示未檢核 | 完整性規則、完整狀態、報告與下載 |
| 二：資料檢核 | slices/02-validation/ | 獨立 rules.py、缺漏提示、保留已填資料、重新檢查 | 報告預覽與匯出 |
| 三：預覽與匯出 | reference/ | 目前輸入快照、輸入變更失效、匯出重新驗證及欄位白名單 | 帳號、多人授權、持久儲存與正式部署 |

## 執行方式

先依根目錄 README 建立及啟用虛擬環境、安裝 requirements.txt。從解壓後的根目錄選擇一個階段；以下先執行切片一：

```sh
cd slices/01-form
python -m pytest -q
python -m streamlit run app.py --server.address 127.0.0.1
```

瀏覽器開啟終端機顯示的本機網址，Ctrl+C 停止服務。回到解壓後根目錄，再進入 slices/02-validation/，執行相同兩條 python 命令；第三階段改進入 reference/。不要在另一個專案目錄繼續輸入相對路徑。每個階段分開執行 pytest，避免不同目錄同名 rules 模組互相混用。

輸入只用 SYN-001、DEMO-A、「合成申請表」等合成值。三欄去除首尾空白後須非空且不超過 80 字元；畫面字數限制之外，第二階段的規則測試也直接傳入錯誤型別、缺少鍵及超長字串。

## 比較與復原

先保留學員工作目錄及目前 Diff，另建比較用副本；不要把教師目錄直接覆蓋學員作品。對照規格，指出每次新增的行為、尚未交付的範圍及命令實際結果。復原只處理已確認屬於本次切片的變更，保留其他工作；不使用整個目錄的強制重設。

切片一按鈕顯示的是當次未檢核輸入，不能作為完整性證據。切片二的結果隨下一次輸入變更重跑而消失，需重新按檢查；切片三才保存已檢查快照，且只有目前資料與快照相同時顯示下載。

## 每次切片的交接紀錄

記下對應驗收情境、允許修改的檔案、實際命令與退出結果、Diff、觀察結果及尚未處理事項。Agent 的完成摘要與測試輸出分開保存；沒有執行過的命令明確標示未執行。這些資料留在學員專案，不將帳號、金鑰、真實個資或內部文件放進公開教材。
