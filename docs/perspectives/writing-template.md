# 觀點文章企劃與撰稿模板

搭配[文章撰寫與編輯規範](authoring.md)使用。複製本模板建立工作稿，依文章需要調整章節；正文以自然敘事串接問題、原理與證據。

本文件是編輯工作表，網站正式內容由 [JSON 模板](template.json)所示的資料結構承接。含私人材料的工作稿放在忽略的 `.local/`；提交到公開 Git 的工作稿也需完成去識別化。所有空欄依實際資料填寫，待核項目保留於編輯清單。

## 1. 文章企劃

| 項目 | 填寫內容 |
| --- | --- |
| 暫定標題 | 具體問題或讀者收穫 |
| 目標讀者與先備知識 | 誰會閱讀？已經知道什麼？ |
| 原發布日期／目前版本／版本修訂日期 | 保留原發布；版本採 vMAJOR.MINOR.PATCH（如 v1.0.1），修訂日期對應此版本；revision 僅供內部計數 |
| 核心問題 | 本篇集中回答的一個問題 |
| 一句主要主張 | 現有證據支持的判斷 |
| 讀者收穫 | 讀完能解釋、辨認或做到什麼？ |
| 文章形式 | 議題解讀／實作手記／觀點反思 |
| 主題 | 資工／AI／資安等；轉為 JSON 時使用支援的值 |
| 緣起 | 哪個事件、疑問或經驗促成本文？ |
| 事件日期與觀察截止時間 | 註明時區；不同事件分別記錄 |
| 預定發布日期 | 排程意圖；正式上線後另記實際結果 |
| 作者與協作者 | 編輯工作紀錄依實際分工填寫；公開 author 僅填作者或品牌名稱，遵循 WRITE-07 |
| 相關教材 | 連結與關聯原因；轉為 JSON 時核對有效 ID |

讀者目標句：這篇文章要幫助＿＿＿讀者，理解＿＿＿問題，並能夠＿＿＿。

## 4. 中文工作稿

以下提示可依文章需要合併、改名或調整順序。

### 標題與摘要

標題：＿＿＿。

摘要：用數句交代情境、核心問題與讀者收穫。

### 緣起與問題

交代事件、讀者需要理解的問題及必要背景。保留影響判斷的時間與環境。

### 白話原理

先解釋用途，再介紹術語與運作方式。用一個具體例子連接概念；比喻後接回實際機制。

### 處理過程與判斷

寫出當時掌握的資訊、選擇理由、查證步驟及觀察結果。來源放在它支持的說法附近。

操作區塊另填：環境與先備條件、讀取或修改的對象、命令、預期輸出、判讀方式，以及適用時的清理或還原方式。標示內容是實測、推演或合成示例。

### 結果與下一步

交代已確認的結果、能帶走的理解，以及接下來可以檢查或練習的事項。尚在處理的案例註明觀察截止時間與下一個驗證步驟。

### 圖表與延伸閱讀

每項列出用途、所在章節、來源及文字說明。圖表確認手機閱讀與必要的替代文字；延伸閱讀說明與本文的關係。

## 5. 英文工作稿與對照

完成可獨立閱讀的英文標題、摘要與正文。沿用中文的章節 ID 與順序，採自然英文表達。

- [ ] 兩種語言都完整回答核心問題。
- [ ] 數字、單位、日期、版本、識別字、命令與來源一致。
- [ ] 適用條件、推論程度、驗收結果與下一步一致。
- [ ] 術語首次說明清楚，署名符合實際分工。
