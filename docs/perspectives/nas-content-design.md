## 從第一原理確立文章主張

讀者的需求是共同使用資料，同時保有可控制的存取及可驗證的復原能力。依序回答四個問題：誰能連到 NAS、連線後可以做什麼、系統與端點有哪些風險、資料受損後如何還原。

主要問題：NAS 暫停連線後，如何有依據地安排檢查與恢復服務？主要主張：把連線範圍、帳號權限、修補及資料復原分開檢查，再用驗收結果決定復線範圍。

以「NAS 已經斷網，接下來該確認什麼？」延續既有觀點選題；原稿標題作為教學來源標題保留。情境以去識別化回報引入，原稿的 DS925+、IP 與共享目錄均按示例處理；實機型號、完整版本及處置結果另由管理者核對。

正文先用白話說明每個角色，再將細節放進圖解。`smb://192.168.1.20/Research` 可作合成範例，旁註其位址與目錄為示意。圖中的研究資料種類維持一般分類，避免引入真實醫療或個人資料。

文章收尾保留理解檢查：「NAS 已更新且沒有公開的入站入口，受感染的使用者電腦為何仍可能改寫共享檔案？請選一項對應措施並說明保護的環節。」參考答案說明可寫入權限、端點防護、權限縮減與獨立復原各自作用；不宣稱單一措施涵蓋所有風險。

## 視覺與實作契約

- 白底、細邊框、圓角與足夠留白；藍色表達使用者／服務、青綠表達允許路徑、橘色表達待確認條件、紅色表達中斷／影響、紫色表達資料／復原角色。每個狀態同時有文字或符號，顏色不單獨傳達意義。
- HTML 提供節點標題、說明及圖說；CSS 管理並排與上下重排；SVG 提供設備圖示與必要連線。核心內容直接可見，無 JavaScript 仍可閱讀。
- 靜態圖不增加拖曳、縮放或點擊假互動。下載連結有明確名稱與可見焦點；補充答案如採原生 details，使用鍵盤可以開關。
- 原稿圖形是參考，網站版優先讓文字換行和手機重排。每張獨立 SVG 保留 viewBox、title、desc，大小小於 100000 bytes；下載版與可見 HTML 的節點、條件、方向和圖說語意一致。
- 現行 Perspective 章節模型沒有圖解欄位。實作時同步擴充型別、驗證器、搜尋文字、渲染及測試，沿用受審核圖解邊界；不以任意 HTML 或未審核 SVG 注入繞過內容驗證。
- 中英共用穩定章節及圖 ID，技術條件一致。新的 SVG ID 需包含文章、圖及語言識別，避免多圖 marker 或標題 ID 衝突。
