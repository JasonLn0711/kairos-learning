# 差距與優先順序

P0 表示進入下一個實作階段之前須解決的設計問題，P1 用於垂直切片驗收，P2 用於細節調整。每列的字母與步驟都對應 [稽核紀錄](01-reference-audit.md) 及本機 manifest。功能正確性的判定另有依據。

| ID | 參考證據 | 本站證據 | 可核對的差異 | 學員影響 | 優先 | 負責元件 | 修正方向 | 驗收測試 |
|---|---|---|---|---|---|---|---|---|
| V1 角色輪廓 | B1 筆電、A5 人群、圓柱與藍色設備 | C1 舞臺與 InteractiveStage 的 entity-top/left/right | C 的五個角色共用機箱與底座，只換頂面符號或標籤 | 要先讀文字才能辨認發起者 | P0 | InteractiveStage、geometry | 建立原創人物、筆電、設備、資料庫和各自邊界 | 隱藏名稱，以實際桌面及 320 寬尺寸辨認角色；檢查路徑起訖 |
| V2 鏡頭 | B1 單一角色，B5 四個，viewBox 寬約 583→697 | C1 至 C10 外框寬 640 SVG units，C1 已有五個角色 | 第一個動作與後續依賴同時佔據視野 | 起點與當步參與者不易區分 | P0 | InteractiveStage、geometry | 依步驟選參與者並穩定銜接鏡頭 | 同尺寸疊比第一、中間、總結步，檢查文字與封包全程可見 |
| P1 數學關係 | B5 以標註邊呈現依賴；外站沒有本課公式 | E1、E3，LearningStage | E1 的 777×665 px 舞臺主要為兩張值卡，E3 才顯示權重與合成值 | 很難沿圖追蹤分數、權重、乘積與結果 | P0 | LearningStage | 以相同尺度連接權重、值、貢獻 | 以 1、0 得約 3.076，再以 0、0 得 4，逐項比對文字、圖形及原公式 |
| P2 停止語意 | A6 顯示失敗並保留可用節點 | F1–3、aase/simulations | F1 的格式與授權以兩張並排文字卡開始；後續階段與停止位置未在同一底圖持續標識 | 容易把授權與執行、執行與驗收混為一談 | P1 | LearningStage、PolicyStage | 用順序與文字區別失敗、跳過及執行成功 | 切換每一關，核對第一個停止點、後續未執行與原始題意 |
| V3 動作可達性 | A/B 的 320 寬截圖在首屏看得到底部下一步 | C 的 320 寬控制區高 128 px，位於圖面後方 | C 首屏可見選單與部分圖面，下一步在下方 | 單手逐步閱讀需要捲動 | P1 | ImmersiveShell | 測試緊湊換步方式，保留閱讀順序與完整解說 | 320、390 寬、放大文字與鍵盤操作，確認控制不遮住最後一段 |
| V4 訊息辨讀 | A5 重播序列顯示小型彩色訊息沿折線移動，圖例解釋用途 | C 的 packet 為半徑 11 的 halo 配菱形或鎖形，來源碼含 marker 與方向 | C 讓封包隨全圖縮放，單一角色共享同樣連接外框 | 小螢幕較難辨讀傳輸種類和返程 | P1 | InteractiveStage、geometry | 依角色接點放置箭頭，維持封包與底圖對比 | 逐格核對快取命中不走 DNS 往返、慢查詢延長等待、回應返向 |
| V5 寬桌面比例 | A 在 1920 寬的 SVG 寬 1182 px | C 的 SVG 寬 867 px，main 有 1600 px 上限 | 可畫寬度相差 315 px | 寬螢幕的密集拓樸仍擠在中央 | P2 | ImmersiveShell | 以角色最終大小決定最大舞臺寬 | 同時檢查 1920 與 1280 的標籤、內文行長及控制可達性 |
| F1 閱讀與狀態 | B 的側欄隨步驟更新，第一步 Back 停用 | C/E/F 完整解說可開關，Escape 回到按鈕；C 另有 role=status | 說明、來源與動態狀態分屬不同區域 | 更換外框時可能失去閱讀位置或狀態通知 | P1 | ImmersiveShell、InteractiveLesson、AaseConceptLearning | 保留焦點回復、語系及無 JS 來源閱讀 | 雙語長文、鍵盤開關、停用 JS、螢幕閱讀器回讀 |

V 表示視覺或操作差距，P 表示教學表達，F 表示既有功能的遷移風險。40/120 的內容數及歷史 Chromium 通過紀錄均無法判定以上的視覺驗收結果。
