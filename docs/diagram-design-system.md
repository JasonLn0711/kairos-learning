# 原生網頁教學圖解設計規範

適用所有觀點與教學文章。依[全站文章規範](article-standards.md)的 FIG-01–06、INT-01、HTML-01–04、A11Y-01–03 執行。NAS 範例的[正式資料](../content/perspectives/nas-cve-patching.json)與[驗收回執](releases/2026-11-01-nas-memory-foundations.md)連接內容、元件及下載檔。

## 先畫清楚關係，再安排版面

提供截圖時，先列出標題、分組、節點、資料格、連線起訖與線型意義。以程式碼重製這些可教學的關係，盡量保留原有卡片比例、配色、留白及層次；字型渲染及手機重排可以不同。交付時具體記錄差異，不以「已做成 SVG」代替視覺驗收。

- 位址、內容、使用權使用不同文字欄位。地址只是位置標籤，不用同一個數字暗示跨 Process 共用實體頁面。
- 同一 Process 內重用與不同 Process 隔離，必須在圖說及分組中明確區分。
- 實線流程箭頭表示順序或指定呼叫；虛線必須在圖說中定義，例如「按需跨層管理」或「已失效參照」。不能把每種箭頭都解讀成封包流量或必然發生的下一步。
- 顏色搭配文字：藍色為配置／使用，橘色為釋放或待處理狀態，綠色為新用途／核心管理，紅色為失效參照。狀態以標題、標籤與線型辨識，不只靠顏色。
- ABC → XYZ 是覆寫示意；釋放後的 ABC 不保證保留。不得用讀取已釋放記憶體證明示意圖，也不得宣稱新配置必定取得原位址。

## 可重用版型與資料契約

使用既有 `TeachingDiagram` 模型，`layout` 省略時保留原有流程與分類卡。新增以下受限版型，由 [StructuredDiagram.svelte](../src/lib/components/StructuredDiagram.svelte)產生 HTML，由 [structured-diagram-svg.ts](../src/lib/structured-diagram-svg.ts)匯出相同資料的 SVG。

| layout | 結構 | 桌面 | 窄欄 |
| --- | --- | --- | --- |
| `cells` | 一組四個位址節點，每節點一個 cells 值 | 四格並排；位址、數值、字元解讀分開 | 兩格或單格，保留位址順序 |
| `stages` | 一組三階段，每節點三個 cells 值 | 三張卡片與向右箭頭；released 格用虛線 | 三階段上下排列，箭頭轉向下 |
| `layers` | 上層兩節點、下層一節點 | 使用者空間兩卡；核心空間單卡，虛線跨層 | 上層兩卡也改上下排列 |
| `lifetime` | 前後兩組各三節點；指標／記憶體各一個 cells 值，第三節點為狀態；僅後組記憶體標 released | 兩個色塊區，每區指標 → 記憶體＋狀態標籤；後組箭頭與目標框為虛線 | 各區上下排列，狀態標籤不另接箭頭 |
| `access-path` | 上組三節點流程、下組一張管理說明卡 | Pointer → CPU／MMU → RAM，下方配置器以無箭頭虛線連結責任 | 存取路徑上下排列，下方管理說明獨立呈現 |
| `reference` | 指標、目標、錯誤說明三節點 | 指標及說明在左，目標在右，紅色虛線連接 | 按指標、目標、錯誤說明順序閱讀 |

節點保留 `title`、`body`、受審核 `icon`／`tone`；可加 `cells: string[]`（1–4 個、每個最多 8 字元）與 `state: "released"`。cells 僅供 cells／stages／lifetime 版型使用，released 僅供 stages／lifetime 使用；各版型的格數仍依上表限制。cells 承接數值、ASCII 字元等技術標記，兩語相同；解說放在可翻譯的 body。模型不接受任意 HTML、SVG path、CSS、外部圖片或事件處理器。驗證器檢查版型列舉、節點數、cells 結構、釋放狀態及雙語一致性；新需求先擴充受審核模型與測試，不能繞過驗證。

## 排版與文字

1. 正文與圖中文字使用可選取的 HTML；圖說、解說、閱讀順序在無 JavaScript 下仍成立。
2. 桌面忠於原圖的比較與分層；以圖容器寬度判斷重排，不用螢幕尺寸假設文章欄寬。現有版型在容器 620px 以上使用橫排，340px 以下的記憶體格改單欄。
3. HTML 解說至少 16 CSS px，行高至少 1.7；數值可較大。卡片高度隨文字延伸，英文與 200% 文字不裁切；不靠縮小整張圖達成手機驗收。
4. 使用圓角、低彩度底色、可辨識邊框及足夠留白。長圖可以垂直延伸，整頁不能水平溢出。表格與程式碼保留具名稱、可鍵盤捲動的局部容器。
5. 裝飾箭頭不重複朗讀；圖說提供無障礙名稱。cells 的讀出值與顯示值一致，沒有把數值只烘焙成圖片。

## SVG 與驗收

- HTML、搜尋文字、SVG 下載共用正式資料，不手改生成 SVG。完成變更後執行 `npm run generate:perspective-diagrams`。
- 獨立 SVG 保留桌面幾何配置、相同資料格及虛線語意，包含 viewBox、title、desc；每檔小於 100000 bytes。換行由匯出器依卡片寬度計算，驗證文字在 viewBox 內且沒有互相遮蓋。
- 在 320、390、768、1280 CSS px 檢查中英文；另驗 200% 文字與關閉 JavaScript。目視桌面與手機截圖，逐一確認格數、數值、箭頭、分層與釋放狀態。
- 真正以 Tab／Shift+Tab／Enter 驗證下載與焦點；Space 僅在有對應控制時驗收。鍵盤可捲動程式碼與寬表格。
- SVG 必須與產生器逐位元組相符；正式站下載再核對檔案。發布邊界重建與瀏覽器測試依序執行，避免測到暫時被清除的 build。
- 記錄實測平台、URL、版本、結果與證據。瀏覽器模擬、實體手機與完整螢幕閱讀器分別記錄。

## 可執行程式範例

C／C++ 記憶體範例必須先檢查配置成功、先初始化再讀取、在有效生命週期內使用並釋放。使用合成資料，不用未定義行為展示舊資料殘留。說明環境、編譯及執行命令、預期輸出、錯誤碼與清理方式；實際執行平台與未驗平台分開。`calloc()` 的位元組清零，不自動代表任意物件已完成語意初始化；重設一個指標不會同步修正其他別名。

補充新教學範圍依 WRITE-06 升 minor；只有排版／閱讀修正則升 patch。保留原發布日，維護版本修訂日與雙語更新紀錄，署名遵循 WRITE-07。

## 指標與硬體權限圖的補充規則

- 「指標變數存在」「位址位元可能殘留」「語言允許使用該指標值」「硬體允許某次存取」分別表達。free 不自動把呼叫端變數設為 NULL，也不代表釋放後的舊值可合法讀取、比較或解參考。
- `0x1000*`、`ABC?` 必須明示為概念標籤與可能殘留，不是讀取已釋放資料的實測輸出；after-state 恰有一個 released 目標。
- 狀態徽章不接成下一步資料流；配置器與 MMU 的責任連線用無箭頭虛線，解釋其非逐次存取查詢。一般頁面權限、配置區塊生命週期及特殊偵測工具分別交代。
- C 別名範例先檢查配置成功；釋放後直接賦予 NULL 等新值，不列印或比較舊指標，不藉「未崩潰」證明安全。完整範例、理解題與實際執行紀錄分開標示。

參考實作與驗收：[free 與 MMU 教學回執](releases/2026-11-01-nas-pointer-lifetime.md)。

## M02-06 網路圖解與互動準則

依 2026-11-03 [採納原文](article-standards.md#m02-06-設計採納fig-06int-01)，以下模式供各類教學選用。前述記憶體配色屬該領域語意；網路圖與其他主題應另定一致的角色配色，搭配文字及線型，不將橘色一律解讀為釋放。

### 讓版型表達教學關係

| 參考範例 | 可重用設計 | 編輯核對 |
| --- | --- | --- |
| 圖 2：位元結構 | 將整體拆成數值格，再以群組與文字標明固定部分、可變部分；公式緊接圖解。 | 192.0.2.25/24 的前三組共 24 bits，最後一組 8 bits；說明其他前綴不一定落在八位元邊界。重排後仍可辨識兩個群組。 |
| 圖 3：實驗室內部網路 | 外框標出網段邊界；同層設備並列，共同連至閘道，再通往外部。 | 手機上下排列仍保留「平行設備」語意，不畫成設備彼此依序轉送；內部網段與外部服務分組清楚。 |
| 圖 4：封包轉送與 BGP 公告 | 同圖區分資料傳送與可達性公告，以標籤、實／虛線和箭頭方向交代。 | 此例封包向下、公告向上；這是圖中情境，不推廣為所有 BGP 路徑。圖說明示簡化範圍。 |
| 圖 5：DNS、CDN 與 Origin | 查詢／回覆與 HTTPS 傳送分開；回源連線旁直接寫觸發條件。 | DNS 不畫成內容傳送的中繼站；快取命中可由 CDN 回覆；入口 IP 不直接證明 Origin 位置。 |
| CIDR 網段模擬器 | 固定案例，改變一個參數，同步顯示所屬網段、總位址數、範圍與公式。 | 結果能由表格或程式範例核對；標示總位址數，不誤稱可用主機數。 |

圖說交代讀者要看什麼，節點呈現角色與值，連線旁說明動作或條件，圖尾保留簡化假設與判讀界線。正文解釋原理與例外；圖解協助閱讀，不能代替完整教學。

### 技術與視覺實作

- 優先復用現有 Svelte 元件、語意 HTML、CSS Grid 與容器查詢；文字可選取、搜尋及換行。SVG 承接箭頭與圖示，獨立下載圖保留同一語意。單張圖不另加框架或繪圖服務。
- 使用低彩度卡片、明確邊框、留白及一致的角色色；重要差異同時以文字、分組或線型表達。節點高度隨內容延伸，圖中文字遵守既有字級與行高規定。
- 以圖容器寬度安排橫排轉直排，同步調整箭頭；保留平行、包含、對照、雙向與條件關係。M02-06 使用 560px、300px 容器斷點作為實作案例，其他版型依文字與關係選擇，不硬套固定斷點。
- 來源資料、HTML、搜尋文字及下載 SVG 同步維護。沿用受限版型、已知路徑、雙語節點順序與 Svelte 文字跳脫；新增領域先檢查現有模型，再補必要的資料契約及驗證，不將 M02-06 專用路徑規則當成通用元件介面。
- SVG 由資料與產生器重建，維持受審核 serializer 邊界、title／desc、viewBox、文字換行及大小限制；不手改生成圖檔。確切檔案與指令見[內容指南](content-authoring.md#m02-06-網路角色圖與-cidr-模擬器)。

### 小型互動的教學契約

互動前說明固定條件、可調參數及觀察目標；操作後在同一區塊呈現結果與推導公式。使用原生控制、可見 label、焦點樣式與適合的動態通知，讓滑鼠、觸控及鍵盤得到相同結果。沒有明確探索問題時，保留靜態圖表即可。

M02-06 的 `CidrExplorer` 固定 IPv4 為 192.0.2.25，僅接受整數 /24–/30；`examplePrefix` 在計算入口拒絕超界與非整數。無 JavaScript 時保留 /24 的完整預設結果並停用控制，旁邊提供表格與 Python 練習。新互動依自己的有效輸入範圍設計，不直接延伸此簡化公式處理任意 IPv4、IPv6 或 /31、/32。

純計算互動明示不修改環境；需要網路請求或其他副作用時另訂功能範圍。不可把拖曳、動畫或顯示答案寫成已完成實驗、通過測驗或掌握技能，也不新增無實際行為的送出、評分與進度按鈕。

### 驗收與證據

沿用 FIG、HTML、A11Y 驗收，另外逐圖核對分組、方向、線型、條件文字及手機閱讀順序。中英文在 320、390、768、1280 CSS px 與 200% 文字下檢查，記錄無 JavaScript 的正文、圖解、下載及預設結果。

互動計算測試涵蓋支援範圍、上下界與非法輸入；鍵盤實測 Tab／Shift+Tab、方向鍵及原生控制支援的 Home／End。M02-06 的七個前綴應逐一核對網段、總數與起訖位址。SVG 檢查文字未超出 viewBox、未遮擋箭頭，並核對下載內容與資料；幾何測試通過後仍需目視圖意。

參考 [M02-06 瀏覽器測試](../tests/browser/m0206.spec.ts)及[修訂回執](releases/2026-11-01-m02-06-network-revision.md)。既有測試與歷史回執提供檢查方法；新文章仍須記錄本次實測結果、未驗項目與正式站回讀，不沿用舊結果宣稱通過。

## AASE M01-03：五面向共同支撐圖

使用者參考圖為五個平行節點→共同母線→共同成果，沒有方向箭頭。沿既有 ConceptVisual cards，items 固定六筆，順序是身分／權限／資料／協作／維護／共同成果；title、body、caption、description 都是同一教材 JSON 的跳脫文字，兩語結構一致，並直接進入搜尋。AASE 驗證器對此課 differences 段限制一個六 item cards；其他 cards、CEH 型別與 SVG 審核邊界保持。

OrganizationDimensions 的桌面為五欄與共同橫線，成果由中央支線連接。容器不超過 42rem（包含文字放大後）時，節點與成果各自連到左側母線；垂直排列仍是共同支撐，不是時序。CSS 偽元素為裝飾，不收任意座標或圖形標記。權限節點採橘底 #b15840／白字，對比約 4.84:1；其他節點灰底、成果淡橘框。英文標題至少 1rem，窄欄完整換行，不省略文字。

此模型本輪沒有新增 SVG 匯出；主要閱讀證據為語意 HTML、相同資料的搜尋文字、四尺寸／200% 文字／無 JavaScript、手機與桌面圖的平行分組及線端目視。原 PNG、完整供稿及版面差異在[來源紀錄](sources/aase/m01-03/replacement-2026-11-06/README.md)，[修訂回執](releases/2026-11-06-aase-m01-03-replacement.md)記錄本機及正式站驗證。

## 補充教材的比例、目錄與條件流程（FIG-04–07）

2026-11-14依 Day02-A 七圖採納，承接[共同規範](article-standards.md#contextual-supplement)。圖解先選關係，再選排版；原圖的配對、層級、方向、框線強調與條件都屬重製範圍，字體及手機重排差異列入回執。以下版型只在符合教學關係時採用，不要求每篇全部配齊。

| 關係／參考 | 可重用呈現 | 必須核對 |
| --- | --- | --- |
| 排名＋比例（四主題配置） | 原生欄名／列名表格，旁附同源比例條；手機每列重排，保留表頭語意、順位、項目、數值與定位。 | 說明比例單位、分母與建議／觀測性質；完整配置合計100%、同順位保持並列。各寬度量測色塊有效寬度，明示間距與容差，數字及圖說不只靠色彩。 |
| 目錄樹（檔案下載範圍） | 根、同層目錄、各自檔案用縮排／巢狀關係與資料夾／檔案圖示表示；圖說明示授權範圍。 | 同層目錄維持同層，檔案不畫成先後流程；長路徑換行仍辨識父子關係。圖示為固定裝飾，語意有可讀文字。 |
| 有條件的四步流程（SQLi／CSRF） | 依時間或因果排列，箭頭方向明確；框線標出原圖特別強調的階段，條件文字留在相關節點。 | 區分可能發生與必然結果；保留查詢權限、Cookie／請求政策等成立條件，框線不當作額外事件或驗證結果。 |
| 雙端訊息（TCP 三向交握） | 桌面左右端點、由上而下時間軸與方向箭頭；手機改為完整訊息列及方向文字。 | 核對每次發送端／接收端與順序；不同顏色另有文字，不把反向封包畫成同向。固定訊息圖與可縮放連線圖依各自模型驗收。 |
| 配對清單（證據判讀問題） | 每列概念與問題成對，窄版每對上下排列。 | 沒有順序關係就不加箭頭；授權等行動前提須明說，不把清單順位變成最後才辦理。 |

### 同源資料、受限匯出與驗收

- 數值、節點文字與語意關係由正式資料及受審核版型共同決定；必要的固定順位、深度或方向須在契約中列明。比例等關鍵值除了型別與節點數，也核對與可讀文字一致；未知名稱、額外標記欄位與節點增減須拒絕。
- HTML、搜尋文字、圖說與 SVG 下載涵蓋相同必要資訊。單語／雙語範圍依文章契約；中文專頁的新增圖不因此建立不存在的英文頁，也不放寬雙語教材。
- SVG 由同源 serializer 生成，文字跳脫，固定元素／屬性白名單，保留 `viewBox`、`title`／`desc`；公開教學圖檔各小於100000 bytes。原始 PNG 原樣保管於來源位置，原圖大小不當作已優化的網頁載入成果。
- 桌面／手機逐圖目視，核對原圖及重製差異；320、390、768、1280 CSS px、200%與無 JS仍可辨識關係。圖中文字可選取／搜尋、行高與字級符合 HTML-02，寬表或程式碼有名稱與局部鍵盤捲動；可原生重排的表格不以橫向裁切處理。
- SVG 幾何檢查包括文字未超出 `viewBox`、未互相遮蓋；目視再檢查文字與箭頭／框線的關係。Tab／Enter實際觸發下載，核對HTTP結果、位元組及大小／SHA；幾何綠燈不能取代圖意或正式站下載驗收。
