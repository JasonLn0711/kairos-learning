# 原生網頁教學圖解設計規範

適用所有觀點與教學文章。依[全站文章規範](article-standards.md)的 FIG-01–05、HTML-01–04、A11Y-01–03 執行。NAS 範例的[正式資料](../content/perspectives/nas-cve-patching.json)與[驗收回執](releases/2026-11-01-nas-memory-foundations.md)連接內容、元件及下載檔。

## 先畫清楚關係，再安排版面

提供截圖時，先列出標題、分組、節點、資料格、連線起訖與線型意義。以程式碼重製這些可教學的關係，盡量保留原有卡片比例、配色、留白及層次；字型渲染及手機重排可以不同。交付時具體記錄差異，不以「已做成 SVG」代替視覺驗收。

- 位址、內容、使用權使用不同文字欄位。地址只是位置標籤，不用同一個數字暗示跨 Process 共用實體頁面。
- 同一 Process 內重用與不同 Process 隔離，必須在圖說及分組中明確區分。
- 實線流程箭頭表示順序或指定呼叫；虛線必須在圖說中定義，例如「按需跨層管理」或「已失效參照」。不能把每種箭頭都解讀成封包流量或必然發生的下一步。
- 顏色搭配文字：藍色為配置／使用，橘色為釋放或待處理狀態，綠色為新用途／核心管理，紅色為失效參照。狀態以標題、標籤與線型辨識，不只靠顏色。
- ABC → XYZ 是覆寫示意；釋放後的 ABC 不保證保留。不得用讀取已釋放記憶體證明示意圖，也不得宣稱新配置必定取得原位址。

## 可重用版型與資料契約

使用既有 `TeachingDiagram` 模型，`layout` 省略時保留原有流程與分類卡。新增以下受限版型，由 [StructuredDiagram.svelte](../src/lib/components/StructuredDiagram.svelte)產生 HTML，由 [structured-diagram-svg.ts](../src/lib/structured-diagram-svg.ts)匯出相同資料的 SVG。

| layout | 結構 | 桌面 | 窄欄 |
| --- | --- | --- | --- |
| `cells` | 一組四個位址節點，每節點一個 cells 值 | 四格並排；位址、數值、字元解讀分開 | 兩格或單格，保留位址順序 |
| `stages` | 一組三階段，每節點三個 cells 值 | 三張卡片與向右箭頭；released 格用虛線 | 三階段上下排列，箭頭轉向下 |
| `layers` | 上層兩節點、下層一節點 | 使用者空間兩卡；核心空間單卡，虛線跨層 | 上層兩卡也改上下排列 |
| `lifetime` | 前後兩組各三節點；指標／記憶體各一個 cells 值，第三節點為狀態；僅後組記憶體標 released | 兩個色塊區，每區指標 → 記憶體＋狀態標籤；後組箭頭與目標框為虛線 | 各區上下排列，狀態標籤不另接箭頭 |
| `access-path` | 上組三節點流程、下組一張管理說明卡 | Pointer → CPU／MMU → RAM，下方配置器以無箭頭虛線連結責任 | 存取路徑上下排列，下方管理說明獨立呈現 |
| `reference` | 指標、目標、錯誤說明三節點 | 指標及說明在左，目標在右，紅色虛線連接 | 按指標、目標、錯誤說明順序閱讀 |

節點保留 `title`、`body`、受審核 `icon`／`tone`；可加 `cells: string[]`（1–4 個、每個最多 8 字元）與 `state: "released"`。cells 僅供 cells／stages／lifetime 版型使用，released 僅供 stages／lifetime 使用；各版型的格數仍依上表限制。cells 承接數值、ASCII 字元等技術標記，兩語相同；解說放在可翻譯的 body。模型不接受任意 HTML、SVG path、CSS、外部圖片或事件處理器。驗證器檢查版型列舉、節點數、cells 結構、釋放狀態及雙語一致性；新需求先擴充受審核模型與測試，不能繞過驗證。

## 排版與文字

1. 正文與圖中文字使用可選取的 HTML；圖說、解說、閱讀順序在無 JavaScript 下仍成立。
2. 桌面忠於原圖的比較與分層；以圖容器寬度判斷重排，不用螢幕尺寸假設文章欄寬。現有版型在容器 620px 以上使用橫排，340px 以下的記憶體格改單欄。
3. HTML 解說至少 16 CSS px，行高至少 1.7；數值可較大。卡片高度隨文字延伸，英文與 200% 文字不裁切；不靠縮小整張圖達成手機驗收。
4. 使用圓角、低彩度底色、可辨識邊框及足夠留白。長圖可以垂直延伸，整頁不能水平溢出。表格與程式碼保留具名稱、可鍵盤捲動的局部容器。
5. 裝飾箭頭不重複朗讀；圖說提供無障礙名稱。cells 的讀出值與顯示值一致，沒有把數值只烘焙成圖片。

## SVG 與驗收

- HTML、搜尋文字、SVG 下載共用正式資料，不手改生成 SVG。完成變更後執行 `npm run generate:perspective-diagrams`。
- 獨立 SVG 保留桌面幾何配置、相同資料格及虛線語意，包含 viewBox、title、desc；每檔小於 100000 bytes。換行由匯出器依卡片寬度計算，驗證文字在 viewBox 內且沒有互相遮蓋。
- 在 320、390、768、1280 CSS px 檢查中英文；另驗 200% 文字與關閉 JavaScript。目視桌面與手機截圖，逐一確認格數、數值、箭頭、分層與釋放狀態。
- 真正以 Tab／Shift+Tab／Enter 驗證下載與焦點；Space 僅在有對應控制時驗收。鍵盤可捲動程式碼與寬表格。
- SVG 必須與產生器逐位元組相符；正式站下載再核對檔案。發布邊界重建與瀏覽器測試依序執行，避免測到暫時被清除的 build。
- 記錄實測平台、URL、版本、結果與證據。瀏覽器模擬、實體手機與完整螢幕閱讀器分別記錄。

## 可執行程式範例

C／C++ 記憶體範例必須先檢查配置成功、先初始化再讀取、在有效生命週期內使用並釋放。使用合成資料，不用未定義行為展示舊資料殘留。說明環境、編譯及執行命令、預期輸出、錯誤碼與清理方式；實際執行平台與未驗平台分開。`calloc()` 的位元組清零，不自動代表任意物件已完成語意初始化；重設一個指標不會同步修正其他別名。

補充新教學範圍依 WRITE-06 升 minor；只有排版／閱讀修正則升 patch。保留原發布日，維護版本修訂日與雙語更新紀錄，署名遵循 WRITE-07。

## 指標與硬體權限圖的補充規則

- 「指標變數存在」「位址位元可能殘留」「語言允許使用該指標值」「硬體允許某次存取」分別表達。free 不自動把呼叫端變數設為 NULL，也不代表釋放後的舊值可合法讀取、比較或解參考。
- `0x1000*`、`ABC?` 必須明示為概念標籤與可能殘留，不是讀取已釋放資料的實測輸出；after-state 恰有一個 released 目標。
- 狀態徽章不接成下一步資料流；配置器與 MMU 的責任連線用無箭頭虛線，解釋其非逐次存取查詢。一般頁面權限、配置區塊生命週期及特殊偵測工具分別交代。
- C 別名範例先檢查配置成功；釋放後直接賦予 NULL 等新值，不列印或比較舊指標，不藉「未崩潰」證明安全。完整範例、理解題與實際執行紀錄分開標示。
