# 全站文章寫作與響應式教學規範

採用日期：2026-11-01。適用所有觀點、CEH、AI、網路與 MATLAB 教學頁面。新增與修訂文章必須遵循；既有差距由盤點追蹤，保留原始教材與發布歷史。

## Agent 工作流程

閱讀本規範及對應內容指南 → 確認讀者、主要問題與供稿範圍 → 保存來源並建立逐章逐小節對照 → 查核來源 → 檢查內容模型及元件 → 完整撰稿與圖解 → 核對雙語內容與深度 → 逐頁瀏覽器及正式站回讀 → 記錄結果。現有模型沒有需要的能力時，先記錄差距，不能插入任意 HTML 繞過驗證。

## 逐章逐小節的完整教學（WRITE-05、08–10）

2026-11-03 使用者更正原文：「我們需要的是，每個章節中，還有很多小節，都必須詳實寫入。」本節將此要求納入共用規範；適用供稿抽換、內容補充與完整教學修訂。若使用者明確要求摘要、節選或縮短，依該次範圍辦理，並標明節選界線。

### 完整性與白話化

以供稿中的章、小節與更細的情境分支為核對單位。每個小節都須在正文有相應解說，保留原有問題、概念與原理、推導過程、比喻及其限制、案例條件、操作步驟、表格、命令、示意流程、結果判讀、例外與下一步。依來源實際內容核對，不要求每節硬加同一套元素，也不另創未要求的研究或實驗。

「白話化」「優化」「抽換」不代表授權濃縮成章級摘要。可以調整措辭、段落與閱讀順序，讓初學者理解怎麼做、為什麼，以及證據能支持到哪裡；不能只留下結論、標題、關鍵字或幾句概述，刪去承接結論的教學過程。合併重複段落時保留所有獨立資訊與推理關係，並在對照中標出合併位置。

長文以清楚的小節、導覽、短段落及局部捲動改善閱讀，不以刪除細節解決篇幅。正文、原理、流程與圖解依 A11Y-03 直接可見；參考答案及實際問答維持既有收合規則。摘要、知識地圖與下載原稿可輔助閱讀，不能代替文章內的完整教學。

### 來源、修正與雙語對照

編輯前先保存原始供稿與待替換版本，沿用文章既有來源紀錄，建立「原文章／小節 → 成稿章節與錨點 → 保留的教學內容 → 改動理由」對照。先檢查較深層小節、情境 A／B／C、條列步驟與問答，避免只盤點最上層標題。

原稿保存與正文採用分開驗證。技術錯誤、過度推論、過時敘述或不能直接執行的命令模板，應在成稿修正並留下原文、修正與依據；不能為逐字一致而保留錯誤，也不能以技術修正為由刪去整段解釋。格式正規化與實質改動分開記錄；重排時維持推導依賴，保留既有有效錨點與發布歷史。

雙語逐小節對應相同的教學內容、例子、條件、命令、結論與限制。譯文可採自然語序與適當分段，並遵守既有模型契約；不能讓其中一語只剩摘要。標題對照表用來找漏項，實際正文仍須逐節閱讀核對。

### 驗收與完成判定

1. **來源到成稿**：檢查每個小節及情境分支的實質內容是否保留。原文加明列修正可逐段比對；自由改寫須逐節檢查意義與教學深度。標題數、字數及關鍵字只能輔助找差距。
2. **成稿到頁面**：確認全部正文、表格、命令、流程與答案進入實際頁面，順序與錨點正確；檢查生成器是否漏掉深層標題、程式碼或特殊字元。只保存來源檔，不能算完成文章抽換。
3. **閱讀與操作**：依既有 HTML／FIG／A11Y 規則檢查手機、桌面、文字放大、鍵盤、無 JavaScript 與圖檔。抽查畫面呈現不能替代全文完整性核對；全文比對也不能替代人工判讀教學品質。
4. **發布後回讀**：有發布授權時，完成必要驗證再部署，核對正式頁採用的版本、全文與相關資產。相同附件雜湊只證明來源相同；遇到使用者更正內容深度或呈現要求，仍須重新對照現況，不能沿用上一輪完成結論。

交付分別說明來源保存、內容採用、驗證與發布狀態，列出漏項或待驗事項。不得用「已涵蓋所有概念」「測試全過」代替逐小節完整性的證據，也不把單篇修訂宣稱為全站改善。

## 圖解與技術選擇

沿用 Svelte、HTML、CSS、SVG；單張圖不新增框架或外部服務。Downloads 的 index-example.html 示範 HTML 節點、SVG 圖示及雙欄轉單欄；採其重排原則，核心補充說明改為直接可見。原檔所連結的獨立 SVG 未隨檔提供，不能當作已完成交付。

## 原發布、版本與修訂日期（WRITE-06）

文章摘要下方沿用一列低彩度小字，以間隔點分開資訊；手機自然換行，不另加卡片、圖示或醒目徽章。日期格式統一 `YYYY-MM-DD`，按 Asia/Taipei 的實際編輯日期記錄，使用 `<time datetime="…">`，文字至少 14 CSS px、行高至少 1.7。

標準顯示：`原發布 2026-10-23 · v1.2.1 · 版本修訂 2026-11-01`。英文對應 `First published`、`Version revised`；兩語共用同一筆日期。

- **原發布日期**：文章第一次發布的日期；後續修改保留原值，另依現有發布閘門處理上線。
- **目前版本**：所有新文章及修訂文章統一採 `vMAJOR.MINOR.PATCH`，例如 `v1.0.1`，不以 `v1`／`v2` 或內部 revision 代替。初版為 `v1.0.0`；白話改寫、閱讀改善與不改變核心結論的修正升 PATCH；增加教學範圍升 MINOR 並將 PATCH 歸零；改變核心結論、學習契約或需重做原操作流程的重大重構升 MAJOR，後兩碼歸零。資料欄位 `contentVersion` 儲存不含 v 的三段非負整數，顯示時加 v；`revision` 僅作內部遞增計數。歷史整數版號遷移須記錄基準與影響，保留 Git 歷史，不聲稱過去曾顯示語意版本。NAS 原 v1 以 1.0.0 為遷移基準，本次白話修訂顯示 v1.0.1，先前 v2 屬誤標。
- **版本修訂日期**：目前內容版本完成修訂的日期，與該版本的修訂紀錄一致。新文章初版可與原發布日相同。未有可信紀錄的舊文章先省略此欄，列入待補紀錄，不推算或用今天代填。
- **閱讀改善就是版本更新**：導讀、文字易讀性、圖解文字替代、排版、響應式及無障礙操作等會改變讀者閱讀體驗的修訂，都納入文章版本。未改變核心教學範圍時提升 patch（例如 `v1.1.0 → v1.1.1`）；新增教學範圍依既有規則提升 minor，重大重構依規則提升 major。同時更新版本修訂日期、遞增內部 revision，保留原發布日。資訊列一律不另設「閱讀更新」。
- **內容校對與觀察日期**：校對日期表示查核，觀察日期表示事件資料範圍；各自保留原意，不替代版本修訂日。

執行順序：確認原發布紀錄 → 判定修訂影響與版本級別 → 維護版號與對應日期 → 記錄修改摘要 → 核對中英資訊列與 320px／200% 文字 → 經授權發布後補上正式回執。重新建置、測試、部署及只改日期顯示元件，都不自動改寫文章日期。
