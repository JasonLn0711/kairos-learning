# M04-10｜列舉防護：如何讓該看的人看得到，不該看的人拿不到？

這一課其實是在教你一個非常重要的資安觀念：

資安不是讓所有人都無法取得資料，而是讓正確的人，在正確的條件下，只能取得他應該取得的資料。

例如，公司有一台伺服器，裡面有員工名單、財務資料、設備資訊。

我們希望達成三件事：

- 財務人員可以正常使用財務資料。
- 一般員工可以使用自己工作需要的資料，但不能讀取機密文件。
- 外部陌生人不能任意探查公司的內部系統。

但這裡有個陷阱：如果你直接把整台伺服器關閉，大家確實都無法列舉資訊了，卻也無法正常工作。

因此，真正的目標是 安全性與可用性同時成立。

## 一、先搞懂：列舉到底有什麼危險？

Enumeration（列舉）就是向系統詢問：「你這裡有哪些東西？」

想像你走進一間公司，詢問櫃檯：

「你們有哪些部門？員工有誰？財務室在哪裡？有哪些電腦？資料櫃放在哪裡？」

這些問題看起來沒有直接偷走任何資料，但如果陌生人能拿到完整的內部清單，就比較容易找出值得進一步攻擊的目標。

不過，列舉並不等於入侵。許多正常業務也需要查詢資訊。

{{figure:rights}}

這三個權限完全不一樣。

有人看得到資料夾名稱，不代表能讀取文件；能讀取文件，也不代表能修改文件。

這就是列舉防護的第一個重點：資訊揭露、資料讀取、資料修改，要分別管理。

## 二、資安防護的四個關卡

我們把伺服器想成一間有保全的大樓。

{{figure:controls}}

特別注意兩個初學者經常混淆的問題。

### 問題 A：我已經登入了，為什麼還不能讀取資料？

因為 Authentication（確認身分）不等於 Authorization（給予權限）。

例如，你確實是公司的員工，但是你不是財務部門成員，因此不能讀取財務報表。

### 問題 B：我已經啟用 HTTPS 或 TLS，資料是不是就安全了？

不是。

TLS 能保護傳輸過程，也能在正確驗證憑證的條件下協助確認伺服器身分，但如果系統本身允許一般員工讀取機密資料，那麼 TLS 只是把「不該給的資料」安全地送到錯誤的人手上。

## 三、什麼是最小權限（Least Privilege）？

一句話：

你完成工作需要多少權限，我就只給你多少，不多給。

例如公司聘請一位清潔人員。

他需要進入走廊、會議室、洗手間，但不需要董事長的保險箱密碼。

在資訊系統也是一樣。

| 使用者  | 需要的能力  | 不應有的能力   |
| ---- | ------ | -------- |
| 一般員工 | 讀取公告   | 修改薪資資料   |
| 財務人員 | 讀取財務文件 | 管理整台伺服器  |
| 監控系統 | 查詢設備狀態 | 任意改變設備設定 |
| 訪客   | 使用訪客網路 | 連接內部管理系統 |

例如 SNMP 監控帳號，需要知道路由器目前的流量和介面狀態，卻不需要修改路由器設定。

如果管理員為了方便，直接給這個監控帳號最高權限，雖然監控程式可以正常工作，但帳號一旦外洩，就可能產生更嚴重的風險。

所以資安人員不只要問「功能能不能用」，還要問「是不是給了超出需求的權限」。

## 四、前面學過的協定，應該如何防護？

把 M04 前面所有列舉課程整合起來，防護思路其實一致：限制不必要的資訊，但保留正當服務。

| 協定            | 白話用途         | 防護重點                           |
| ------------- | ------------ | ------------------------------ |
| DNS           | 網站名稱電話簿      | 正常名稱查詢可用，但區域資料傳送 AXFR 應限制給核准對象 |
| SMB / NFS     | 公司共用資料櫃      | 依身分限制檔案的讀取、修改與刪除               |
| LDAP / AD     | 公司員工與資源名冊    | 控制哪些人能查哪些帳號與欄位                 |
| SNMP          | 設備健康監控櫃檯     | 限制來源、安全層級及可讀寫的管理物件             |
| FTP           | 檔案收發站        | 控制登入、列目錄、下載與上傳                 |
| SMTP          | 電子郵件寄送系統     | 限制不必要的使用者驗證與名單查詢線索             |
| NTP           | 校時服務         | 可以正常校時，但限制不必要的管理資訊查詢           |
| RPC / NetBIOS | 系統間通訊及舊式名稱服務 | 盤點相依關係後，限制不需要的入口及資訊揭露          |

其中有兩個很適合 CEH 考試理解的例子。

### 例子一：SNMPv3 是不是就一定安全？

不一定。

假設你把 SNMP 換成 v3，而且使用 `authPriv`，這代表在適當設定下，訊息具備認證、完整性及加密保護。

但如果同一個帳號仍然被授權讀取所有敏感設備資訊，問題仍然存在。

你還需要透過 VACM 等存取控制設定，限制它真正能讀取或修改的管理物件。

記住：

`authPriv` 主要處理通訊安全；`read view / write view` 主要處理操作權限。

### 例子二：SMB 有簽章，就等於加密嗎？

不等於。

你可以把它想成寄送文件。

- Signing（簽章）：像具有驗證能力的封條，協助確認訊息未遭未授權竄改。
- Encryption（加密）：像將文件放入上鎖的箱子，避免途中被旁觀者讀取。
- Access Control（存取控制）：決定收件人到底有沒有資格拿到文件。

這三者不能互相取代。

技術依據：[SNMPv3 訊息安全 RFC 3414](https://www.rfc-editor.org/rfc/rfc3414.html)、[VACM RFC 3415](https://www.rfc-editor.org/rfc/rfc3415.html)、[Microsoft SMB 安全機制](https://learn.microsoft.com/en-us/windows-server/storage/file-server/smb-security)、[AXFR RFC 5936](https://www.rfc-editor.org/rfc/rfc5936.html)。

## 五、如何證明防護真的有效？

這是整堂課最重要的部分。

假設公司訂定了以下規則：

「普通員工能讀取公告，但不能讀取財務資料；財務人員可以讀取財務資料。」

管理者應該測試不同身分，而不是只看一眼防火牆設定就宣布完成。

{{figure:acceptance}}

這個測試其實包含兩種資安驗證方法：

Positive Test（允許案例）：原本應該能成功的事情，真的成功了嗎？

Negative Test（拒絕案例）：原本應該被拒絕的事情，真的被拒絕了嗎？

兩者缺一不可。

假設防火牆直接封鎖了整台檔案伺服器：

- 訪客讀不到財務報表。
- 普通員工讀不到財務報表。
- 但財務人員也讀不到財務報表。

這不是完整的防護驗收成功，因為正常業務功能也失效了。

## 六、為什麼「連線逾時」不代表安全？

假設你用一個網路測試工具，連線到某台伺服器，出現：

```
Connection timed out
```

請問這代表什麼？

它只能直接告訴你：在這次測試條件下，沒有在期限內得到預期回應。

可能的原因包括：

- 防火牆刻意阻擋。
- 伺服器已經關機。
- 網路路由有問題。
- 服務沒有正常啟動。
- 測試目標或設定有誤。

因此，資安報告不能直接寫「逾時代表防火牆保護成功」。

要證明防火牆真的阻擋，至少應尋找對應規則及實際流量紀錄，並確認來源、目的地、時間與測試內容一致。

這就是 CEH 必須建立的工程思維：不要把工具回傳的現象，直接當成原因。

## 七、日誌和告警，是監視器，不是門鎖

Log（事件日誌）像監視器錄影，Alert（告警）像警報器。

假設系統發現某個帳號在一分鐘內查詢了幾百個員工名稱。

系統可能會發出告警，但你不能直接宣布：「有人正在駭入！」

因為它也可能是合法的人事資料同步程式。

你需要進一步確認來源、使用者、查詢內容、時間、業務用途，以及過去是否有類似活動。

另外，就算日誌完整記下某人讀取機密資料，也不代表資料沒有外洩。

日誌負責留下證據，存取控制才負責限制行為。

## 八、整堂課整理成一套可用的方法

往後看到任何列舉防護問題，都可以依照這個順序思考。

1. **先訂政策：**誰應該能從哪裡，對什麼資源做什麼？
2. **再做設定：**透過網路分段、防火牆、身分驗證、權限與加密機制落實政策。
3. **驗證允許：**正常使用者是否仍能完成工作？
4. **驗證拒絕：**不被授權的來源或帳號是否受到限制？
5. **取得證據：**設定、實際回應與日誌能否相互支持？
6. **修正再測：**未符合政策的地方是否確實改善？

整個 M04 的知識可以這樣連起來：

- 列舉技術教你發現系統對外揭露了什麼。
- 列舉防護教你決定哪些資訊可以揭露、哪些必須限制。
- 驗收測試教你用證據證明防護真的生效。

換句話說，資安工程不是單純追求「查不到」，而是追求「在規定的條件下，得到正確的允許或拒絕結果」。

## 九、理解測驗：你來當資安工程師

假設你負責一間公司的網路安全，政策規定：

- 訪客網路不得查詢內部設備管理資訊。
- 核准的監控主機必須能讀取設備運作狀態。

測試發現：訪客連線逾時，但監控主機也無法取得設備狀態。目前沒有防火牆紀錄或服務日誌可供確認。

同事說：「兩邊都查不到，代表系統防護很成功！」

請你回答：

1. 你同意同事的判斷嗎？為什麼？
2. 你認為目前哪些事情是已知事實，哪些還只是推測？
3. 你下一步會要求管理者提供什麼證據，才能判斷是否可以結案？

請先寫下自己的答案，再展開參考解析核對。這裡不提交答案或記錄分數。
