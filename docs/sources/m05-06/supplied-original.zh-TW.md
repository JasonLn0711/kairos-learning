# CEH M05-06｜驗證式與非驗證式掃描：掃描完成，真的代表安全嗎？

這一課最重要的觀念是：

掃描工具說「工作完成」，不代表「所有項目都檢查成功」，更不代表「系統沒有漏洞」。

我們要學會分辨三件事情：掃描器看得到什麼、它有沒有權限檢查，以及最後取得的證據能不能支持安全結論。

這就是兩種漏洞掃描的基本差別。

- 非驗證式掃描（Unauthenticated Scan）：不使用目標系統的登入身分，從網路上能觀察到的資訊進行檢查。
- 驗證式掃描（Authenticated Scan）：使用事先核准的帳號或其他登入憑證，進一步查看內部資訊。

注意：驗證式的「驗證」是指身分認證（Authentication），不是說掃描結果已經被證明正確。

## 二、兩種掃描究竟在看什麼？

想像有一台 Linux 伺服器，正在提供公司的網站服務。

公司 Linux 伺服器

網站服務、作業系統、套件、設定檔

未登入掃描

觀察網路回應、開放的服務、公開版本資訊

「外面看得到什麼？」

已登入掃描

依帳號權限查看套件版本、修補紀錄、系統設定

「裡面實際裝了什麼？」

概念示意：兩條路徑是互補的觀察方式，不是破解系統的先後步驟。

例如，非驗證式掃描發現網站回應顯示某個舊版軟體。

掃描器可能提出警告：「這個版本可能受到某項 CVE 影響。」

但它未必知道：

這家公司是否已經把安全修補移植回舊版本？相關功能有沒有啟用？目前執行的程式是否真的有該項弱點？

因此，版本字串通常是線索，不一定是漏洞成立的完整證據。

驗證式掃描若成功取得內部套件修訂號、修補與設定資料，就可能進一步回答這些問題。

不過，這裡還有一個重要觀念：非驗證式不等於外網掃描，也不等於被動掃描。 在公司內網使用掃描器、不登入目標系統，一樣可以是非驗證式掃描。主動送出探測封包，也仍然需要授權。

## 三、整課最重要：掃描必須通過三道關卡

假設你使用一套漏洞掃描工具，設定了公司給你的檢查帳號。

工具顯示掃描完成，甚至沒有找到任何漏洞。

現在先不要高興，因為還有三道關卡。

掃描任務已經結束

這只是工作狀態，不是安全結論

第一關：設定（Configuration）

這次掃描真的有使用你設定的帳號嗎？

帳號放進掃描工具，不代表已指派給目標。

第二關：認證（Authentication）

目標系統有沒有接受這個帳號？

帳號過期、SSH 連不上、帳號被鎖，都可能失敗。

第三關：覆蓋（Coverage）

登入後，必要的檢查項目真的有成功執行嗎？

能登入，不代表有權讀取套件清單、設定或紀錄。

依據實際取得的證據判讀

說明已確認事項、未完成檢查及未知風險

這三關的差別，是這一課最值得真正理解的地方。

## 四、實際案例：成功登入，卻掃出零個漏洞

假設你有一台 Ubuntu 伺服器，使用工具進行驗證式掃描。

掃描結果

虛構練習

掃描任務

已完成

SSH 登入

成功

讀取套件清單

Permission denied

發現套件漏洞

0

你能不能跟老闆說：「報告！這台主機零漏洞，非常安全」？

不能。

因為掃描器雖然成功登入，但根本沒有取得套件清單。

這就像房屋檢查員成功進入大門，卻因為電箱被鎖住，沒有檢查電線，最後在報告上寫「未發現電線問題」。

這句話可能在字面上沒有說謊，但如果沒有揭露「電箱未檢查」，就會讓人誤以為已經確認安全。

資安上我們必須區分：

| 狀態    | 真正代表的意思             |
| ----- | ------------------- |
| 掃描完成  | 任務已結束               |
| 登入成功  | 帳號通過身分認證            |
| 檢查成功  | 指定項目已取得可用證據         |
| 沒發現漏洞 | 在已完成的檢查範圍內沒有發現      |
| 系統安全  | 需要更廣泛的證據，不能只靠單次掃描宣稱 |

這也與 CEH 中的 False Negative（偽陰性、漏報） 有關。

真正有漏洞的系統，可能因為掃描不到必要資訊，而沒有在結果中顯示漏洞。

但要特別注意：檢查失敗本身不等於已證實有漏報。只有當漏洞實際存在卻沒有被報出時，才構成漏報。

## 五、那麼是不是帳號權限越高，掃得越完整？

不一定，而且可能增加其他風險。

例如，某些 Linux 主機的深度設定檢查需要 root 或特定管理權限。一般帳號可能只能查看部分資料。

但是，如果你把最高權限帳號交給掃描工具，一旦工具、憑證庫或執行環境遭到入侵，攻擊者也可能取得高權限。

所以正確做法不是一律使用 root，也不是堅持所有掃描都只用普通帳號。

應該根據原廠要求與檢查需求，核定必要權限，使用專用帳號、限制目標、保管好憑證，並記錄哪些檢查受到權限限制。

安全掃描本身，也必須被安全管理。

尤其不要為了讓掃描成功，就擅自關閉 MFA、防火牆或其他安全控制措施。

## 六、Agent 與驗證式掃描，又有什麼不同？

你可能在企業端點管理或資安系統中，看過安裝在電腦裡面的 Agent。

Agent 就像安排一位檢查員常駐在房子裡面。

它可以在授權的本機權限下收集安裝軟體、版本或設定資訊，再回報管理平台。

這與遠端登入掃描不同，但兩者可以互補。

| 方法       | 比較擅長回答的問題              |
| -------- | ---------------------- |
| 非驗證式網路掃描 | 從指定網路位置能看到哪些服務與暴露面？    |
| 驗證式掃描    | 系統內部有哪些套件、修補與設定狀況？     |
| 本機 Agent | 這台設備在資料蒐集當時，回報了哪些內部狀態？ |

Agent 可能具有本機高權限，所以不能把它直接當成非驗證式掃描。

同樣地，Agent 看得到主機內部，不代表它能完整判斷從外部網路究竟可以連到哪些服務。

因此，實務上常常需要不同觀察方式交叉驗證。

## 七、真正的資安專業，是懂得解釋證據的界線

假設你正在替企業執行經授權的滲透測試或漏洞評估。

發現某個服務顯示舊版資訊，接著進行驗證式掃描，確認主機套件已安裝發行商的安全修補版本。

這時候，合理的結論可以是：

> 根據本次取得的套件修訂資訊與發行商公告，已確認該套件安裝包含指定安全修正的版本。然而，執行中程序是否已載入更新，以及其他部署副本是否受影響，仍有待確認。

這比「已修補，沒有風險」更精確。

因為你必須知道一件事情：

安裝了更新，不代表正在執行的程式一定已經載入更新。

例如某個服務可能尚未重新啟動，仍使用更新前載入的程式或函式庫。

同時，修補了一個套件漏洞，也不表示系統設定、帳號權限與網路曝露問題都一起解決了。

所以在實務報告中，我們應該把「已證實的事實」、「合理推論」和「仍然未知的事項」分開。

## 八、理解檢核：換你當資安檢測人員

某公司提供一台 Linux 主機供你進行合法的漏洞評估。

掃描工具顯示：任務已完成、SSH 認證成功、套件清單讀取遭拒、套件漏洞數量為 0。

問題一：你能宣稱這台主機的套件全部安全嗎？

可以，因為漏洞數量是 0。

不可以，還需要確認檢查覆蓋與證據。

可以，但必須先確認登入成功。

問題二：接下來最應優先補查哪兩項？（選兩項）

確認套件清單是否成功讀取，檢查項目有沒有完整執行

取得實際版本與修補資訊，對照可信的原廠安全公告

確認掃描工具顯示 Finished，就視為系統沒有漏洞

只要能成功 SSH 登入，就代表主機所有項目都已檢查

提交答案，請你批改

本課請記住這個核心公式：

掃描可信度 = 明確的掃描範圍 ＋ 成功完成的檢查 ＋ 足以支持結論的證據。

這不是數學上的計分公式，而是提醒你：資安專業人員不只會使用掃描器，更要能說明它究竟檢查到了什麼，以及哪些事情仍然不知道。
