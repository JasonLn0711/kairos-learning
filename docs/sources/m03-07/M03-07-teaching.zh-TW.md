# CEH M03-07｜Nmap：把掃描設定、輸出與證據串起來

**一句話結論：先寫清楚要查什麼、可以查哪裡，再選擇最小必要設定，保存完整結果，最後只下證據支持的結論。**

前幾課分別介紹主機探索、掃描方式、連接埠狀態、服務版本與作業系統指紋。這一課把它們組成可重現的工作流程：拿到一份 Nmap 結果時，你能說明它測了什麼、漏了什麼，以及下一步應如何核對。

## 1｜生活例子：巡查表決定你能回答什麼

假設你負責巡查一棟大樓。若巡查表只要求確認一樓的兩扇門，你可以回報那兩扇門當時的狀態；整棟大樓是否安全，還需要其他證據。報告也要留下巡查時間、位置與方法，讓下一位同事知道差異可能來自哪裡。

**Nmap（Network Mapper，網路探索與安全稽核工具）**也需要這種巡查表。**Target（目標）**是被檢查的主機或位址；**Scan Configuration（掃描設定）**決定協定、連接埠、探測方式及其他功能。工具輸出描述的是這次設定下的觀察範圍。

同一連接埠從內網看可能開啟，從外部看可能被過濾，因此要把來源位置和時間一起留下。[Nmap：連接埠狀態與觀察位置](https://nmap.org/book/man-port-scanning-basics.html)

## 2｜開始前，先把授權變成可核對的範圍

一份可執行的掃描計畫，至少要交代：

- **目標與排除項目**：明列允許的位址、主機、協定與連接埠；共享服務、第三方設備及未授權區域分開列出。
- **目的與方法**：例如只確認兩個 TCP 入口是否可連線，或另有核准的服務辨識。能連到設備不代表已取得掃描授權。
- **時間與來源**：允許的時段、掃描端位置，以及可聯繫的管理者。
- **停止條件**：出現服務異常、告警或超出核准時段時停止，保留當時紀錄並通知負責窗口。
- **結果保存**：檔案位置、可讀取的人及保留方式；原始結果可能含內部位址與軟體資訊。

這些是本課建議的工作規劃，不是工具自動替你取得的授權。實務上還要遵循單位核准的程序。這一課只做紙上判讀，不會操作任何第三方目標。

## 3｜四個設定問題：對象、入口、方法、附加功能

先看一個**僅供閱讀、不要求執行**的範例。假定你管理自己的隔離實驗環境，允許檢查該環境本機的 TCP 8000、8001：

    nmap -n -sT -p 8000,8001 --reason -oN lab-check.nmap -oX lab-check.xml 127.0.0.1

127.0.0.1 是執行命令那個網路環境的本機迴路位址。若在容器或虛擬機器執行，看到的是該環境；不能把本機結果當成外部使用者的連線結果。

把命令拆成四個問題：

1. **查誰？** 最後的 127.0.0.1 指定單一目標。不要為了方便改成整個網段；網段表示法會擴大目標集合。主機名稱也需要先確認解析到的位址是否在授權範圍。[Nmap：目標指定](https://nmap.org/book/man-target-specification.html)
2. **查哪些入口？** -p 8000,8001 明列兩個連接埠；搭配本例的 TCP 方法，範圍就是這兩個 TCP 入口。沒有列到的埠沒有本次檢測證據。-p- 會擴大到連接埠 1–65535；-F 則使用較少的常見埠，不是相同範圍的單純加速。[Nmap：連接埠選擇](https://nmap.org/book/man-port-specification.html)
3. **怎麼查？** -sT 是 TCP Connect Scan（TCP 完整連線掃描），請作業系統嘗試建立連線。它與 -sS 的 SYN 探測不同；-sU 才是 UDP 掃描。TCP 的結果不能代替 UDP 結果。[Nmap：掃描方法](https://nmap.org/book/man-port-scanning-techniques.html)
4. **還加了什麼？** -n 關閉反向 DNS 名稱解析；--reason 顯示工具判定狀態的依據；-oN 與 -oX 分別保存文字及 XML 結果。這個範例沒有要求版本探測、作業系統辨識或腳本掃描。[Nmap：名稱解析](https://nmap.org/book/man-host-discovery.html)；[Nmap：輸出選項](https://nmap.org/book/man-output.html)

若真的在核准實驗環境執行，本命令會嘗試連線、可能產生日誌，並寫入指定檔案；相同檔名可能覆寫舊資料。這裡沒有啟動測試服務，所以不能預告哪個埠一定開啟。

## 4｜先知道省略了什麼，才看得懂結果

**Host Discovery（主機探索）**是先判斷哪些目標值得繼續檢查的階段。-sn 保留主機探索而不做連接埠掃描；-Pn 跳過一般的主機探索判定，直接把指定目標列入後續掃描。使用 -Pn 不是證明每台主機真的存活，也不是繞過防火牆。在本地乙太網路，仍可能需要 ARP 等位址解析。[Nmap：主機探索](https://nmap.org/book/man-host-discovery.html)

如果報告說「主機似乎未啟動」，先查清楚使用了什麼探索方法及網路條件；不要直接寫成「這台設備不存在」。同樣地，只執行 -sn 也不能交付「所有連接埠均已檢查」的結論。

**Service Detection（服務辨識）**常用 -sV，**OS Detection（作業系統辨識）**使用大寫 O 的 -O。它們提供不同層次的線索。-A 會合併多項功能，包括版本、系統、預設腳本與路徑追蹤；它不是「只把同一個小測試做得更準」的按鈕，也不是時間設定。新增這些功能之前，要核對目的、負載與授權。[Nmap：附加功能的範圍](https://nmap.org/book/man-misc-options.html)

## 5｜速度也是測量條件

Nmap 會等待回應，也可能重送探測。**Timeout（逾時）**是等待超過設定時間；**Retry（重試）**是沒有取得所需回應時再次嘗試。網路延遲、封包遺失與設備的回應限制，都會影響時間及結果。

把等待時間設得太短、重試降得太少，可能漏掉較慢的回應。-T0 到 -T5 是時間行為範本，數字大小不是可信度或安全等級。速度調整要符合核准時段與環境承受能力，不能因為工具跑完就認定檢查完整。收到逾時、略過或中斷資訊時，應記為限制或未完成範圍。[Nmap：時間與效能](https://nmap.org/book/man-performance.html)

實務上的比較順序是：先固定目標、協定、埠及方法，再記錄時間設定。不同時間範本、不同來源位置的兩次結果，未必能直接當作設備設定改變的證據。

## 6｜保存的不是只有螢幕截圖

範例中的 -oN 保存適合人閱讀的文字；-oX 保存 **XML（Extensible Markup Language，可延伸標記語言）**，讓程式依欄位讀取主機、埠、狀態等資料。-oA 可一次產生 .nmap、.xml、.gnmap 三種檔案；其中 grepable 格式已被官方標示為不建議新整合採用，程式化整理優先考慮 XML。[Nmap：輸出格式](https://nmap.org/book/man-output.html)

原始檔之外，再保存一份簡短說明：完整命令、實際工具版本、開始與結束時間及時區、來源位置、授權範圍、警告／錯誤與中斷情形。可用 nmap --version 查看本機工具版本；本文沒有聲稱已替你執行或安裝任何版本。

圖表或摘要可以衍生，但原始結果應保留。若為分享而去除內部位址，另外建立去識別化副本，避免讓後續核對失去原始依據。

## 7｜合成案例：兩個入口，三種層次的結論

以下是**人工編寫的判讀資料，不是本次實測輸出**：

    目標：隔離實驗環境的本機
    設定：TCP Connect，只檢查 8000、8001
    8000/tcp  open
    8001/tcp  closed
    此資料沒有版本探測或作業系統辨識結果

可以寫：「在記錄的時間與來源環境，以 TCP Connect 觀察到 8000 接受連線，8001 呈關閉狀態。」這是本次資料支持的觀察。

若接著想知道8000執行什麼服務，就需要核准的服務辨識或管理端程序／設定資料；僅靠埠號，不能確認軟體名稱與版本。若想知道外部是否能連線，需另行核准外部觀察位置與測試。至於是否有弱點、是否能取得權限，也要各自取得證據。

現在假設第二份報告由另一個來源看到8000為 filtered。先比對來源、時間、協定、方法與路徑，並查防火牆或主機日誌，再判斷差異；不要先宣布服務已經關閉。[Nmap：狀態的觀察範圍](https://nmap.org/book/man-port-scanning-basics.html)

## 8｜把掃描結果用在防護驗收

資產盤點和防火牆維護可以使用這套流程：先列出「哪些來源應能連到哪些服務」，在核准範圍內取得結果，再和設定、程序及日誌比對。應開放的服務要確認正常功能；不應開放的入口要確認存取規則確實生效。

如果觀察到異常入口，先確認資產負責人與業務用途，再由有權限的管理者處理。完成變更後，用相同條件複測，並確認必要服務沒有被誤擋。掃描沒有發現某項問題，只能說明這次涵蓋範圍內的觀察；整體安全仍需要其他維運及查核證據。

## 9｜安全練習與小檢核

這次用紙本或文字編輯器處理第7節資料即可，不需執行命令：

1. 寫出本次允許的目標、協定、兩個埠及方法，列出未檢查的項目。
2. 各寫一句「直接觀察」與「仍需管理端或其他位置確認」的結論。
3. 列出讓別人重現同樣觀察所需的紀錄，以及發生服務異常時的停止條件。

預期成果是一張可核對的掃描工作單。此練習沒有建立服務或變更設定，無需清理系統；只保留自己的分析。

先想四題，也可以只回覆最想釐清的一題：

1. 只掃描 TCP 8000、8001，兩者都沒有開啟時，能否說整台主機沒有任何對外服務？為什麼？
2. -sn 與 -Pn 對工作流程各改變了什麼？哪個選項本身能證明主機真的存活？
3. 有人提議把範例加上 -A，當成「同一範圍的更精準測試」。你會先核對什麼？
4. 同一埠在兩份報告中分別是 open 與 filtered，該如何記錄差異並安排下一步？
