## 1. AES：一定要會的對稱式加密演算法

優先掌握

### 白話理解

假設你有一份銀行客戶資料，想把它存到伺服器，但不希望駭客偷走後可以直接閱讀。

這時可以使用 AES（Advanced Encryption Standard，進階加密標準）。

AES 就像一部具有複雜數學鎖頭的機器：

- 將原始資料（Plaintext）放進去。
- 用一把秘密金鑰（Secret Key）控制加密。
- 產生無法直接理解的密文（Ciphertext）。
- 持有正確金鑰的人，可以執行解密。

AES 屬於 Symmetric Block Cipher（對稱式區塊密碼）。

「對稱式」表示加密與解密使用同一把秘密金鑰；「區塊密碼」表示演算法的基本處理單位具有固定長度。

### 考試必背的三個數字

| 演算法     | Block Size（區塊長度） | Key Size（金鑰長度） |
| ------- | ---------------- | -------------- |
| AES-128 | 128 bits         | 128 bits       |
| AES-192 | 128 bits         | 192 bits       |
| AES-256 | 128 bits         | 256 bits       |

不論 AES-128、AES-192 或 AES-256，區塊長度永遠都是 128 bits。

後面的數字代表金鑰長度，而不是每次加密的資料長度。

這是 NIST FIPS 197 明確規定的內容。

### 為什麼考題常拿 AES、Blowfish、Twofish 比較？

因為三者都是對稱式區塊密碼，但規格不同。

| 演算法      | 區塊長度     | 金鑰長度             |
| -------- | -------- | ---------------- |
| AES      | 128 bits | 128／192／256 bits |
| Blowfish | 64 bits  | 32–448 bits      |
| Twofish  | 128 bits | 128／192／256 bits |

假設題目說：

> 使用 64-bit 區塊，而且金鑰長度可以從 32 到 448 bits。

你應該立即想到 Blowfish。

如果題目說：

> 128-bit 區塊、256-bit 金鑰、AES 遴選決選者。

就要再看其他條件，因為 Twofish 與最終成為 AES 的 Rijndael 都曾參加決選，不能只靠這些資訊斷定唯一答案。

### 考試要記住

AES = 對稱式 + 區塊密碼 + 128-bit 區塊 + 128／192／256-bit 金鑰。

不必在這次精讀背誦 AES 內部的 SubBytes、ShiftRows、MixColumns 等轉換步驟；附件這 8 題沒有直接要求這種細節。

## 2. AES-GCM：讓加密不只保密，還能偵測竄改

### 白話理解

假設你使用 AES 加密一筆銀行轉帳訊息。

加密的主要目的是：不讓別人看到內容。

但是你還有第二個需求：如果駭客修改了加密訊息，銀行系統應該能發現。

這時可以使用 AES-GCM。

GCM（Galois/Counter Mode）是一種 Block Cipher Mode of Operation（區塊密碼運作模式）。

它讓 AES 不只用來加密資料，還能搭配產生的 Authentication Tag（驗證標籤），在解密時確認資料是否遭到未授權修改。

### AES-GCM 的簡化工作流程

輸入

明文 + 秘密金鑰 + Nonce + 可選的關聯資料（AAD）

AES-GCM

加密並計算驗證標籤

Ciphertext

密文，保護機密性

Authentication Tag

驗證完整性與真實性

接收端驗證 Tag

通過：接受解密結果；失敗：拒絕資料

這裡的 Nonce（也常稱 IV）是一個重要參數。在同一把金鑰下，必須遵守 GCM 的 IV 唯一性要求，否則可能嚴重損害安全性。

NIST SP 800-38D 定義 GCM 的認證加密、驗證標籤與 IV 要求。

csrc.nist.gov



### CEH 要理解到什麼程度？

先記住兩個差別：

- AES：是一種加密演算法。
- AES-GCM：是 AES 搭配 GCM 運作模式，提供機密性及認證加密能力。

不要把 AES-GCM 誤認成另一種與 AES 完全無關的加密演算法。

也不要以為所有 AES 加密模式都能自動提供完整性驗證。

一句話記憶：AES 負責加密；GCM 讓這套加密方案也能偵測未授權竄改。

## 3. Birthday Bound：為什麼 64-bit 區塊可能不夠安全？

### 白話理解

先想一個問題：

一個班級有 23 個學生，至少兩個人生日相同的機率是多少？

答案竟然已經超過 50%。

這就是著名的 Birthday Paradox（生日悖論）。

原因是我們不是只比較某一個人與其他人的生日，而是在比較班上所有可能的兩人組合。

人數增加時，配對組合增加得非常快。

密碼學中的 Birthday Bound（生日界限），就是利用類似的機率原理，分析碰撞風險。

### 與 AES、Blowfish 有什麼關係？

假設某種區塊密碼每次處理 64 bits 資料。

其區塊空間大小是：

\\[ 2^{64} \\]

但在某些常見加密模式中，碰撞相關風險在處理約 \\(2^{32}\\) 個區塊時就可能變得顯著，而不必等到 \\(2^{64}\\) 個區塊。

簡化的生日界限公式為：

\\[ \boxed{q\approx 2^{n/2}} \\]

其中 \\(n\\) 是區塊長度，\\(q\\) 是區塊數量。

| 演算法      | 區塊長度     | 生日界限量級           |
| -------- | -------- | ---------------- |
| Blowfish | 64 bits  | \\(2^{32}\\) 個區塊 |
| AES      | 128 bits | \\(2^{64}\\) 個區塊 |

對 64-bit 區塊來說：

\\[ 2^{32}\times 8\text{ Bytes}=32\text{ GiB} \\]

這不是說 Blowfish 加密到 32 GiB 就一定會被破解，而是某些加密模式下，隨資料量增加，碰撞風險可能達到不能忽略的程度。實務限制取決於模式與協定，安全性也可能在到達這個數值以前逐漸下降。

IETF RFC 7146 附錄 A 討論了這個問題；2016 年的 Sweet32 研究也示範了 64-bit 區塊密碼在特定通訊協定中的實際碰撞攻擊。

[image](https://www.google.com/s2/favicons?domain=https://www.rfc-editor.org\&sz=32)

rfc-editor.org+1



### CEH 要記住

Birthday Bound：區塊越短，處理大量資料時，某些碰撞相關風險越容易出現。

這可以幫助你理解 Blowfish 的 64-bit 區塊為何是限制之一，但目前提供的 8 題主要考演算法參數辨識，不需要深入計算碰撞機率。

## 4. Kerckhoffs's Principle：安全性不能依賴演算法保密

### 白話理解

假設有兩家公司設計加密系統。

A 公司宣稱：「我們自己發明一套加密公式，只要別人不知道公式，就無法破解。」

B 公司宣稱：「我們使用公開、經過研究的 AES。即使攻擊者知道演算法，也不能因此直接解密資料。」

哪一種安全設計理念比較合理？

B 公司的理念更符合現代密碼學。

Kerckhoffs's Principle（柯克霍夫原則）的核心是：

> 密碼系統即使被敵人知道如何運作，也應該在金鑰未洩漏的前提下保持安全。

這個原則可追溯到 Auguste Kerckhoffs 在 1883 年提出的密碼系統設計思想。

[image](https://www.google.com/s2/favicons?domain=https://people.cs.rutgers.edu\&sz=32)

Foundations and Classical Ciphers



為什麼？

因為演算法通常很難永遠保密。程式碼可能外洩，設備可能被逆向工程，內部人員也可能離職。

但金鑰可以更換，公開演算法也能接受研究人員的持續檢驗。

然而，這個原則不代表公開的演算法一定安全，也不代表只要金鑰保密，實作就不會出現漏洞。

### CEH 要記住

Algorithm can be public; the secret key must remain protected.

如果考題問：「密碼系統的安全性應主要依賴什麼？」

你要想到的是密碼機制本身的安全設計與秘密金鑰的保護，而不是只靠隱藏演算法。

## 最後複習：4 句話掌握全部重點

1. AES： 對稱式區塊密碼，128-bit 區塊，金鑰有 128／192／256 bits。
2. AES-GCM： AES 搭配 GCM 模式，提供加密與完整性驗證；必須正確管理 Nonce。
3. Birthday Bound： 區塊長度影響大量資料處理時的碰撞風險；64-bit 區塊有特別值得注意的限制。
4. Kerckhoffs's Principle： 演算法可以公開，安全設計不能只依賴隱藏演算法。

以這次 CEH 考古題而言，你應該優先記熟 AES、Blowfish、Twofish 的分類及區塊與金鑰規格。這比背誦生日悖論的推導過程更能直接幫助你解題。
