# CEH M09-03｜語音釣魚、簡訊釣魚與身分冒充

**Module 09：Social Engineering（社交工程）**  
**本課主題：Vishing、Smishing、Impersonation**

今天接著 M09-02 的 **Phishing（釣魚：利用欺騙性訊息，誘導人交出資訊或採取不安全行動）** 往下學。上一課主要問「攻擊者鎖定誰」；這一課改問：**對方透過什麼管道接近你，又憑什麼讓你相信他的身分？**

不用先懂電話系統或網路設定。本課會從生活情境，一步步連到身分驗證、驗證碼、防護與證據判讀。可以分段讀，不需要為了跟上排程一次讀完。

## 一、先想像：簡訊與電話互相證明，就一定可信嗎？

以下 Northstar 教材中心、人物與事件都是虛構案例，只用來練習判斷，沒有對任何真實對象發送訊息或測試。

小林正在整理課程資料，手機收到一則簡訊，大意是：「教材平台出現異常登入，請聯絡服務人員處理。」

不久後電話響了。對方自稱平台客服，說得出小林的名字與教材專案名稱，來電畫面也顯示熟悉的服務名稱。對方表示要「協助取消異常操作」，請小林把剛收到的登入驗證碼念出來。

小林可能會想：

> 簡訊先提醒，客服又打來，而且知道我的工作，應該是真的吧？

但從資安角度看，我們目前只知道「收到一則簡訊」和「有人來電」。**如果兩個管道都由同一個攻擊者安排，它們只是互相配合的說法，不是兩份獨立證明。**

本課最重要的一句話是：

**看起來像、聽起來像、知道你的事，都不等於身分已驗證；身分驗證通過，也不等於每項要求都有授權。**

## 二、三個名詞：兩個在說管道，一個在說冒充手法

### 1. Vishing：語音釣魚

Vishing 是 **Voice phishing（利用語音的釣魚）** 的組合詞。有人透過電話、語音通話或語音留言，以欺騙方式誘導你交出資料或採取不安全的行動，就屬於這個範圍。

例如，有人冒充資訊人員，要求你提供登入資訊。重點是利用語音互動取得信任，不是「有電話」就算攻擊，也不要求一定使用假聲音。真人正常說話，也可能進行語音釣魚。[加拿大資安中心：語音釣魚](https://www.cyber.gc.ca/en/what-voice-phishing-vishing-itsap00102)

它可以要求的，不只密碼，還可能包括同意帳號操作、付款、提供文件，或允許遠端協助。**正常客服也會打電話，所以分類要同時看欺騙、目的與要求，不能只看通訊工具。**

### 2. Smishing：簡訊釣魚

Smishing 結合了 **SMS（Short Message Service，手機簡訊服務）** 與 phishing。典型做法是以欺騙性簡訊，誘導收件者交出敏感資料、進入假網站或執行其他危險動作。

例如假借配送、帳務或登入異常，要求從簡訊內的入口處理。簡訊可以帶連結，也可能只要求回覆資料或撥打電話；「沒有連結」不等於安全。[加拿大資安中心：簡訊釣魚](https://www.cyber.gc.ca/en/guidance/smishing-protect-yourself-sms-attacks-itsap00103)

本課先用「SMS 簡訊」掌握這個詞。通訊軟體裡也可能有釣魚與冒充，但不是看到任何文字訊息，都要不分管道地叫作 Smishing。

### 3. Impersonation：身分冒充

Impersonation 指假扮成其他人、角色或組織，讓你把原本給那個身分的信任交給冒充者。

例如假冒客服、主管、同事或來訪廠商。它描述的是「扮成誰」，不是限定某個管道：電話、簡訊、電子郵件、通訊軟體，甚至面對面都可能發生。官方社交工程指引也將假冒可信人物列為常見手法。[加拿大資安中心：社交工程](https://www.cyber.gc.ca/en/guidance/social-engineering-itsap00166)

把三個詞排在一起，就比較不會背錯：

| 詞彙 | 主要在回答什麼？ | 本課案例 |
| --- | --- | --- |
| Vishing 語音釣魚 | 透過什麼管道誘導？ | 用電話要求提供登入驗證碼 |
| Smishing 簡訊釣魚 | 透過什麼管道誘導？ | 用欺騙性簡訊引導處理假事件 |
| Impersonation 身分冒充 | 假扮成誰來取得信任？ | 自稱教材平台客服 |

**這不是三選一的互斥分類。** 一次事件可以先有簡訊釣魚，再有語音釣魚，而且兩段都使用身分冒充。釣魚跨管道進行的現象，也見於 NIST（美國國家標準暨技術研究院）的說明。[NIST：釣魚管道與防護](https://www.nist.gov/blogs/cybersecurity-insights/phishing-resistance-protecting-keys-your-kingdom)

## 三、接回上一課：目標、管道、身分，是不同觀察角度

M09-02 的 **Spear phishing（魚叉式釣魚／定向釣魚）**，重點是針對特定對象設計；**Whaling（鯨釣）**，重點是鎖定高階、高價值人物。

今天的 Vishing 與 Smishing，重點則是管道。

因此，在小林的案例，如果查證後確認對方特別蒐集他的工作背景、量身設計內容，可以描述為「針對小林的定向釣魚，透過簡訊與語音接觸，並冒充平台客服」。這比硬選一個名詞更完整。

反過來，對方聲稱「我是董事長」，也不代表事件自動變成鯨釣。仍要分清楚：

- **鎖定誰**：希望哪個人照做？
- **透過哪裡**：電話、簡訊或其他管道？
- **冒充誰**：借用哪個身分？
- **要求什麼**：資料、登入、付款、權限或其他行動？

這四個問題是本課整理的判讀工具，不是官方規定的攻擊階段。

## 四、為什麼來電顯示、聲音與個人資料都不夠？

### 1. 來電顯示是畫面線索，不是完整的身分證明

**Caller ID（來電顯示）** 是手機畫面上顯示的來電號碼或名稱。**Spoofing（偽冒）** 則是讓某項識別資訊看起來像來自別的來源；本課特別指偽冒來電顯示。

來電顯示可以被操弄，所以「畫面上是銀行或公司的號碼」，不能單獨證明電話另一端就是該機構。[美國聯邦貿易委員會：辨認詐騙](https://consumer.ftc.gov/articles/how-avoid-scam)

這裡再分清楚兩個詞：

- 身分冒充：整體上假扮成客服或主管。
- 來電顯示偽冒：操弄畫面上的號碼或名稱，是可能使用的其中一項技術。

對方即使使用普通陌生號碼，也能在說話時冒充客服。因此，身分冒充不一定需要來電顯示偽冒。

### 2. 聲音很像，也只能增加熟悉感

**AI（Artificial Intelligence，人工智慧）語音複製**，是用技術產生近似某人的聲音。官方消費者防詐資料已提醒，熟悉的聲音也可能被模仿。[FTC：語音複製與緊急求助詐騙](https://consumer.ftc.gov/consumer-alerts/2023/03/scammers-use-ai-enhance-their-family-emergency-schemes)

不過，我們不能反過來說「聲音怪怪的，所以一定是 AI 攻擊」；通訊品質也可能造成失真。正常、流暢的聲音，同樣不能保證安全。

**防守目標不是靠耳朵猜出所有假聲音，而是讓重要操作不只依賴聲音。**

### 3. 知道你的背景，不等於有權要求你操作

小林的名字、專案名稱可能出現在公開網站，也可能來自其他來源。單靠電話裡說得出這些內容，無法判定資訊來源，更無法證明對方的身分與權限。

這是推理上的界線：**知道某項資料，與有資格替這個帳號做決定，是兩件事。** 不需要先證明背景資料從哪裡外洩，才願意暫停可疑要求。

## 五、真正要守住的是哪一道界線？

回到小林的電話，對方要的不是「聊幾句」，而是讓小林交出一個可以協助完成帳號操作的驗證碼。

**Authentication（身分驗證）** 是確認正在使用服務的人是否掌握該身分所需的驗證條件。**Authorization（授權）** 是決定這個人可以執行哪些操作。

生活類比：櫃檯確認你是公司員工，不代表你就能領走公司的全部鑰匙。

同樣地，就算確認電話另一端確實是某位同事，還是要確認：這項資料可以給他嗎？他有權批准付款嗎？是否走完必要流程？

### 登入驗證碼為什麼不能當成客服的身分證？

**OTP（One-Time Password，一次性密碼／驗證碼）** 通常只在有限條件下有效，用來協助驗證某次操作。它可能真的來自平台，卻不代表「叫你把碼念出來的人」也是真的客服。

用本課的虛構情境理解：如果有人在別處嘗試登入，平台可能把真正的驗證碼送給帳號持有人。持有人再受騙把碼交出去，就可能讓別人完成那次驗證。這是風險示意，不是已發生的事實；實際是否成功仍要查紀錄。

**MFA（Multi-Factor Authentication，多因素驗證）** 是使用不同類型的驗證因素，例如密碼搭配你持有的驗證裝置。它能增加保護，但不是所有 MFA 都具有同樣的抗釣魚能力。

NIST 明確區分：需要使用者手動輸入的 OTP 等驗證輸出，不應視為具備抗釣魚能力，因為這個輸出沒有綁定到正在驗證的特定連線工作階段，可能被轉交到真正服務。[NIST SP 800-63B-4：抗釣魚能力](https://pages.nist.gov/800-63-4/sp800-63b.html#phishres)

現在先記住：

- 自己從可信入口發起操作，與應陌生來電要求提供登入驗證碼，不是同一件事。
- 不提供登入驗證碼、密碼或復原碼給未驗證的來電者。
- 不因對方說「為了資安」，就關閉保護或核准自己沒發起的驗證要求。
- 抗釣魚驗證主要保護登入驗證環節，不能替你判斷每筆付款或資料交付是否合理。M09-06 會再深入整套防護。

## 六、完整拆解 Northstar 案例：先辨認風險，再查證

下面是**本課合成情境的分析**，不是實際事件調查結果。

| 觀察到的要求 | 正在碰觸的安全界線 | 較安全的決策 |
| --- | --- | --- |
| 簡訊叫小林從新入口處理登入異常 | 把處理入口交由未驗證訊息決定 | 自己開啟原先使用的官方入口 |
| 來電自稱客服，知道專案名稱 | 把熟悉背景當成身分證明 | 透過既有可信聯絡資料核實 |
| 要求念出登入驗證碼 | 把驗證能力交給未驗證對象 | 停止提供，交由正式窗口處理 |
| 要求保持通話、不要聯絡公司窗口 | 阻止獨立查證 | 結束可疑互動，依既有程序確認 |

「很急」不一定代表詐騙；真的事故也可能很急。但**急迫不應成為略過驗證的理由**。真正可用的緊急程序，應預先定義由誰確認、誰核准、如何留下紀錄，而不是由電話中的人臨時決定全部規則。

## 七、如何驗證才算真的離開對方安排的圈子？

**Independent verification（獨立查證）** 的核心，是改用不由這次可疑要求提供、控制或指定的可信來源，確認身分與要求。

重點不只是「換一個通訊軟體」。如果從可疑簡訊點進客服聊天室，再照聊天室提供的號碼打電話，三個地方可能仍由同一方控制。

在 Northstar 的案例，小林可以這樣做：

1. **停下來**：先不提供資料、不核准登入、不安裝軟體。
2. **離開可疑互動**：結束電話，不使用來電畫面的一鍵回撥，也不使用簡訊提供的聯絡方式。
3. **自己找到既有入口**：例如公司原本的資訊服務台、既存通訊錄或先前確認的官方平台。
4. **核對具體事項**：有沒有這張服務工單？誰提出？要做哪項操作？授權範圍是什麼？
5. **依核准流程處理**：確認為真，也只做工作需要且已授權的部分；確認不清楚，就交由負責窗口升級處理。

「服務工單」就是一份有編號、內容與處理人的工作紀錄。但**對方念得出工單號碼，也不等於工單真的存在或內容正確**；要從自己取得的可信入口核對。

這個流程是教學案例的防守設計。官方指引同樣建議使用已知可信電話或正式網站查證，而非使用對方提供的號碼或直接回撥。[加拿大資安中心：來電查證建議](https://www.cyber.gc.ca/en/what-voice-phishing-vishing-itsap00102)

若懷疑原本可信的帳號也被冒用，僅向同一個帳號再問一次仍不夠。高風險事項應依組織程序，使用另一個已核實的窗口或獨立核准，避免整個決策只依賴單一可能失陷的管道。

## 八、組織不能只要求員工「自己小心」

接回 M01-06 的 **Defense in depth（縱深防禦）**：把不同層的控制一起安排，避免一次判斷失誤就造成全部損失。

以下是為 Northstar 設計的控制例子，不表示每間公司都已有這些設定：

| 層次 | 可以設計的措施 | 保護重點與限制 |
| --- | --- | --- |
| 人員與流程 | 固定查證窗口；允許暫停可疑要求；提供簡單通報方式 | 讓員工有可執行的下一步，而不只靠辨認口音 |
| 帳號 | 適合系統的抗釣魚驗證；敏感操作重新確認 | 強化驗證，不代表所有商業要求都可信 |
| 權限 | 只給工作需要的權限；重要變更由不同人確認 | 減少單一帳號或單一決策能造成的影響 |
| 裝置 | 軟體安裝與遠端協助採正式核准 | 避免假客服把「協助」變成未授權控制 |
| 偵測與應變 | 保留登入、權限變更、服務工單紀錄；建立通報與處置程序 | 協助發現及追查，紀錄本身仍可能不完整 |

正常的遠端協助工具不必然是惡意程式；風險在於**誰控制、是否經過驗證與授權、允許做到什麼程度**。

這也串起前面的 M01：

- **M01-01：CIA 安全目標**。機密性關心資料是否被未授權讀取；完整性關心資料或設定是否被不當修改；可用性關心有權使用的人是否能正常使用。
- **M01-02：資產與風險**。帳號、教材、付款與服務都是要保護的對象；風險要看可能性與後果，不只看訊息有多可疑。
- **M01-03：授權邊界**。教材只分析虛構事件；實際電話演練、蒐證與測試，需要明確範圍和授權。
- **M01-04／05：入口與行為**。電話、簡訊、帳號復原流程都可能成為接觸點；再依實際行為分析，不因一個警訊就宣稱已完成整條攻擊。
- **M01-07：事件應變**。先控制風險，再根據紀錄釐清影響、恢復與改善。

## 九、證據判讀：接到電話、交出碼、帳號被用，是不同層次

小林事後說：「我有接電話，而且好像念過一組碼。」資安人員應先接住通報，記錄他做過什麼，不責怪，也不直接寫成「全公司資料已外洩」。

下面是**教學用證據矩陣**：

| 已有資訊 | 可以支持什麼？ | 還不能直接斷定什麼？ |
| --- | --- | --- |
| 手機顯示一則簡訊與一通來電 | 有相應訊息或通話紀錄 | 顯示的來源就是真實身分 |
| 小林表示自己念出登入驗證碼 | 有憑證暴露的陳述，應立即依風險處置 | 對方一定成功登入 |
| 平台記錄某次驗證成功 | 該次驗證流程成功 | 一定是攻擊者，也不代表讀過全部資料 |
| 有不尋常的權限變更或檔案下載 | 存在需要核查的活動 | 所有變更都惡意、所有下載都已外傳 |
| 獨立窗口確認未曾提出該要求 | 支持該身分／要求可能遭冒用 | 事件的全部來源與影響已釐清 |

要交叉核對的內容可以包括時間、帳號、裝置、實際操作、服務工單及資料存取紀錄。**Log（日誌／系統紀錄）** 是系統留下的活動記載；它是證據來源之一，不是永遠完整的現場錄影。

找不到異常紀錄，不等於保證沒事；可能是沒有記錄、保存時間不足，或尚未找到正確資料。另一方面，陌生裝置或異常時間也可能有合理原因，仍需查證。

**處置不必等到百分之百確定；結論卻要寫在證據能支持的範圍內。** 如果已提供密碼、登入驗證碼，或允許可疑遠端協助，應立即透過正式管道通報，由負責人依情況保護帳號、處理工作階段與裝置。不要為了確認而再次執行可疑內容，也不要自行清除所有紀錄。

## 十、兩分鐘桌上練習：不打電話，也能看見信任從哪裡來

這是紙上觀察，不需要上網、不需要輸入帳號，也不算已完成實作。

在紙上畫兩條路：

**路線 A：可疑簡訊 → 簡訊內客服連結 → 客服提供的回撥號碼 → 對方說「確實是我們」。**

**路線 B：可疑簡訊 → 暫停 → 自己開啟既有公司服務台 → 核對工單與承辦人 → 按權限處理。**

把每一步的「聯絡資料是誰提供的」圈出來。

路線 A 看起來查了三次，但查證來源仍由可疑訊息一路提供；路線 B 則把確認權交回原先已建立的可信程序。這是兩者真正的差別，不是用了幾個 App，也不是問了幾次「你真的是客服嗎」。

## 十一、考試與實務最容易混淆的地方

| 容易誤判 | 比較精確的理解 |
| --- | --- |
| 電話詐騙一定要用 AI 假聲音 | 真人、錄音或其他語音形式都可能；AI 不是必要條件 |
| Vishing、Smishing、冒充只能選一個 | 管道與手法可以同時成立，先看題目問哪個角度 |
| 簡訊在熟悉的對話串裡，就是真的 | 顯示名稱、號碼與對話串位置都不能單獨取代驗證 |
| 沒有點連結，所以沒有任何風險 | 也可能直接提供資料、念出驗證碼或照電話指示操作 |
| 換成電話確認，就算獨立查證 | 要看號碼的來源；用可疑訊息提供的號碼，仍可能落在同一圈 |
| 有 MFA 就絕對不會被釣魚 | 驗證方式不同，保護不同；登入安全也不等於付款授權合理 |
| 接到詐騙電話就代表已被入侵 | 接觸、暴露、登入、操作與損害需要分開查證 |

其中，假訊息可能混入原本可信簡訊對話串的情況，已有官方防護資料說明；並不是所有手機或所有事件都一定如此。[加拿大資安中心：簡訊來源偽冒](https://www.cyber.gc.ca/en/guidance/smishing-protect-yourself-sms-attacks-itsap00103)

## 十二、一個小檢核：請用自己的話判斷

**情境：** Northstar 的一般行政承辦人收到「帳號需驗證」簡訊，接著有人打電話自稱資訊服務台，正確說出專案名稱。對方要求提供登入驗證碼，並說只能用簡訊裡的號碼回撥確認。承辦人表示已念出驗證碼，目前尚未取得平台登入與資料存取紀錄。

請用幾句話回答同一個情境：

1. 若確認這是攻擊，簡訊、電話與「自稱資訊服務台」各對應本課哪個概念？它們能同時成立嗎？
2. 你會怎麼查證，才能離開對方安排的管道？
3. 現在能直接認定帳號已遭入侵、教材已外洩嗎？請區分已知風險、待查證結果與應先做的事。

不需要寫很多，也不用給信心分數。**參考解答與本人作答是不同資料；目前先保留題目，等你回答後再針對推理回饋。**

### 本課總結

- **Vishing 看語音管道，Smishing 看簡訊管道，Impersonation 看冒充身分。**
- **熟悉的號碼、聲音、背景與真驗證碼，都不能單獨證明對方及要求可信。**
- **查證要離開可疑來源控制的管道；處置可以先做，結論要依證據。**
