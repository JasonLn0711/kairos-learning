# CEH M20 密碼學｜從零開始，學會判斷每一題

白話深度教學｜M20-R01 對稱加密、M20-R02 非對稱加密與數位簽章｜涵蓋原始第 19–27 題

這次我們不以背誦 AES、RSA、DSA、Twofish 等演算法的名稱為目標，而是要建立一套可以真正解題的知識。

你只要先掌握一個核心觀念：密碼學使用不同工具，解決不同的安全問題。

例如，銀行透過網路傳送一筆 10 萬元的交易紀錄，可能需要同時解決四件事：

1. 別人不能偷看交易內容。
2. 別人不能偷偷把 10 萬元改成 100 萬元。
3. 收件者能確認交易訊息來自可信的銀行系統。
4. 銀行與客戶必須安全地建立通訊金鑰。

這四項要求不是單靠同一個加密演算法就一定能全部完成。

## 第一階段｜先理解密碼學到底在做什麼

這張圖就是整堂課的知識主幹。後面的所有演算法，都可以放回這四個位置。

### 2. 先認識六個基本術語

假設我們有一句話：

`Transfer NT$100,000 to Account B`

這是銀行要傳送的原始交易指令。

| 英文術語              | 中文    | 白話意思                |
| ----------------- | ----- | ------------------- |
| Plaintext         | 明文    | 原本可以讀懂的資料           |
| Ciphertext        | 密文    | 經過加密後、不能直接理解原始內容的資料 |
| Encryption        | 加密    | 把明文轉換成密文            |
| Decryption        | 解密    | 使用適當金鑰與方法還原明文       |
| Algorithm         | 演算法   | 規定資料如何被運算與轉換的方法     |
| Cryptographic Key | 密碼學金鑰 | 控制加解密運算的秘密值或相關金鑰材料  |

你可以把演算法想成一部保險箱的鎖具機構，而金鑰是開啟它的鑰匙。

演算法通常可以公開，真正必須保密的是秘密金鑰。

這點非常重要：現代密碼學不應只靠隱藏演算法本身來維持安全。

### 3. 為什麼加密後會變成看不懂的內容？

電腦所有資料底層都是位元（Bit）。

一個 Bit 只有兩種可能值：

`0` 或 `1`

八個 Bits 組成一個 Byte（位元組）。

例如，英文字母 A 在 ASCII 編碼中可以表示為：

`01000001`

加密演算法會根據金鑰，對資料執行一系列經過設計的數學轉換。

明文 Plaintext

Transfer NT$100,000

加密演算法 + 秘密金鑰

例如 AES-256

密文 Ciphertext

7F 2A 91 C0 5B ...

示意字串，非實際 AES 運算結果

使用正確金鑰與解密程序

恢復原始明文

Transfer NT$100,000

這裡要特別理解兩件事。

第一，加密不是單純把文字換成另一種編碼。Base64、十六進位表示法都不是加密，因為一般人不需要秘密金鑰就可以反向解碼。

第二，加密演算法本身只是密碼系統的一部分。實務上還需要適當的加密模式、初始化資料、金鑰管理與錯誤處理。

這也解釋為什麼「我們使用 AES-256」不能單獨證明整套系統安全。

## 第二階段｜對稱加密：為什麼 AES、Twofish、Blowfish 不一樣？

對應原始題目：19、21

### 1. 什麼叫 Symmetric Encryption？

Symmetric 是「對稱」的意思。

假設 Alice 要寄一個上鎖的箱子給 Bob。

Alice 使用一把鑰匙把箱子鎖上，Bob 使用相同的鑰匙打開。

這就是對稱加密。

Alice

加密

同一把金鑰 K

共享秘密

Bob

解密

優點：運算效率通常很高，適合處理大量資料。

難點：Alice 和 Bob 必須先安全取得共同的秘密金鑰。

這是 AES 與 Twofish 所屬的類型。

### 2. 什麼是 Block Cipher？

Cipher 是「密碼演算法」，Block 是「資料區塊」。

Block Cipher（區塊加密演算法）是指：一次對固定長度的資料區塊進行加密轉換。

想像工廠有一台機器，每次只能放進 16 個相同大小的小盒子。

無論你要處理幾千個盒子，機器每次工作的基本單位仍然是 16 個。

這就類似 128-bit Block Cipher。

假設：

\\[ 1\text{ Byte}=8\text{ bits} \\]

那麼：

\\[ 128\div 8=16\text{ Bytes} \\]

因此，128-bit Block 的意思是，每個加密區塊有 16 bytes。

不是整份檔案只能有 16 bytes。

要加密更長的資料，系統會用適當的 Mode of Operation（運作模式）來處理多個區塊。

### 3. Key Size 與 Block Size 絕對不能搞混

原始題目寫：

> operates on 128-bit blocks, accepts keys up to 256 bits

意思是：

這個演算法以 128 位元為資料區塊，支援最長 256 位元的金鑰。

Block Size

128 bits = 16 bytes

機器一次處理的資料大小。

Key Size

256 bits = 32 bytes

控制加密轉換的秘密金鑰長度。

AES 的三種標準版本分別使用 128、192、256-bit 金鑰，但每一種的 Block Size 都是 128 bits。這是 NIST FIPS 197 的正式規定。

[image](https://www.google.com/s2/favicons?domain=https://csrc.nist.gov\&sz=32)

NIST Computer Security Resource Center



所以：

看到 128-bit Block + 256-bit Key，不能直接說一定是 Twofish。

### 4. Stream Cipher 又是什麼？

除了 Block Cipher，還有 Stream Cipher（串流加密演算法）。

兩者最簡單的差別：

| 特性     | Block Cipher         | Stream Cipher        |
| ------ | -------------------- | -------------------- |
| 基本處理方式 | 固定大小的資料區塊            | 產生金鑰串流，和資料逐位元或逐位元組結合 |
| 例子     | AES、Twofish、Blowfish | RC4、ChaCha20         |
| 題目辨識   | 常出現 Block Size       | 常出現 Keystream        |
| 實務注意   | 需要正確運作模式             | 需要正確 nonce／金鑰串流使用規則  |

Keystream 是「金鑰串流」，可以想成演算法利用秘密金鑰等輸入產生的一長串位元，再與資料結合。

因此，第 19 題如果出現 RC4，光是「128-bit block」這個條件，就可以排除它。

因為 RC4 不是固定區塊長度的 Block Cipher。

### 5. Twofish 與 AES 的歷史關係

這是兩題最重要的知識。

以前常用的 DES（Data Encryption Standard）因為金鑰太短等問題，逐漸不符合新的安全需求。

美國 NIST 因此舉辦一場公開評選，尋找新一代的對稱加密標準。

最後有五個演算法進入決選：

### AES 選拔：五個決選者

MARS

決選演算法

RC6

決選演算法

Serpent

決選演算法

Twofish

決選演算法

Rijndael

獲選為 AES

來源：NIST《Report on the Development of the AES》。

[image](https://www.google.com/s2/favicons?domain=https://csrc.nist.gov\&sz=32)

NIST Computer Security Resource Center

可以把它想成一場有五個決賽選手的競賽。

Twofish 是決賽選手之一，但不是冠軍。

Rijndael 才是最後獲選的演算法，也就是 AES 標準所採用的設計。

因此：

- 問「誰曾經是 AES 決選者，但沒有獲選？」可以選 Twofish。
- 問「哪個演算法最後獲選為 AES？」是 Rijndael。
- 只問「誰曾進入 AES 決選？」則 Twofish 和 Rijndael 都符合，不能直接排除 AES。

### 6. 第 19、21 題怎麼解？

| 題目          | 選項                               | 正解 |
| ----------- | -------------------------------- | -- |
| 19. EC-Q493 | A RC4、B AES、C Blowfish、D Twofish | D  |
| 21. P1-Q114 | A Blowfish、B Twofish、C RC4、D AES | B  |

兩題其實是同一個考點，只是交換了選項排序。

解題順序：

先看 128-bit block，可以排除 RC4 與使用 64-bit block 的 Blowfish。

剩下 AES 與 Twofish。

再看 AES 競賽的歷史，出題者預期的是曾進入決選但未獲選的 Twofish。

所以選 Twofish。

不過，原始題幹沒有明確寫出「未獲選」，因此嚴格而言無法完全排除 AES。這是題庫措辭的缺陷，不應把它誤認成密碼學定律。

你應該真正記住的是：

AES 與 Twofish 都是 128-bit Block Cipher，也都支援 256-bit 金鑰。Twofish 是 AES 選拔的決選演算法；Rijndael 才是最後獲選的設計。

## 第三階段｜磁碟加密：為什麼 VeraCrypt 不一定能阻止資料外洩？

對應原始題目：20. EC-Q024

這題的難度不在於記住 VeraCrypt 的名稱，而在於能不能分辨「資料儲存時的安全」與「電腦正在被攻擊時的安全」。

### 1. 先理解電腦硬碟如何儲存檔案

假設你電腦裡面有一顆 1 TB SSD。

裡面有 Windows、資料庫、照片、文件與各種應用程式。

Disk（磁碟）是實際或邏輯上的儲存裝置；Partition（分割區）則是磁碟中劃分出來的區域。

你可以把它想成一棟大樓：

整棟大樓相當於一顆磁碟。

不同樓層相當於不同分割區。

而各個房間裡面的文件，相當於不同的檔案。

### 2. 三種常見加密方式

File Encryption（檔案加密）

只把某個文件鎖起來。例如只加密 `patient-list.xlsx`。

Volume Encryption（磁碟區加密）

把一個磁碟區或加密容器整體保護起來，掛載後可像一般磁碟使用。

Full Disk Encryption（全磁碟加密，FDE）

保護整個磁碟或系統儲存範圍。實際哪些區域受保護，取決於產品及配置。

例如，你的筆電不幸遺失。

如果硬碟已經妥善加密、電腦也已關機，撿到的人即使把 SSD 拆下來，通常也無法直接讀取裡面的機密資料。

這就是 Encryption at Rest（靜態資料加密）的典型用途。

但如果你已經登入系統、開啟文件，加密系統就必須讓你能正常讀取資料。

這涉及另一個重要名詞：

Mounted Volume（已掛載磁碟區）：作業系統已經把某個磁碟區接入可存取的檔案系統路徑。

Unlocked Volume（已解鎖磁碟區）：相關加密金鑰已經可以用來解密磁碟資料。

掛載與解鎖是相關但不完全相同的概念；加密磁碟區通常須解鎖後才能正常存取。

### 3. VeraCrypt 是什麼？

VeraCrypt 是磁碟加密軟體，可以建立加密容器，也能加密磁碟分割區或其他支援的儲存裝置。

其中一個特色是 Hidden Volume（隱藏磁碟區）。

假設你建立了一個看起來像 100 GB 加密空間的容器。

容器內部可以再建立一個使用不同密碼的 Hidden Volume。

### 隱藏磁碟區如何運作？

Outer Volume 外層加密磁碟區

一般加密資料

Hidden Volume 內層隱藏磁碟區

使用另外一組密碼，存放需要額外隱藏的資料

概念圖，非真實磁碟配置比例。VeraCrypt 的 Hidden Volume 會利用外層磁碟區的可用空間。

[image](https://www.google.com/s2/favicons?domain=https://veracrypt.io\&sz=32)

VeraCrypt

這涉及 Plausible Deniability（合理否認性）。

白話說，就是希望在特定條件下，僅從加密容器的外觀，難以證明容器內另有一個隱藏區域。

但合理否認性不是保證永遠不會被發現。例如，攻擊者若能反覆取得不同時間點的磁碟快照，比較哪些區域發生變動，就可能找到異常線索。

[image](https://www.google.com/s2/favicons?domain=https://veracrypt.io\&sz=32)

### 4. 為什麼伺服器被入侵後，加密可能救不了正在外洩的資料？

題目說，一間醫療機構的伺服器已經被入侵，駭客正在讀取病患紀錄。

我們比較兩種情況。

| 情境       | 磁碟狀態             | 加密的效果             |
| -------- | ---------------- | ----------------- |
| A：筆電遺失   | 關機，磁碟未解鎖         | 可以有效降低離線讀取資料的風險   |
| B：伺服器遭入侵 | 磁碟已解鎖，攻擊者有足夠讀取權限 | 磁碟加密本身無法阻止攻擊者讀取明文 |

原因是，當合法應用程式讀取檔案時，系統必須在某個環節解密資料。

如果攻擊者已經取得足夠權限，可能就能沿著相同的資料存取路徑取得明文。

VeraCrypt 官方也提醒：磁碟加密不是記憶體加密，已開啟檔案的明文與相關金鑰材料可能出現在 RAM（主記憶體）。

[image](https://www.google.com/s2/favicons?domain=https://veracrypt.io\&sz=32)

VeraCrypt



這不是 VeraCrypt 特有的弱點，而是必須理解的威脅模型差異。

Threat Model（威脅模型）就是：先定義我們要防的是誰、他有什麼能力、他能接觸什麼資料，再判斷防護是否有效。

所以，實際應變時應先依事件應變程序控制攻擊者的存取、阻止外洩並保全證據，而不是在受入侵主機上貿然執行大規模加密。

### 5. 第 20 題怎麼解？

EC-Q024：D. VeraCrypt

選項包括 BitLocker、FileVault、Rohos 與 VeraCrypt。

BitLocker 是 Windows 的磁碟加密功能；FileVault 是 macOS 的磁碟資料保護功能。

Rohos 也有加密儲存及隱藏分割區相關功能，所以不能只說「具有隱藏功能」就百分之百排除它。

[image](https://www.google.com/s2/favicons?domain=https://rohos.com\&sz=32)

Rohos



VeraCrypt 最符合題幹整組特徵，尤其是外層加密容器內建立不同密碼的 Hidden Volume。

因此考試選 D。

但實務上，題目敘述的「加密已掛載磁碟，就能立即防止已入侵主機的資料外洩」並不成立。

這題要同時學會兩件事：

考試辨識 VeraCrypt 的功能；實務上辨識加密不能解決的威脅。

### 6. 再補一個專有名詞：Encryption Mode

同樣使用 AES，也可以採用不同的 Mode of Operation（運作模式）。

這可以想成你買了相同的引擎，但把它用在不同用途的機器上。

AES 是核心加密演算法；Mode 則規範如何把它應用於較長的資料或特定場景。

例如：

- XTS-AES：常用於區塊儲存裝置的保密性保護。
- AES-GCM：能在適當條件下提供加密與完整性驗證。

XTS-AES 本身不提供資料認證，這是 NIST SP 800-38E 明確指出的限制。

[image](https://www.google.com/s2/favicons?domain=https://csrc.nist.gov\&sz=32)

NIST Computer Security Resource Center



所以不能簡單說：「只要用了 AES，資料不僅不會被偷看，也一定不會被偷偷修改。」

## 第四階段｜非對稱密碼學：為什麼要有公鑰與私鑰？

對應原始題目：22、23，並延伸至 24–27

### 1. 對稱加密遇到的困難

假設 Alice 和 Bob 從來沒有見過面。

Alice 想用 AES 加密一份合約寄給 Bob。

問題是，Bob 必須有正確的秘密金鑰，才能解密。

那麼 Alice 要怎麼把秘密金鑰交給 Bob？

如果透過不安全的管道直接傳送，金鑰可能被攔截。

這就是 Key Distribution Problem（金鑰分配問題）。

### 2. Public Key 與 Private Key

Asymmetric Cryptography（非對稱密碼學）引入不同的金鑰關係。

Public Key（公鑰）可以公開。

Private Key（私鑰）必須受到保護。

兩者是依照特定演算法建立、具有數學關係的 Key Pair（金鑰對）。

對於支援公鑰加密的方案：

### Alice 寄送機密文件給 Bob

Alice 取得 Bob 的公鑰

這把公鑰可以公開，但身分必須可信

Alice 使用 Bob 公鑰加密

傳送密文

Bob 使用自己的私鑰解密

Alice 不需要取得 Bob 的私鑰

這個概念的價值是：寄件者不需要預先與每個收件者共享同一把秘密金鑰。

但是，要注意：

非對稱密碼學不等於所有演算法都能拿來加密檔案。

RSA 有加密與簽章方案，DSA 主要是簽章演算法，Diffie–Hellman 則是金鑰協議。

### 3. RSA 是什麼？

RSA 是由 Rivest、Shamir、Adleman 三位研究者姓氏組成的名稱。

它是著名的 Public-Key Cryptosystem（公鑰密碼系統）。

RSA 的主要數學基礎涉及大整數模運算與整數分解相關的計算困難性。

我們先不必推導全部數學。

你只需要理解：RSA 的公鑰與私鑰具有特殊的數學對應關係，能夠支援不同密碼學方案。

例如：

| RSA 方案     | 功能            |
| ---------- | ------------- |
| RSAES-OAEP | 公鑰加密、私鑰解密     |
| RSASSA-PSS | 私鑰產生數位簽章、公鑰驗證 |

這兩個是不同的安全方案，不是把公私鑰運算方向對調就能安全地完成所有功能。RFC 8017 詳細規範了兩種方案。

[image](https://www.google.com/s2/favicons?domain=https://www.rfc-editor.org\&sz=32)

RFC Editor



所以當題目問：

> Which is an asymmetric encryption algorithm?

A. AES\
B. DES\
C. RSA\
D. Blowfish

你就可以推理：

AES、DES、Blowfish 是對稱加密演算法。

RSA 是公鑰密碼演算法。

第 23 題 P3-Q056：C. RSA。

### 4. Diffie–Hellman 是什麼？

Diffie–Hellman，簡稱 DH，是一種 Key Agreement（金鑰協議）機制。

它最有趣的地方是：

兩個人即使透過可能被旁聽的網路交換公開資訊，也能在適當安全條件下各自算出相同的共同秘密，而不必直接傳送那個秘密。

先使用一個生活類比。

Alice 有自己的秘密顏色，Bob 也有自己的秘密顏色。

兩人先約定一個公開的基底顏色。

Alice 把基底顏色與自己的秘密顏色混合，傳給 Bob。

Bob 也做類似操作，傳給 Alice。

雙方利用自己保留的秘密，繼續執行可交換順序的混合程序，最後得到相同結果。

顏色混合只是一種幫助理解的類比，真正的 DH 使用數學上的群運算，而不是實際混合顏料。

### 5. 用一個小數學例子理解 DH

這裡的數學是刻意用很小的數字示範，完全不具實際密碼學安全性。

雙方公開約定：

\\[ p=23,\qquad g=5 \\]

其中：

- \\(p\\)：用於模運算的質數。
- \\(g\\)：指定群中的生成元或基底。
- `mod`：取餘數，例如 \\(29\bmod 23=6\\)。

Alice 秘密選擇：

\\[ a=6 \\]

Bob 秘密選擇：

\\[ b=15 \\]

Alice 計算公開值：

\\[ A=5^6\bmod23=8 \\]

Bob 計算公開值：

\\[ B=5^{15}\bmod23=19 \\]

Alice 收到 19 後計算：

\\[ K_A=19^6\bmod23=2 \\]

Bob 收到 8 後計算：

\\[ K_B=8^{15}\bmod23=2 \\]

### 雙方得到相同的共同秘密

Alice

秘密 a = 6

收到 B = 19

K = 2

Bob

秘密 b = 15

收到 A = 8

K = 2

這個共同秘密只是數學示範。真實協定會使用安全參數、驗證機制與 KDF 等程序。

這是 DH 的關鍵：

Alice 沒有把自己的秘密 \\(a\\) 傳給 Bob。

Bob 也沒有把自己的秘密 \\(b\\) 傳給 Alice。

但最後兩人得到相同的共同秘密。

### 6. 那駭客不能直接攔截公開值嗎？

可以攔截。

但是，在安全參數與適當假設下，僅知道公開值，無法在可行時間內推算出共同秘密。

真正需要注意的另一個問題是：攻擊者有沒有可能把公開值換成自己的？

這就是 Man-in-the-Middle Attack（MITM，中間人攻擊）。

### 中間人攻擊的概念

Alice

以為對方是 Bob

Eve

攔截、替換公開值

Bob

以為對方是 Alice

若缺乏身分認證，Eve 可能分別與兩端建立不同的秘密，進而攔截並重新加密訊息。

所以 DH 需要配合身分驗證機制，才能抵抗這類攻擊。

這裡先理解：

建立秘密，不等於知道你正在跟誰建立秘密。

### 7. 為什麼 HTTPS 同時使用多種密碼學技術？

你開啟銀行的 HTTPS 網站時，不是單靠 RSA 或 AES 就完成所有工作。

以使用憑證驗證伺服器、採用 ECDHE 的 TLS 1.3 連線為例：

````
```mermaid
flowchart TD
    A["瀏覽器要連接銀行網站"] --> B["使用 ECDHE 協議建立共同秘密"]
    B --> C["驗證伺服器憑證與交握簽章"]
    C --> D{"身分驗證成功嗎？"}
    D -->|否| E["拒絕可信連線"]
    D -->|是| F["使用 HKDF 導出流量加密金鑰"]
    F --> G["使用 AES-GCM 等 AEAD 保護通訊資料"]
```
````

這是概念流程圖，不是逐封包的精確交握時序。TLS 1.3 也支援其他金鑰建立配置，例如預共享金鑰模式。其正式規範見 RFC 8446。

[image](https://www.google.com/s2/favicons?domain=https://www.rfc-editor.org\&sz=32)

RFC Editor



這裡還有幾個名詞：

TLS（Transport Layer Security）：保護網路通訊的協定。

ECDHE（Ephemeral Elliptic Curve Diffie–Hellman）：使用橢圓曲線數學與暫時性秘密值建立共同秘密的機制。

HKDF（HMAC-based Key Derivation Function）：從適當的秘密材料導出不同用途金鑰的方法。

AEAD（Authenticated Encryption with Associated Data）：在正確使用下，能同時提供加密與完整性驗證，並可認證指定的附加資料。

這也是為什麼實務上通常使用混合式密碼系統（Hybrid Cryptosystem）：透過公鑰機制協助安全建立金鑰，再由高效率的對稱加密保護大量資料。

### 8. 回到第 22 題

EC-Q053：D. Asymmetric encryption

題目希望安全地解決通訊雙方的金鑰分配問題。

出題者要你知道：非對稱密碼學可以支援這項目的。

其他三個選項：

Disk Encryption 是保護儲存資料的技術。

Symmetric Encryption 本身不會自動解決首次交換秘密金鑰的問題。

Hash Functions 只能產生資料摘要，不能單獨完成安全的金鑰建立。

所以最合理答案是 D。

更精確的專業說法是 Public-Key Key Establishment（公鑰金鑰建立），包含金鑰傳送、協議或封裝等特定機制，不應把它們全部混稱為「非對稱加密」。

## 第五階段｜數位簽章：怎麼證明訊息沒被竄改？

對應原始題目：24、25、26、27

這一部分是本次最容易混淆的內容。

你必須先把三個術語分開：

Encryption（加密）是防止偷看；Hash（雜湊）是產生資料指紋；Digital Signature（數位簽章）是利用私鑰產生可由公鑰驗證的簽署證據。

### 1. Hash 是什麼？為什麼像指紋？

假設你準備了一份交易文件：

> 付款 NT$100,000 給廠商 A。

電腦可以把這份文件交給 SHA-256（Secure Hash Algorithm 256）運算，產生一個 256-bit 的摘要。

這個摘要叫 Hash Value（雜湊值），也叫 Digest（摘要）。

文件 A

付款 NT$100,000 給廠商 A

SHA-256

Hash Function（雜湊函數）

256-bit Digest

固定長度的資料摘要

流程示意；未顯示實際計算的 SHA-256 摘要。

假設有人偷偷把金額改成 1,000,000 元。

重新計算 Hash 時，幾乎必然得到不同的摘要。

這涉及 Avalanche Effect（雪崩效應）：輸入即使只有微小變化，輸出也可能出現大幅差異。

但是要注意：

Hash 不等於 Encryption。

Hash 不是設計來讓人使用金鑰還原原文的。它通常屬於 One-Way Function（單向函數）性質的密碼學建構。

而且 Hash 也不是數學上絕對不可能碰撞。

Collision（碰撞）指兩份不同的輸入得到相同的 Hash。安全的密碼學雜湊函數應使攻擊者難以找到可利用的碰撞。

### 2. 為什麼單獨 Hash 還不夠？

假設攻擊者能修改交易文件，也能修改旁邊附上的 Hash。

他把金額改成 1,000,000 元，再替新文件計算一個新的 Hash。

接收方拿到新的文件與新的 Hash，重新運算後發現兩者吻合。

接收方能證明這份文件和所附摘要一致，卻無法單靠這件事證明文件來自銀行。

所以：

Hash 可以協助偵測資料變動，但不能單靠一個未經保護的 Hash 證明訊息來源。

這就需要 Digital Signature 或 MAC（Message Authentication Code，訊息認證碼）等機制。

### 3. Digital Signature 的完整運作流程

想像銀行要寄送一份交易確認書。

銀行首先有自己的私鑰，以及相對應的公鑰。

簽署時：

````
```mermaid
flowchart TD
    A["交易資料 M"] --> B["計算 Hash"]
    B --> C["取得資料摘要 H(M)"]
    C --> D["使用銀行私鑰與簽章演算法"]
    D --> E["產生 Digital Signature"]
    E --> F["傳送資料 M + Signature"]
```
````

收件者驗證時：

````
```mermaid
flowchart TD
    A["收到交易資料 M 與簽章 S"] --> B["確認銀行公鑰的可信身分"]
    B --> C["使用相應公鑰、簽章方案驗證 M 與 S"]
    C --> D{"驗證通過？"}
    D -->|否| E["簽章無效，不能採信"]
    D -->|是| F["取得簽章與資料完整性的密碼學證據"]
    F --> G["再檢查交易授權、時效與業務規則"]
```
````

要注意，數位簽章的具體運作不只是把 Hash 使用私鑰「加密」這麼簡單。

例如 RSA-PSS 需要特殊的編碼程序，而 DSA、ECDSA 有自己的簽章方程式。

這張圖是跨演算法的共同概念。

### 4. 數位簽章可以提供哪三種安全性質？

這是第 26 題的主要考點。

| 英文術語            | 中文    | 白話例子                    |
| --------------- | ----- | ----------------------- |
| Integrity       | 完整性   | 文件簽署後，金額有沒有被修改？         |
| Authentication  | 來源認證  | 這份簽章是否對應銀行受信任的簽署金鑰？     |
| Non-repudiation | 不可否認性 | 能否提出具有歸屬性的證據，支持某方曾進行簽署？ |

NIST FIPS 186-5 也把這三項列為數位簽章的重要安全用途。

[image](https://www.google.com/s2/favicons?domain=https://csrc.nist.gov\&sz=32)

NIST Computer Security Resource Center



但請留意第三項的限制。

不可否認性不是「只要簽章通過，當事人就絕對不能否認」。

如果私鑰被偷、簽章系統遭到操控，或者授權程序存在缺陷，仍然可能產生爭議。

在真實企業環境中，還需要：

PKI（Public Key Infrastructure，公開金鑰基礎建設）：管理憑證、公鑰與信任關係的整體制度及技術。

Digital Certificate（數位憑證）：將公鑰與特定身分或其他屬性連結起來的簽署資料。

CA（Certificate Authority，憑證機構）：按照適用規則簽發及管理憑證的機構。

HSM（Hardware Security Module，硬體安全模組）：專門保護密碼學金鑰並執行相關運算的安全硬體。

Audit Log（稽核紀錄）：記錄誰在什麼時間、透過什麼程序執行特定操作的證據。

### 5. 為什麼「數位簽章不保證保密性」？

假設銀行寄給你一份已經完成數位簽章的交易文件。

任何人只要取得這份文件和簽章，都可能閱讀文件的原始內容。

因為數位簽章本身並沒有把文件變成密文。

所以：

- 想防止別人偷看，應考慮 Encryption。
- 想驗證訊息來源與完整性，應使用適當的 Digital Signature。
- 兩個安全目標都要達到，就必須適當組合相關機制。

第 26 題 P3-Q071：B. Integrity, Non-repudiation, and Authentication。

其他選項提到的 Confidentiality、Availability、Privacy、Speed 等，都不是數位簽章直接提供的完整安全性質組合。

其中 Availability（可用性）是指授權使用者在需要時能取得系統與服務。數位簽章不能保證伺服器不當機，也不能阻止網路中斷。

## 第六階段｜RSA、DSA、Diffie–Hellman、ElGamal 的真正差別

重點對應：24、25、27

我們已經知道這些都屬於公鑰密碼學相關技術。

但考題常故意把不同演算法放在同一組選項裡。

你需要知道每個演算法最獨特的用途與特徵。

### 1. 四種技術的比較

| 演算法            | 你應先聯想到什麼？           | 核心功能           |
| -------------- | ------------------- | -------------- |
| RSA            | 公鑰密碼系統、整數分解、模冪運算    | 加密、簽章、特定金鑰建立方案 |
| DSA            | 數位簽章、一次性秘密值 \\(k\\) | 數位簽章           |
| Diffie–Hellman | 雙方共同建立秘密            | 金鑰協議           |
| ElGamal        | 離散對數、隨機秘密值          | 相關加密與簽章演算法     |

這不是說所有使用模冪運算的簽章都是 RSA。

RSA、DSA、ElGamal 都可能出現模運算或模冪運算。

所以如果題目只寫 modular arithmetic，其實不夠精確。

### 2. DSA 為什麼特別強調一次性隨機值？

DSA 是 Digital Signature Algorithm（數位簽章演算法）。

傳統 DSA 在產生簽章時，需要一個特殊的秘密值 \\(k\\)。

這個 \\(k\\) 常稱為 Per-message Secret Number，也可視為簽章運算中的 Nonce（一次性值）。

為什麼這麼重要？

想像你每次簽署文件，都不只是使用永久的私鑰，還需要額外的一組秘密計算材料。

如果這組材料不夠安全，就可能把永久私鑰暴露出去。

在傳統 DSA 中，簽章會產生兩個數：

\\[ (r,s) \\]

它們是利用訊息摘要、私鑰、一次性值及公開參數計算出來的。

這裡出現三個重要的公開參數：

\\(p\\)：有限域模數，通常為質數。

\\(q\\)：相關子群的階，傳統 DSA 中為質數。

\\(g\\)：子群的生成元。

這就是題目中所謂 Public Domain Parameters（公開域參數）的意思。

不是網域名稱 Domain Name，也不是網站 DNS。

而是數學上定義密碼學運算環境的參數。

### 3. 為什麼 DSA 重複使用 \\(k\\) 很危險？

我們用更深入但簡化的方式理解。

DSA 簽章的一個核心關係是：

\\[ s=k^{-1}(H(m)+xr)\bmod q \\]

其中：

- \\(H(m)\\)：訊息的摘要。
- \\(x\\)：真正需要保護的私鑰。
- \\(k\\)：該次簽章使用的秘密值。
- \\(r,s\\)：簽章的兩個數值。
- \\(q\\)：運算使用的子群階。
- \\(k^{-1}\\)：\\(k\\) 在模 \\(q\\) 運算下的乘法反元素。

這裡的 \\(k^{-1}\\) 不是普通浮點數的除法，而是在模運算裡具有特殊定義的反元素。

如果系統對兩份不同文件，不慎使用相同的 \\(k\\)，就可能暴露足夠的數學關係，讓攻擊者推算出私鑰 \\(x\\)。

換句話說：

不是只有私鑰本身需要保護，簽章過程中使用的秘密材料也需要保護。

這個問題也是為什麼安全的隨機數產生器如此重要。

不過，RFC 6979 定義了 Deterministic DSA／ECDSA（確定性簽章方法）：可以安全地從私鑰與訊息摘要推導簽章用的 \\(k\\)，不必每次取得新的外部隨機輸入。這與意外對不同訊息重複使用不安全的 \\(k\\) 不同。

[image](https://www.google.com/s2/favicons?domain=https://www.rfc-editor.org\&sz=32)

RFC Editor



### 4. DSA 在現代還適合新系統嗎？

這是 CEH 題庫經常沒有跟上的標準變化。

NIST FIPS 186-5 在 2023 年發布後，DSA 只保留既有簽章的驗證用途，不再作為該標準核准的新簽章產生演算法。

標準列出的新簽章產生技術包括 RSA、ECDSA 與 EdDSA。

[image](https://www.google.com/s2/favicons?domain=https://csrc.nist.gov\&sz=32)

CSRC



因此：

考試看到傳統 DSA 特徵，可以依題幹選 DSA。

設計新的受 NIST 標準約束的系統，則不應因此把舊式 DSA 當成預設新選擇。

### 5. 第 24 題怎麼解？

P1-Q085：C. DSA

題目描述一個簽章服務：

- 每次簽章產生新的隨機值。
- 使用公開群參數與子群內的模運算。
- 用公鑰驗證簽章。

從傳統演算法特徵判斷，DSA 最符合出題者想表達的機制。

RSA 也能做簽章，但題目所描述的特定子群參數與一次性秘密值，更指向 DSA。

Diffie–Hellman 主要用於金鑰協議，不是一般數位簽章演算法。

ElGamal 簽章與 DSA 有數學上的共同特徵，也使用一次性秘密值，因此原題並非完全沒有歧義。

但在選項中，DSA 仍是最合理的預期答案。

### 6. 第 25 題：為什麼 RSA 不只是簽章？

P2-Q034：A. RSA

這題描述的步驟是：

先計算交易 Hash，再使用私鑰產生數位簽章，最後使用公鑰驗證。

但是這幾個步驟，單獨來看不能辨識 RSA。

因為 DSA 也會進行類似的簽署與驗證。

關鍵在題目額外宣稱：

> 同一演算法家族支援加密、簽章，以及金鑰建立機制。

這才是出題者希望你聯想到 RSA 的地方。

RSA 的確有不同的加密、簽章與金鑰建立方案。NIST SP 800-56B Rev. 2 也包含 RSA-based 的金鑰傳送及協議方案。

[image](https://www.google.com/s2/favicons?domain=https://csrc.nist.gov\&sz=32)

NIST Computer Security Resource Center



不過，實務上要區分具體的密碼學方案，不能把「RSA 能用於多種目的」解釋成「同一組 RSA 金鑰應同時拿去做所有工作」。

此外，TLS 1.3 已經移除傳統的 Static RSA Key Exchange。

[image](https://www.google.com/s2/favicons?domain=https://www.rfc-editor.org\&sz=32)

RFC Editor



這題的最佳答案是 A，但出題方式仍有概念上的簡化。

### 7. 第 27 題：為什麼公鑰目錄被竄改會危險？

EC-Q084：B. RSA（考試預期）

題目描述支付系統使用私鑰簽署、公鑰驗證，以及模冪運算。

但這幾個條件並不能唯一確認 RSA，因為 DSA 與 ElGamal 類簽章也可能符合部分描述。

真正值得學習的是公鑰驗證的信任問題。

假設你收到一份銀行交易確認書。

你拿公鑰去驗證它，結果成功。

但你從未確認這把公鑰真的屬於銀行。

如果攻擊者能替換公鑰目錄，他可以建立自己的金鑰對，簽署假的交易文件，再把自己的公鑰冒充銀行的公鑰。

於是你可能得到：

「簽章驗證成功」。

卻做出錯誤的身分判斷：

「一定是銀行簽署的」。

這正是 PKI 與可信公鑰綁定所要處理的問題之一。

因此，請把下列兩句分清楚：

Signature Valid：簽章在指定公鑰下通過數學驗證。

Signer Identity Verified：已透過可信程序，確認這把公鑰與預期的簽署身分具有正確關係。

前者不自動保證後者。

## 第七階段｜把九題變成固定的解題方法

現在你已經學過所有必要的基礎概念。

### 3. 你至少要能區分這十個專有名詞

| 專有名詞                         | 一句白話解釋                        |
| ---------------------------- | ----------------------------- |
| Symmetric Encryption         | 雙方使用共同秘密金鑰保護資料                |
| Asymmetric Cryptography      | 利用公鑰與私鑰的數學關係實現特定密碼學功能         |
| Block Cipher                 | 一次轉換固定長度的資料區塊                 |
| Stream Cipher                | 產生金鑰串流並與資料結合的加密機制             |
| Key Exchange / Establishment | 讓通訊雙方建立或取得共同秘密金鑰              |
| Hash Function                | 把任意長度資料映射成固定長度摘要              |
| Digital Signature            | 用私鑰產生可由公鑰驗證的簽署資料              |
| Nonce                        | 在特定密碼學操作範圍中有唯一性要求的值；具體要求依協定而定 |
| Modular Exponentiation       | 進行次方運算後取模數餘數的數學計算             |
| Public Key Authentication    | 驗證公鑰是否確實與預期的身分或實體綁定           |

如果這些專有名詞仍然有不清楚的地方，可以回到前面的銀行、保險箱、磁碟區與 DH 例子重新對照。

第 1 題｜對稱加密與規格識別

某公司使用 128-bit Block、256-bit Key 的加密演算法。廠商宣稱這一定是 Twofish。你會如何判斷？

A. 正確，只有 Twofish 有這種規格

B. 正確，因為 AES 只使用 128-bit 金鑰

C. 無法唯一判定，因為其他演算法也可能符合這組規格

D. 應該是 RC4，因為 RC4 也使用固定 128-bit Block

第 2 題｜磁碟加密與威脅模型

一台已開機並解鎖磁碟的資料庫伺服器遭到入侵，攻擊者已有讀取病患資料的權限。下列何者最正確？

A. 重新加密磁碟就會自動停止外洩

B. 安裝 VeraCrypt 的 Hidden Volume 就能清除攻擊者

C. 必須先處理攻擊者存取權限、外洩與證據保全；磁碟加密不能單獨解決問題

D. 只要產生 SHA-256 Hash，就能避免病患資料被讀取

第 3 題｜金鑰建立與身分驗證

Alice 與 Bob 透過 DH 建立共同秘密，但沒有驗證收到的公開值究竟來自誰。最大的問題是什麼？

A. DH 無法建立共同秘密

B. 攻擊者可能替換公開值，分別與雙方建立不同的秘密

C. 使用公鑰交換一定會暴露自己的私鑰

D. 所有資料都必須改成 DSA 加密

第 4 題｜Hash 與數位簽章

你正在設計銀行交易 API。團隊建議只在交易 JSON 後附上一個 SHA-256 Hash，便宣稱可以證明交易一定來自銀行。這個設計缺少什麼？請解釋如何改善。

第 5 題｜辨識簽章演算法
