## 課程總覽：先理解整張資安地圖

資訊安全其實可以從三個問題開始學習。

第一個問題：我們要保護什麼？

CIA：保密性、完整性、可用性

第二個問題：要怎麼保護？

Security Controls：實體、技術、管理控制

第三個問題：怎麼知道保護有效？

Ethical Hacking：經授權測試、找漏洞、改善風險

這三個問題有因果關係：先決定要保護的目標，再建立防護措施，最後透過測試確認措施是否能抵擋實際威脅。

接下來我們用同一家公司作為案例，逐步理解。

## 第一章｜資訊安全究竟在保護什麼？CIA 三要素

### 1. 先從一個生活情境理解

假設你經營一家診所，診所使用電腦系統管理病歷。

某天發生以下三件事：

事件 A： 一名陌生人偷偷讀取了病人的身分證字號、姓名、病史。

事件 B： 一名員工不小心把病人的用藥劑量從 5 毫克改成 50 毫克。

事件 C： 診所的資訊系統突然故障，醫師無法讀取病歷。

我們可以分別問：

- A：不應該看到資料的人，看到了嗎？
- B：資料有沒有被不當修改？
- C：需要使用資料的人，還能不能正常使用？

這就是資訊安全最基本的三種保護目標。

# C

Confidentiality

保密性

不該看的人不能看

# I

Integrity

完整性

資料必須正確可信

# A

Availability

可用性

需要時能正常使用

這三個英文單字的定義，可以在美國 NIST 的 FIPS 199 資訊安全標準中找到。

### 2. Confidentiality：保密性

Confidentiality 的意思是：只有被允許的人，才能取得受保護的資訊。

想像你把銀行帳戶密碼寫在一張紙上。

紙上的密碼沒有被修改，也沒有消失，但有人偷看了它。

這就是保密性遭到破壞。

在電腦系統裡，常見的保密性問題包括：

- 未授權的人讀取客戶資料。
- 網路封包中的敏感資訊被攔截並讀取。
- 公司將本應私密的文件錯誤設定為公開。
- 使用者將機密資料寄給錯誤的收件人。

這裡有幾個重要的英文名詞。

| 英文                    | 中文    | 白話解釋                    |
| --------------------- | ----- | ----------------------- |
| Confidential          | 機密的   | 不是所有人都能看的資訊             |
| Unauthorized          | 未經授權的 | 沒有被允許做這件事               |
| Disclosure            | 揭露、洩露 | 資訊被提供給別人                |
| Intercept             | 攔截    | 在資訊傳遞途中取得它              |
| Cleartext / Plaintext | 明文    | 沒有經過適當加密保護、可以直接閱讀的內容    |
| Encryption            | 加密    | 使用密碼學方法，讓沒有適當金鑰的人難以理解內容 |

#### 為什麼要加密？

假設你在網路上傳送一句話：

原始資料：明文（Plaintext）

我的銀行密碼是 123456

使用加密演算法與金鑰

加密後：密文（Ciphertext）

7F A2 9C 41 ...

僅示意密文的呈現形式，並非實際加密計算結果。

使用適當金鑰解密

還原原始內容

Encryption（加密）就像把信件放進只有合適鑰匙才能打開的保險箱。

現在延伸一個專有名詞：

TLS（Transport Layer Security，傳輸層安全協定） 是 HTTPS 等通訊協定所使用的重要安全機制，能在正確實作與驗證的前提下，保護傳輸中的資料機密性及完整性。

請注意：不是所有資料加密都等於 TLS，也不是用了 HTTPS 就代表資料在所有儲存及處理環節都安全。

### 3. Integrity：完整性

Integrity 的意思是：資料不能被未經授權或不適當地修改、破壞。

例如銀行系統原本記錄：

`存款餘額：100,000 元`

結果遭到未經授權的竄改，變成：

`存款餘額：900,000 元`

這時最重要的問題是什麼？

不是別人看到了資料，而是資料已經不正確。

這就破壞了 Integrity。

這裡可以再學三個重要名詞。

Tampering（竄改）：未經授權修改資料。

Hash（雜湊）：一種將資料轉換成固定長度摘要值的密碼學機制。常用來比對資料是否發生變動。

Digital Signature（數位簽章）：利用密碼學機制驗證資料來源與完整性，在適當條件下還能支持不可否認性。

舉例來說，你下載一個 Ubuntu ISO 映像檔，網站提供官方 SHA-256 雜湊值。下載後，計算檔案的 SHA-256，如果兩者相同，可以提供檔案內容一致的強力證據。

但有個很重要的細節：

Hash 相同不代表檔案一定可信。 如果攻擊者同時替換檔案與網站上的 Hash 值，你仍有可能被欺騙。因此，Hash 用來檢查內容是否一致，而資料來源是否可信，需要額外的認證機制。

### 4. Availability：可用性

Availability 的意思是：有權使用系統的人，需要時能及時、可靠地使用。

假設醫院系統沒有外洩資料，也沒有人改動病歷，但伺服器突然停止運作。

醫師仍然無法替病人查詢用藥紀錄。

這就是 Availability 問題。

再認識幾個名詞。

| 名詞                     | 意義      | 例子              |
| ---------------------- | ------- | --------------- |
| DoS（Denial of Service） | 阻斷服務    | 使系統無法正常服務       |
| DDoS（Distributed DoS）  | 分散式阻斷服務 | 來自多個來源的大量攻擊流量   |
| Redundancy             | 備援      | 準備額外設備或系統避免單點故障 |
| Backup                 | 備份      | 保留資料副本以協助復原     |
| Disaster Recovery      | 災難復原    | 發生重大事故後恢復服務的能力  |

備份主要協助復原資料，並不保證服務能立即恢復；系統備援與故障轉移才更直接支援持續可用性。

### 5. Non-Repudiation：不可否認性

你的原題還有一個容易混淆的選項：

Non-Repudiation（不可否認性）。

假設甲公司與乙公司簽署一份電子合約。

幾個月後，甲公司主張：「這不是我們簽署的文件。」

如果有可信的數位簽章、金鑰管理、身分驗證及其他佐證，就能提供證據，支持某個行為確實出自特定簽署者。

所以不可否認性想解決的是：

「之後有人否認做過這件事，我們有什麼可靠證據可以判斷？」

NIST 將數位簽章與資料來源認證、完整性及不可否認性連結起來，但這不代表只要有數位簽章，就能在任何法律爭議中自動確定實際操作的人。

[image](https://www.google.com/s2/favicons?domain=https://csrc.nist.gov\&sz=32)

CSRC+1



### 6. 把四個名詞放在一起比較

| 問題         | 主要對應            |
| ---------- | --------------- |
| 秘密資料被偷看    | Confidentiality |
| 銀行餘額遭到竄改   | Integrity       |
| 伺服器故障無法登入  | Availability    |
| 有人否認自己簽署文件 | Non-Repudiation |

真實事件可能同時影響 CIA 多個面向。CEH 單選題通常要求你根據題目最直接描述的安全問題選擇最佳答案。

### 7. 回到原題 P1-Q003

題目敘述一間律師事務所，使用電子郵件傳送敏感法律文件。

其中四段英文特別重要：

- `sensitive legal documents`：敏感法律文件。
- `clear text`：以明文形式傳輸。
- `intercepting the traffic`：攔截網路流量。
- `unauthorized individuals ... view`：未經授權的人可以查看。

你可以這樣推理：

第一步，資料有沒有被修改？題目沒有說。

第二步，系統有沒有不能使用？題目沒有說。

第三步，有沒有發生身分或行為否認的爭議？沒有。

第四步，資料是否有被未授權者讀取的風險？有，這正是題目重點。

所以答案是 B. Confidentiality。

這一題要學會的不是「看到 clear text 就選 B」，而是：

> 當安全事件的核心問題是未經授權取得資訊內容，優先思考 Confidentiality。

## 第二章｜什麼是安全控制（Security Controls）？

對應原題：P3-Q113。

### 1. 為什麼資訊安全不能只依靠防火牆？

想像你有一家公司，所有重要的客戶資料都放在一個機房裡。

公司購買了昂貴的防火牆，也替伺服器安裝防毒軟體。

某天有人直接走進機房，把伺服器硬碟帶走。

你可能會疑惑：「我們不是已經有很好的資訊安全設備了嗎？」

問題在於，防火牆主要管理網路流量，不能取代實體門禁。

這就是 Security Controls（安全控制）的概念。

安全控制是指組織為了降低安全風險，所採取的各種保護措施。它不一定是一個軟體，也可以是一項制度、一名保全、一把門鎖。

NIST 的定義也包含技術、人員、管理和實體環境相關的保護措施。

### 3. 四個很容易混淆的技術名詞

| 名詞                 | 白話解釋            | 主要用途       |
| ------------------ | --------------- | ---------- |
| Firewall（防火牆）      | 網路流量的交通警察       | 依規則允許或阻擋通訊 |
| Antivirus（防毒軟體）    | 偵測和處理惡意程式的工具    | 降低惡意軟體風險   |
| Encryption（加密）     | 把資料放進有密碼學保護的保險箱 | 保護資料機密性    |
| Security Guard（保全） | 在現場管理人員進出       | 實體安全防護     |

以防火牆為例，假設一部伺服器只需要讓外部使用者透過 HTTPS 存取網站。

防火牆可以設定規則，允許必要的通訊，阻擋不符合規則的連線。

但是它不是萬能的。

即使防火牆允許的是正常 HTTPS 流量，網站程式本身仍然可能存在安全漏洞。因此，部署防火牆並不表示網站程式一定安全。

### 4. 什麼是縱深防禦（Defense in Depth）？

假設你把一個價值一億元的物品放在保險箱裡。

你會只靠一把鎖嗎？

比較合理的設計是：建築入口有門禁，內部有保全，重要區域需要額外驗證，保險箱本身還有獨立的鎖。

就算第一道防線失效，攻擊者也不一定能直接拿到物品。

這就是縱深防禦。

以機密資料系統為例

第 1 層｜Physical

保全、門禁與機房管制

第 2 層｜Identity

身分驗證、MFA 與權限限制

第 3 層｜Network

防火牆與網路區隔

第 4 層｜Data

加密、資料存取控制

第 5 層｜Detection & Recovery

監控、備份、復原與事件應變

MFA 是 Multi-Factor Authentication（多因素驗證），意思是使用至少兩種不同類型的驗證因素，例如密碼加上實體安全金鑰。

縱深防禦的關鍵並不是「購買很多資安產品」，而是不同控制措施能夠處理不同失敗情況。NIST 也將它描述為整合人員、技術與作業能力的多層防護策略。

### 5. 安全控制還有另一種分類方式

前面介紹的是「控制如何實施」，但也可以依「控制發揮什麼作用」分類。

| 控制功能 | 英文         | 白話解釋          |
| ---- | ---------- | ------------- |
| 預防性  | Preventive | 事先阻止問題發生      |
| 偵測性  | Detective  | 發現正在發生或已發生的問題 |
| 矯正性  | Corrective | 事故發生後修正問題     |
| 復原性  | Recovery   | 協助恢復受影響的服務    |

例如保全可以阻止未授權人員進入，也可能發現可疑活動。

因此，一個控制措施可以同時具有多種功能。

這點很重要：Physical 和 Preventive 不是互斥選項。前者描述實施形式，後者描述功能。

### 6. 回到原題 P3-Q113

題目：

Which of the following is a "Physical" security control?

翻譯：下列哪一項屬於實體安全控制？

| 選項                | 分析           |
| ----------------- | ------------ |
| A. Firewall       | 防火牆主要屬於技術控制  |
| B. Antivirus      | 防毒軟體主要屬於技術控制 |
| C. Security Guard | 保全是實體安全控制    |
| D. Encryption     | 加密是技術性保護機制   |

所以答案是 C. Security Guard。

這題你要記住的是辨識方法：題目問 Physical，就想「現場的人員、設施、實際進出與設備保護」。

## 第三章｜什麼是倫理駭客（Ethical Hacking）？

這是今天最重要的章節，涵蓋其餘七題。

### 1. 先弄懂 Hacker 到底是什麼

Hacker（駭客）這個詞，在不同時代與情境有不同含義。它可以指擅長理解、修改或探索技術系統的人，也常被用來指入侵電腦的人。

但在 CEH 考試中，更重要的不是「這個人會不會寫程式」，而是他進行安全測試時的目的、授權及行為。

假設兩個人都使用同一套工具測試一間公司的網站。

甲獲得公司正式授權，要檢查網站是否存在漏洞。

乙沒有經過公司同意，卻擅自進行同樣的測試，還打算偷取客戶資料。

使用工具可能相同，行為的授權基礎與目的卻完全不同。

### 2. White Hat、Black Hat、Grey Hat

White Hat（白帽駭客）

在有效授權範圍內執行安全測試，目的是找出並改善安全問題。

例子：公司聘請資安顧問進行滲透測試。

Black Hat（黑帽駭客）

通常指為了竊取、破壞或其他惡意目的，未經授權侵害系統的人。

例子：入侵公司的資料庫，偷取客戶帳號。

Grey Hat（灰帽駭客）

可能沒有直接的惡意或獲利目的，卻在缺乏授權的情況下進行測試。

例子：未經同意嘗試驗證網站漏洞，之後再通知站長。

現在要釐清一個特別重要的觀念：

沒有惡意，不代表行為一定合法。

假設你發現鄰居的家門沒有鎖好。

你覺得自己是在幫忙確認安全性，於是直接進去查看，最後還告訴鄰居「你家很不安全」。

你的出發點可能是好的，但這並不自動使進入他人住宅的行為合法。

網路安全測試也是如此。

補充兩個考試可能出現的名詞：

Script Kiddie（腳本小子） 指主要依靠現成工具或攻擊程式、技術理解相對有限的人。這不是一個與白帽、黑帽完全對等的授權分類。

Blue Hat（藍帽） 在不同資料中定義不一致，有時指受邀進行外部安全測試的人。它也不等於 Blue Team（藍隊，主要負責防禦的安全團隊）。若題目明確描述經授權進行測試，而選項有 White Hat，通常應優先選擇 White Hat。

### 3. Penetration Testing 是什麼？

Penetration Testing，簡稱 Pentest，中文叫做滲透測試。

這個名詞聽起來很技術，但可以從房屋安全檢查理解。

假設屋主想知道家裡的門窗能不能抵擋入侵。

他聘請專業人員，在事先約定的條件下，模擬可能的入侵方式。

檢查人員除了指出哪扇窗戶容易打開，也可能實際、安全地驗證弱點是否會造成不當進入。

電腦系統的滲透測試也是這個概念。

NIST SP 800-115 將滲透測試描述為模擬真實攻擊，嘗試找出繞過系統安全機制的方法。

[image](https://www.google.com/s2/favicons?domain=https://csrc.nist.gov\&sz=32)

CSRC



### 4. 先學會四個核心專有名詞

假設一家銀行的網路系統有個錯誤設定：原本應該限制存取的資料，可以被不具權限的人取得。

這個故事可以拆成四個名詞。

| 名詞            | 中文    | 白話說明             |
| ------------- | ----- | ---------------- |
| Asset         | 資產    | 需要保護的東西，例如系統、資料  |
| Vulnerability | 弱點、漏洞 | 系統可能被利用的缺陷       |
| Threat        | 威脅    | 可能造成損害的行為者、事件或條件 |
| Exploit       | 利用漏洞  | 透過弱點造成原本不應發生的結果  |

NIST 對 Vulnerability 的定義包括軟體、系統程序、內部控制或實作上的弱點，不限於程式碼錯誤。

[image](https://www.google.com/s2/favicons?domain=https://csrc.nist.gov\&sz=32)

CSRC



再往下理解：

Vulnerability Assessment（漏洞評估） 主要是辨識、分析及評估漏洞。

Penetration Testing（滲透測試） 則進一步嘗試在授權範圍內驗證漏洞能否被實際利用，以及可能造成多大的影響。

兩者不是完全切割的工作，但重點不同。

例如，漏洞掃描器發現某個系統使用存在已知漏洞的軟體版本，這只是一項發現，還需要評估是否適用、是否可被利用。

滲透測試則可能進一步確認是否存在實際的安全影響。

也因此，工具顯示有漏洞，不等於已經證明系統遭到成功入侵。

### 5. 授權（Authorization）到底是什麼？

這是七道倫理駭客題目的共同核心。

Authorization 代表某項操作獲得適當權限或許可。

在滲透測試中，你必須先確認：

誰有權允許測試？允許測試哪些系統？何時能測？能使用哪些方法？遇到意外如何處理？

光說一句「老闆說可以測」並不一定足夠。

例如公司董事長同意測試公司的雲端系統，但其中一部分是第三方廠商的共享平台。董事長不一定有權替其他廠商同意所有測試活動。

所以，授權還涉及授權人的權限與測試標的。

### 6. Scope 與 ROE：合法測試的界線

兩個名詞一定要弄清楚。

Scope（測試範圍）：規定哪些系統、網域、IP、帳號或功能可以接受測試。

Rules of Engagement（ROE，交戰規則）：規定測試要遵守什麼限制與操作程序。

兩者互相關聯，但不是同一件事。

例如某公司要測試員工登入系統：

虛構案例：公司的滲透測試約定

| 測試範圍 | `192.0.2.10` 伺服器 |
| ---- | ---------------- |
| 測試日期 | 星期六 10:00–14:00  |
| 允許方式 | 指定的安全性驗證活動       |
| 禁止事項 | DoS、擅自刪除資料、超範圍存取 |
| 事件通報 | 發現系統異常立即通報指定窗口   |

192.0.2.0/24 是保留供文件與教學使用的 IP 位址範圍。

測試時，你發現隔壁的 `192.0.2.11` 也有可能存在漏洞。

你能順便測嗎？

不能因為你懷疑它有問題，就認定自己被授權測試它。

正確作法是先確認原有 Scope，必要時請求正式變更授權。

NIST 對 ROE 的定義特別強調：交戰規則是在測試前建立的詳細準則和限制，用來授權團隊執行已定義的活動。

[image](https://www.google.com/s2/favicons?domain=https://csrc.nist.gov\&sz=32)

CSRC



這也說明為什麼 P3-Q124 的最佳答案是：

C. Always obtain written permission before testing.

在專業實務中，應事先取得適當的書面測試授權。這是重要的風險管理和證據要求，但書面授權仍須有效、涵蓋實際活動，且符合適用法律。

### 7. 倫理駭客的真正目標

你可能會以為倫理駭客的工作就是「成功入侵系統」。

其實不是。

成功突破某個系統，只是可能用來驗證安全風險的一種方法。

真正的目的，是幫助組織理解哪些弱點需要處理。

從安全測試到降低風險

01

取得授權

確認能測哪些系統及活動

02

找出弱點

辨識可能的安全漏洞

03

驗證影響

在限制內確認弱點是否可被利用

04

提出報告

說明證據、影響與修補建議

05

修補與複測

由負責團隊修補，再確認改善是否有效

因此 EC-Q331 的答案是 B：

To identify and fix security vulnerabilities in a system.

這裡的 fix 不一定是由滲透測試人員親自修改程式，而是指促成漏洞修補與安全改善。

NIST SP 800-115 對安全測試的規劃、執行、分析與改善策略也採用這種整體觀點。

## 第四章｜英文 CEH 題目到底怎麼讀？

目前你不需要先完整翻譯題目的每一個字。

比較有效率的方法，是辨認題目在問哪一類知識，再找關鍵證據。

### 1. 先建立解題決策樹

題目到底在問什麼？

駭客角色

Authorization / Permission

White Hat、Grey Hat、Black Hat

資訊受到什麼影響

Read / Modify / Unavailable

Confidentiality、Integrity、Availability

安全控制種類

Physical / Technical

Security Guard、Firewall 等

安全測試目的

Goal / Primary purpose

找出漏洞、降低風險

這個決策樹是解題導航，不是說真實資安問題只能屬於其中一類。遇到多重影響的事件，仍必須辨識題目所問的主要問題。

### 2. 必須看懂的英文關鍵字

| 英文題目用語                        | 中文解釋    | 應想到什麼          |
| ----------------------------- | ------- | -------------- |
| With permission               | 經過許可    | 授權             |
| Full knowledge and permission | 組織知情且允許 | White Hat      |
| Unauthorized                  | 未經授權    | 不符合白帽測試的基本條件   |
| Written permission            | 書面許可    | 正式授權紀錄         |
| Identify vulnerabilities      | 找出漏洞    | 安全測試目的         |
| Exploit vulnerabilities       | 利用漏洞    | 驗證是否可造成實際安全影響  |
| Sensitive information         | 敏感資訊    | 機密性可能相關        |
| Intercept traffic             | 攔截流量    | 可能影響保密性或完整性    |
| Modify / Tamper               | 修改、竄改   | Integrity      |
| Disrupt services              | 使服務中斷   | Availability   |
| Physical control              | 實體控制    | 保全、門鎖、門禁       |
| Primary goal                  | 主要目標    | 選最能代表核心目的的答案   |
| Best describes                | 最符合描述   | 選最貼切，而非只要沾到邊就行 |

特別注意 `primary` 和 `best`。

這些單字代表你不能只判斷某選項「有沒有可能」，而要判斷哪個答案最直接符合題幹。

## 第五章｜逐題解析：你提供的 9 題

現在我們把剛學的知識拿回來解題。

EC-Q001

題目重點： full knowledge and permission from the organization

公司知道並允許駭客進行滲透測試。

正確答案：D. White Hat Hacking。

Blue Hat 定義不一致；Grey Hat 不符合題目明確的正式授權情境；Black Hat 則與題目的合法安全測試目的不符。

P1-Q003

題目重點： clear text ... intercepting the traffic ... read the contents

敏感法律文件以明文傳輸，未授權者可能讀取內容。

正確答案：B. Confidentiality。

Availability 關心服務能否使用；Integrity 關心資料是否被不當修改；Non-Repudiation 關心能否提出證據來反駁對行為的否認。

P3-Q113

題目重點： Physical security control

問題是在辨認安全控制的實施形式。

正確答案：C. Security Guard。

Firewall、Antivirus、Encryption 主要屬於技術控制。保全則直接管理實體場所的人員進出。

EC-Q054

題目重點： full knowledge and permission

和 EC-Q001 幾乎是同一個概念。

正確答案：C. White Hat。

這題只是改變選項排列。真正應記住的是授權條件，而不是 White Hat 一定在 C 或 D。

P3-Q124

題目重點： main ethical rule

問白帽駭客在安全測試前最重要的倫理要求。

正確答案：C. Always obtain written permission before testing。

A「不擇手段取得存取權」不符合授權界線；B「在暗網販賣漏洞」不是負責任的測試目的；D「不告訴受影響的所有者」也不符合適當通報與報告義務。

EC-Q166

題目重點： hired to legally assess ... identifying vulnerabilities and attempting to exploit them

受聘合法評估安全性，並驗證漏洞。

正確答案：D. White Hat。

Grey Hat 不符合題目明確的授權情境；Black Hat 不是合法安全測試角色；Script Kiddie 描述的是技術能力或使用工具的方式。

EC-Q189

題目重點： main difference between ethical hacking and malicious hacking

問倫理駭客與惡意駭客的核心區別。

正確答案：C. Ethical hacking is performed with permission, while malicious hacking is unauthorized。

A 把合法性顛倒；B 錯在認為兩者一定使用不同工具；D 錯在認為兩者可以用單獨作業或團隊作業區分。

這是題目設定下的最佳區別；實務上還須判斷目的、範圍、法律與行為。

EC-Q331

題目重點： primary goal of ethical hacking

問倫理駭客最主要的工作目的。

正確答案：B. To identify and fix security vulnerabilities in a system。

A 的破壞服務、C 的竊取資訊及 D 的散播惡意軟體，都不是正當安全測試的主要目的。

EC-Q476

題目重點： role of a penetration tester

問滲透測試人員的角色。

正確答案：C. Authorized security professional who exploits vulnerabilities。

最關鍵的字是 Authorized。這裡的 Exploits 指在經授權的範圍內驗證漏洞，而不是無限制攻擊。

到這裡，可以發現有些題目其實在重複測量同一個概念。

| 概念群組    | 題數 | 對應題號                          |
| ------- | -- | ----------------------------- |
| 白帽駭客與授權 | 6  | Q001、Q054、Q124、Q166、Q189、Q476 |
| 安全測試的目的 | 1  | Q331                          |
| CIA 三要素 | 1  | P1-Q003                       |
| 實體安全控制  | 1  | P3-Q113                       |

所以今天真正需要建立的是幾個能重複使用的判斷原則，而不是九個孤立答案。

## 第七章｜最終綜合案例：從資安概念推理到專業判斷

這一題先不提供標準答案，我會依你的作答判斷是否真正掌握本課。

### 情境：某醫療機構的資安測試

一家醫療機構委託外部資安公司進行安全測試。

雙方簽署了正式授權文件，測試範圍為病患預約系統。

測試人員發現以下情況：

情況 A： 系統傳輸病患聯絡資料時未使用適當的加密保護，可能被第三人讀取。

情況 B： 某個功能存在權限檢查問題，未授權的人可能修改病患的預約時間。

情況 C： 系統缺乏足夠的服務可用性保護，一旦遭受大量惡意請求，預約服務可能中斷。

情況 D： 測試人員還發現另一個醫療影像系統，但它不在原本的測試範圍內。

情況 E： 該機構的機房雖然設有防火牆，但任何人都可以直接進入機房。

請回答以下五個問題：

1. 情況 A、B、C 分別主要影響 CIA 的哪一項？為什麼？
2. 測試人員能不能直接對情況 D 的系統進行滲透測試？需要確認什麼？
3. 情況 E 最直接暴露哪一類安全控制不足？你會建議什麼措施？
4. 如果你是這次測試的負責人，你認為報告中至少需要包含哪些資訊，才有助於機構實際改善安全？
5. 假設機構修補了已知漏洞，是否就可以宣稱系統「已經完全安全」？請說明理由。

這五題不是要考英文記憶，而是要你把三個主要知識領域連接起來，形成真正的安全判斷。

你可以直接用「1. … 2. …」的格式回答。我會逐題批改，指出正確的推理、尚不完整的概念，以及可能造成 CEH 失分的誤解；若有答錯，會針對缺口補充教學，再用不同題目複測。

本課主要依據的標準包括 [NIST FIPS 199（CIA 安全目標）](https://csrc.nist.gov/pubs/fips/199/final?utm_source=chatgpt.com)、[NIST SP 800-115（安全測試與滲透測試）](https://csrc.nist.gov/pubs/sp/800/115/final?utm_source=chatgpt.com) 與 [NIST SP 800-53（安全控制）](https://csrc.nist.gov/pubs/sp/800/53/r5/upd1/final?utm_source=chatgpt.com)。這些是概念與實務依據，不代表上述練習題是 CEH 官方題目。
