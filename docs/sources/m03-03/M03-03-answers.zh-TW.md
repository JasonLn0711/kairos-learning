# M03-03 情境題參考答案

## answer-connect-syn｜SYN 流程與 RST 方向

判為 open，依據是目標回覆 SYN＋ACK。最後的 RST 來自掃描端，作用是結束這次嘗試；沒有送出完成一般三向交握的最後 ACK。掃描端作業系統也可能產生這個 RST，不能只憑旗標斷言是目標拒絕。

## answer-udp-silence｜UDP 沉默的可能原因

不能直接判斷 DNS 沒有啟動。可能是服務忽略不合格式的酬載、去程被防火牆丟棄、回覆在回程遺失；ICMP 錯誤限速也可能增加等待結果。保留 open|filtered，補上已授權的有效 DNS 查詢、對應 UDP 回覆、封包擷取，以及監聽設定或服務日誌。服務辨識可能縮小不確定性，沒有回覆仍不能直接確定關閉。

## answer-test-conditions｜內外觀察與 SSH 暴露

兩個結果可以同時成立。來源政策、路由、NAT／連接埠轉送、代理或負載平衡器都可能改變路徑與回應。先確認兩次測試對應同一入口，記錄來源、時間、協定、Port 與方法，再核對公開位址及 IPv4／IPv6 入口、轉送規則、防火牆與 SSH 綁定位址。從核准的外部位置複測並比對日誌；單次 filtered 只支持該來源與時間的觀察，不能證明所有外部路徑都封閉。

## answer-application-check｜網站功能查核（原有檢核）

參考答案：補上應用層服務證據；HTTPS 情境也核對 TLS 安全通道與憑證結果，再檢查 HTTP 回應及預定頁面內容。若任務涉及登入或操作權限，再依核准範圍檢查。每一層各記時間、方法與結果。
