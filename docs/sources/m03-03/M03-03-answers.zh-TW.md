# CEH M03-03｜參考解答

## answer-connect-syn｜小檢核一

參考答案：Connect 由作業系統送出 ACK，完成典型三向交握，工具取得連線結果後結束測試連線。SYN 掃描收到 SYN＋ACK 後，通常送 RST 結束嘗試，並依這份起始回應記為 open。兩者都保留各自方法與實際封包／系統結果。

## answer-udp-silence｜小檢核二

參考答案：服務可能正在監聽，但只回覆格式合適的請求；防火牆也可能過濾探測或回程。封包遺失與錯誤訊息限速也是可查核的因素。因此先保留 open|filtered，再核對酬載、等待與重試設定、政策及服務紀錄。

## answer-application-check｜小檢核三

參考答案：補上應用層服務證據；HTTPS 情境也核對 TLS 安全通道與憑證結果，再檢查 HTTP 回應及預定頁面內容。若任務涉及登入或操作權限，再依核准範圍檢查。每一層各記時間、方法與結果。

## answer-test-conditions｜小檢核四

參考答案：至少比較觀察來源與網段、時間、TCP 或 UDP、目的埠、掃描方法、工具版本、等待與重試設定、速率及酬載。也可核對 NAT／代理路徑與當時的防火牆、監聽設定。先確認比較條件，再保留差異與原始回應追查。
