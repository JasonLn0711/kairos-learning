# M03-08 參考解答

## answer-blocking｜告警與阻擋

不夠。filtered 是掃描端無法確定入口的結果，alert 是偵測規則的通知動作。應找相同時間、來源、目的與連接埠的防護動作紀錄，例如規則 FW-17 的 Drop，再與服務端及路徑資料核對。這樣才有證據支持是哪個控制阻擋；仍不擴大成所有流量都受保護。

## answer-viewpoint｜不同來源的結果

掃描狀態依來源、路徑、時間及方法而定。內部來源可能被允許、外部來源被限制，兩者可以同時正確。先確認目標、方法與時間可比較，再對照來源政策，不能拿其中一份取代另一份。

## answer-visibility｜沒有告警

可以先查流量有沒有經過感測器可見的位置，以及告警是否成功傳到查詢介面；也可核對規則啟用狀態、時間窗、鏡像資料完整性及感測器健康。沒有告警只描述目前查到的紀錄，不證明沒有掃描或沒有入侵。

## answer-exception｜測試條件改變

停用防護會改變待驗證的條件。這種測試或許只能協助確認服務本身能否連線，不能證明原本防護有效。應另行保留正常設定下的核准測試，包含預期允許與預期拒絕案例，並記錄例外、影響與復原確認。
