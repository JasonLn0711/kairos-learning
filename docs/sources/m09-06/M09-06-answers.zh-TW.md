# M09-06｜參考解答

## 1. 原訊息提供的新電話，為什麼不算充分獨立驗證？
要求與查證電話可能同屬對方控制，因此「對方再次確認」沒有補上可信來源到特定要求的連結。改用既有、先前核實的聯絡紀錄或正式系統，確認具體資料、目的地、用途與核准。換 App 或多問一次本身不夠；可信管道也要適當維護。

## 2. DMARC 通過且抗釣魚登入，為什麼仍不能直接上傳？
DMARC 檢查網域驗證與對齊，抗釣魚驗證保護登入，兩者都不替資料移轉的用途與目的地核准。仍須獨立核實這項要求，確認分享權限、核准對象、最少資料與必要複核。真的帳號也可能被濫用，真的使用者也可能被誘導做錯事。

## 3. 已輸入密碼但尚無異常登入證據，怎麼判讀與處置？
能確認的是曾提供密碼，驗證材料可能暴露；尚不能宣稱已成功接管或已外洩資料。先透過可信入口依流程更改可能暴露的密碼並通報，保留原訊息與時間。由適當管理者核查登入、復原設定及有效工作階段，必要時撤銷存取；不等待損害才保護帳號，也不假設改密碼已處理所有登入狀態。

本檔是教材示範解答，不是使用者實際回答或理解通過紀錄。
