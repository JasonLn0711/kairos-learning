# M03-06 參考答案

## answer-ttl｜TTL 61 能確認系統嗎？

TTL 61 是接收位置看到的剩餘值；來源初始值與沿途扣減都會影響它。假設從 64 開始、每站扣 1，才可得到 3 次扣減的合成推算。不同系統與設定可能呈現相同 TTL，因此還需其他回應特徵、網路位置及管理端資料。請把實際數值與假設分開記錄。

## answer-active-passive｜主動與被動如何取得證據？

分析已合法取得的既有封包，是利用當時已發生的流量；能分析什麼受紀錄內容及觀察位置限制。Nmap -O 則會另送探測、觀察回應，屬主動辨識。兩者都需要適當授權；被動不代表可以任意收集他人的流量。

## answer-proxy｜前後端線索如何核對？

先確認外部 TCP 連線在哪裡終止。若在前端，協定堆疊指紋優先用來查核前端；服務自述另核對其實際來源與後端執行中程式。保留各自的觀察位置、時間、工具與原始回應，再以架構設定、設備版本和更新紀錄確認。線索不同可以反映不同層的設備，不必先認定其中一個結果錯誤。

## answer-confidence｜候選或無精確匹配如何記錄？

寫明「工具推測／候選」、原始名稱與分數，以及缺少的回應或工具警告。95% 的特徵比對分數不自動等於真實正確率；無精確匹配也不等於沒有作業系統。接著請授權管理者核對目標設備、完整系統與核心版本、套件修補紀錄及前置設備關係。確認前不把候選直接填成已驗證版本或弱點成立。
