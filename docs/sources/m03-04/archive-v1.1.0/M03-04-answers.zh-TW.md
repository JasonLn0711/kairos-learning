# M03-04 情境題參考答案

## answer-response-states｜1. SYN 掃描收到 RST

A. 通常分類為 closed。B. 不能因此認定伺服器關機；掃描端取得了明確回覆，還需查明回覆來自主機或中間設備。C. 核對 HTTPS 服務是否啟動、實際監聽埠與綁定位址，並查防火牆規則與同時段日誌。保留原始方法、來源及 RST。作為對照，UDP 重試後無回覆通常保留 open|filtered。

## answer-udp-uncertainty｜2. UDP 53 的兩個候選

A. 不能確認 DNS 一定啟動。B. 也不能確認一定是防火牆阻擋。服務可能忽略不符合格式的資料，也可能有去回程過濾、遺失或錯誤回報限速。C. 在核准範圍發出有效 DNS 查詢，確認實際使用 UDP，對照回覆、監聽設定、DNS 與防火牆日誌。-sV 可增加辨識機會，仍可能留下不確定性。

## answer-observation-location｜3. 管理與一般網段

A. 不矛盾，結果描述不同來源與路徑。B. 若政策只允許管理網段，這符合初步預期。C. 還需核對兩次是否為同一入口、時間與方法，並比對服務綁定、防火牆允許／拒絕規則及同時段日誌；以實際連線與應用權限確認可用範圍。單次 filtered 不能證明所有限制都生效。

## answer-ack-followup｜4. ACK Scan 的 unfiltered

A. 不能直接判為 open。B. ACK Scan 主要觀察這類探測的過濾行為，開放或關閉的入口都可能回 RST。C. 在核准範圍使用 SYN 或 TCP Connect 掃描，觀察是否接受新連線，再對照監聽設定；應用程式功能需要另行查核。

## answer-report-fields｜原有練習：補齊查核紀錄

至少補四項，例如目標 IP 與授權用途、來源網段、時間與時區、UDP 掃描方式與工具版本、等待／重試、酬載格式、原始輸出與理由。保留 UDP 53 的協定與埠號，補服務／DNS／防火牆紀錄、下一步核准查詢與負責人，讓別人能重現並接續處理。
