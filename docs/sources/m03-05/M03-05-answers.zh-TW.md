# M03-05 參考解答

## answer-port-label｜1. 入口編號與服務身分

`open` 描述這次測試取得的連接埠狀態。`https` 可能只是依埠號對照的常見名稱，也可能來自額外的服務辨識；先查明產生方式。即使取得與 HTTPS 相符的回應，也要進一步核對產品、完整版本及部署位置。比較穩妥的記錄是保留原始輸出與探測方法，將尚未驗證的產品、版本列為待確認。

## answer-null-probe｜2. 已建立連線就已接觸目標

TCP 連線建立會與目標交換網路封包，服務也可能留下連線紀錄。NULL probe 的「空」是尚未先送應用層探測內容，不是完全沒有互動。因此仍需取得授權並考慮服務影響；分析已合法取得的既有流量、沒有發出新連線，才是另一種被動觀察方式。

## answer-backend-evidence｜3. 補齊後端與修補證據

至少取得三類資料：第一，代理與後端的架構及回應產生位置，釐清字串在描述誰；第二，後端實際執行的程式、完整套件版本與供應商修訂號；第三，供應商安全公告、回補與安裝紀錄，以及弱點適用的設定條件。必要時確認服務已重新載入修補版本。把外部回應和內部證據分開記錄，再判斷是否受影響。

## answer-banner-patching｜4. 分開驗收資訊揭露與修補

隱藏版本可以標記為「已減少版本資訊揭露」，前提是調整後的實際回應已驗證。但「弱點已修復」需要另一組證據：套件與公告對照、修補安裝結果、執行中版本與必要設定檢查，並於授權範圍內完成相應驗證。兩項工作可以一起安排，不能互相代替。
