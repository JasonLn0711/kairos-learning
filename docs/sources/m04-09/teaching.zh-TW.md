**M04-09｜其他列舉：NTP、IPsec、VoIP、IPv6、BGP，看到回應後怎麼判讀？**

上一課從 LDAP 學到：查詢結果受到身分、範圍與條件限制。這一課把同樣的判讀方法用在校時、VPN、網路電話、IPv6 與路由服務，也補上 Telnet、TFTP。這是路線中的一個整合單元。

**本課要學會的事：先辨認服務的用途，再說清楚「這份回應證明了什麼、還缺什麼證據」。** 不同協定會透露不同資訊，服務有回應、資料可讀、身分驗證成功及取得操作權限，分別需要證據。

**1. 先建立一張共同的判讀清單**

Enumeration，中文是「列舉」，是在授權範圍內，依服務的回應整理名稱、角色、設定或資源等資訊。這像詢問不同櫃檯：校時櫃檯回答時間，電話櫃檯處理通話，路由櫃檯交換網路可達性。拿到一種回應，不會自動取得其他櫃檯的權限。

每次先問四件事：

- **問的是哪一種操作？** 例如向 NTP 要時間，和查詢 NTP 的管理資訊，目的不同。
- **由誰、從哪裡問？** 網路來源、使用身分與權限，可能改變結果。
- **實際收到什麼？** 保留請求、回應、時間及工具顯示，不只抄「成功」或「開放」。
- **這份結果的範圍多大？** 一個欄位、一台服務或一個觀測點，通常不足以代表整個環境。

連接埠是辨識線索。TCP、UDP 分別有自己的連接埠空間；預設埠可以更改，也可能由其他程式使用。以下的埠號用來理解常見部署，真正的服務仍要由協定回應與設定交叉確認。

**2. NTP：取得時間，和取得管理資料，是兩種能力**

NTP 是 Network Time Protocol，「網路時間協定」，讓電腦校對時間。時間正確，才有助於比對事件紀錄、排程及處理有時效的驗證。常見 NTP 使用 UDP 123。

一般校時回應會包含時間戳記與 Stratum 等欄位。Stratum 可先理解成時間同步階層：例如 stratum 2 表示位於第二層的時間伺服器。**它不是安全評分，也不是精準度或真實性的保證。** 回應內容還要配合來源、同步狀態及實際設定判讀。[NTPv4 規格](https://www.rfc-editor.org/rfc/rfc5905.html)

有些實作另有管理查詢介面，可在條件允許時回傳版本、關聯或運作狀態。「能取得時間」不表示「能讀管理資訊」。管理者也可能保留校時功能，同時限制外部管理查詢。

例如，合成紀錄顯示某伺服器回覆校時封包、stratum 為 2，但沒有任何管理查詢結果。可以說它在這次觀察中提供了 NTP 校時回應；不能寫成「已取得全部上游節點、版本及用戶端清單」。

防護上，依用途限制管理查詢來源、停用不必要功能並維護版本。對公開校時服務，還要評估限速及反射放大風險：攻擊者可能偽造來源位址，讓伺服器把回應送給受害者；是否形成放大，以及倍數多少，取決於實際請求、回應與設定，不能從 UDP 123 開放直接推出。[NTP 安全與運作建議](https://www.rfc-editor.org/rfc/rfc8633.html)

驗收時分別留下「核准用戶端仍能校時」及「未核准來源拿不到不必要管理資訊」的證據。兩者要同時滿足，才符合預期用途。

**3. IPsec／IKE：協商有回應，還沒證明 VPN 已登入**

IPsec 是 Internet Protocol Security，一組在 IP 層保護通訊的協定，常用於 VPN。VPN 是 Virtual Private Network，「虛擬私人網路」，用來建立受控的遠端或站點間連線。

IKE 是 Internet Key Exchange，「網際網路金鑰交換」。可以把它想成建立 IPsec 通道前的協商程序：雙方選擇保護方式、交換金鑰材料，並完成相應的身分驗證。常見 IKE 使用 UDP 500；配合 NAT 穿越時常見 UDP 4500。NAT 是 Network Address Translation，「網路位址轉換」。[IKEv2 規格](https://www.rfc-editor.org/rfc/rfc7296.html)

需要特別分清楚：ESP（Encapsulating Security Payload，封裝安全負載）與 AH（Authentication Header，驗證標頭）是 IPsec 的保護協定，分別使用 IP 協定編號 50 與 51。**這裡的 50、51 不是 TCP／UDP 連接埠。** ESP 在適用的 NAT 穿越情境也可以包在 UDP 4500 裡。[IPsec 架構](https://www.rfc-editor.org/rfc/rfc4301.html)

在 IKEv2，初始 IKE_SA_INIT 交換會協商演算法等資訊；後續 IKE_AUTH 才包含身分驗證的重要步驟。SA 是 Security Association，「安全關聯」，可理解成雙方使用的一組安全參數與狀態。

若紀錄只到 IKE_SA_INIT 回應，合理結論是「此端點回應了這次初始協商」。還不能說測試者已通過身分驗證、建立了可用的資料通道，或能存取公司內網。甚至已連上 VPN，也仍須逐項核對哪些內部資源獲准存取。

防護與驗證要對應不同階段：核對允許的協商方式、驗證方法及憑證，再以核准測試身分檢查通道與資源權限。保留連線狀態、驗證結果及政策紀錄，不把 IKE 封包回應當成登入成功；金鑰與驗證秘密不放入報告。

**4. VoIP／SIP：電話控制訊息，和聲音內容，要分開看**

VoIP 是 Voice over Internet Protocol，「網路語音」，讓語音透過 IP 網路傳送。SIP 是 Session Initiation Protocol，「會話初始協定」，常用來建立、修改及結束通話，像電話系統的接線流程。

SIP 常見 TCP／UDP 5060；使用 TLS 的 SIP 常見 TCP 5061。TLS 是 Transport Layer Security，「傳輸層安全協定」，用來保護這段訊令連線。服務也可採其他埠與部署方式，不能看到 5061 就直接認定實際連線已正確加密或驗證憑證。[SIP 規格](https://www.rfc-editor.org/rfc/rfc3261.html)

SIP 的 OPTIONS 等要求，可依實作與政策回傳服務能力或支援方法。不同回應有時能形成帳號或分機存在性的線索，但要核對回應語意及服務政策；收到驗證挑戰，也不代表密碼已通過，更不能直接推論可以撥打付費電話。

實際聲音常由 RTP，Real-time Transport Protocol「即時傳輸協定」，另行傳送；媒體位置與埠號依會話協商決定。SIP 是控制通話的訊號，RTP 是常見的媒體承載方式。**SIP 這一段用了 TLS，並不自動證明聲音也加密。** 媒體保護要另外核對，例如是否正確採用 SRTP，也就是 Secure RTP「安全即時傳輸協定」。[RTP 規格](https://www.rfc-editor.org/rfc/rfc3550.html)｜[SRTP 規格](https://www.rfc-editor.org/rfc/rfc3711.html)

防護重點包括限制不必要的能力與帳號資訊揭露、驗證及撥號權限、合理限速，以及分別確認訊號與媒體的保護。驗收要看設定和獲准測試通話的實際結果，不能只看伺服器支援某功能的宣告。

**5. IPv6：鄰居資訊是局部觀察，不是完整設備名冊**

IPv6 是 Internet Protocol version 6，「第六版網際網路協定」，採 128 位元位址。它不是像 FTP 一樣的單一應用服務，所以不存在一個「IPv6 列舉專用連接埠」。

同一條鏈路上的設備，會使用 ICMPv6 的 Neighbor Discovery，簡稱 ND，「鄰居探索」，處理鄰居位址解析、路由器探索等工作。ICMPv6 是 Internet Control Message Protocol for IPv6，中文是「IPv6 網際網路控制訊息協定」；NS（Neighbor Solicitation）／NA（Neighbor Advertisement）是鄰居詢問／公告，RS（Router Solicitation）／RA（Router Advertisement）是路由器詢問／公告。這些訊息扮演不同角色，不能把每個回應都當成一台新的伺服器。[IPv6 鄰居探索](https://www.rfc-editor.org/rfc/rfc4861.html)

在授權主機上查看本機鄰居快取，或分析已獲准擷取的封包，可能取得同鏈路鄰居及路由器的線索。快取反映已學到且目前保留的紀錄，**不是整個網路的完整資產清單**。設備也可能同時擁有多個 IPv6 位址；位址數量不能直接當設備數量。

例如只看到兩筆鄰居快取，可以說本機此時保存兩筆相關紀錄；要盤點所有設備，還應與授權的資產、交換器及位址管理資料比對。一般 /64 子網路的位址空間非常大，也不適合沿用「從頭到尾逐個掃描」的想法。

防護要同時維護 IPv4 與 IPv6 的政策，並保護路由器公告等關鍵控制流量。**把所有 ICMPv6 一律擋掉，可能破壞正常連線**，包含鄰居探索與路徑 MTU 探索等必要功能。MTU 是 Maximum Transmission Unit，「最大傳輸單元」，此處指鏈路可承載的最大 IP 封包大小；路徑 MTU 取決於沿途鏈路的限制。[ICMPv6 防火牆建議](https://www.rfc-editor.org/rfc/rfc4890.html)

驗收應確認不需要的流量受到限制，同時必要的位址解析、路由器探索及封包大小調整仍能運作。阻擋規則存在，和正常服務仍可用，要各有證據。

**6. BGP：看見路由公告，不代表取得路由器控制權**

BGP 是 Border Gateway Protocol，「邊界閘道協定」，用來交換網路可達性資訊與相關屬性，常見於不同自治系統之間。AS 是 Autonomous System，「自治系統」，可先理解成採共同路由管理政策的一組網路，使用自治系統編號 ASN（Autonomous System Number）識別。BGP 常見 TCP 179。[BGP-4 規格](https://www.rfc-editor.org/rfc/rfc4271.html)

路由資料中可能看到 Prefix，也就是位址前綴，以及 AS_PATH 等路徑屬性。公開 Looking Glass 或路由收集器，提供從特定網路觀測點看見的路由資訊；它們是觀測工具，不是給讀者路由器的管理登入權。[RouteViews 官方說明](https://api.routeviews.org/docs/)

例如某觀測點看見文件示意前綴 203.0.113.0/24，搭配文件示例 ASN 64496。這只用來說明欄位，並非聲稱這段位址真正在網際網路被如此公告。真實路由判讀要同時保留觀測點與時間，因為不同觀測點可能看見不同路由。[文件示例 ASN](https://www.rfc-editor.org/rfc/rfc5398.html)

AS_PATH 提供 BGP 路由屬性的資訊，不能單憑它畫出完整內部拓樸，也不能把每個 AS 直接當成封包實際經過的一台路由器。公開路由可見，不表示可以建立任意 BGP 鄰居連線或更改公告。

防護可包括限制核准的鄰居、前綴過濾與路由數量上限，避免錯誤或不合政策的公告。RPKI 是 Resource Public Key Infrastructure，「資源公開金鑰基礎建設」；配合路由來源驗證，可檢查某來源 AS 是否獲授權公告某個前綴。**來源驗證不等於整條 AS_PATH 都已驗真。**[路由來源驗證規範](https://www.rfc-editor.org/rfc/rfc6811.html)｜[BGP 運作安全建議](https://www.rfc-editor.org/rfc/rfc7454.html)

驗收要比對設定、接收或送出的路由，以及預期的過濾結果。讀到一張路由表，不足以證明這些防護正在生效。

**7. Telnet／TFTP：功能簡單，仍要分清實際可讀與可寫範圍**

Telnet 是傳統的遠端終端機協定，常見 TCP 23。連線可能顯示歡迎訊息或登入提示，形成系統用途與產品資訊的線索。看到提示不代表登入成功。傳統未加密 Telnet 不提供登入內容的機密性保護；管理用途通常應改採合適的受保護替代方式，例如 SSH（Secure Shell，安全殼層協定），可提供受加密保護的遠端管理連線；再驗證舊入口確實停用或受限。[Telnet 規格](https://www.rfc-editor.org/rfc/rfc854.html)

TFTP 是 Trivial File Transfer Protocol，「簡易檔案傳輸協定」，常見於設備開機或設定檔傳送。它以 UDP 69 接收初始請求，後續資料傳輸使用雙方選定的傳輸識別碼（Transfer ID，簡稱 TID），實際對應 UDP 埠；不能把整段傳輸都想成固定走 69。[TFTP 規格](https://www.rfc-editor.org/rfc/rfc1350.html)

基本 TFTP 沒有使用者登入驗證機制，也沒有一般檔案目錄瀏覽操作。但可取得哪些檔案、能否上傳，仍取決於伺服器、檔案與網路限制。「不需要輸入帳密」不等於「任何檔案都能下載」，更不等於可以改寫設定。

因此應限制來源、服務目錄及不必要的寫入能力，敏感檔案改用適合的受保護傳輸方式。驗收時使用管理者事先放好的無敏感測試檔，分別確認允許讀取、禁止讀取及寫入政策；讀取授權不包含試寫，也不應靠猜測真實設定檔名來擴大範圍。

**8. 把線索串起來：一份合成查核紀錄**

以下是紙上推演，沒有對任何設備連線或實測。假設管理者已提供隔離實驗環境的合成紀錄：

1. NTP 回覆一般校時要求，stratum 為 2；未提供管理查詢結果。
2. VPN 端點回覆 IKE_SA_INIT；紀錄沒有 IKE_AUTH 成功，也沒有資料通道測試。
3. SIP 服務經已驗證的 TLS 連線回覆能力資訊；未提供媒體封包與 SRTP 設定。
4. 本機鄰居快取有兩筆 IPv6 紀錄。
5. 某路由觀測點顯示一筆前綴與 AS_PATH。

依這份合成紀錄，你可以寫：「紀錄中包含校時回應、初始 IKE 協商回應、受 TLS 保護的這段 SIP 能力回應、本機兩筆鄰居紀錄及一個觀測點的路由資訊。」

接著列出待補證據：NTP 管理介面的暴露範圍、VPN 的驗證及資源權限、語音媒體保護、完整資產盤點，以及路由政策與過濾的有效設定。

這樣的寫法讓管理者知道已確認的範圍，也知道下一步該查哪一層。把五種正常回應一口氣寫成「全面入侵成功」或「全部安全」，都會掩蓋真正需要處理的問題。

**9. 一個小檢核**

只用上面的合成紀錄，請選出最有證據支持的結論，並用一句話說明理由：

A. IKE 有回應，代表 VPN 已登入並能存取內網。
B. SIP 連線採 TLS，代表通話聲音必定加密。
C. 鄰居快取只有兩筆，代表整個 IPv6 網路只有兩台設備。
D. 已確認特定操作有回應；登入權限、媒體加密及完整資產範圍仍需各自查證。

本題是原創教學題，不是官方考題。請先選擇答案並說明理由，再展開參考解答；閱讀答案不代表已確認理解。

本次練習只讀合成資料：先辨認操作、再對照實際回應、最後寫下結論與缺少的證據。沒有安裝工具或修改環境，因此沒有環境清理操作。Wireshark 這類封包分析工具可協助檢視已獲准的紀錄，但工具顯示仍須按協定與上下文判讀。真正連線測試另須先確認目標、操作、頻率、停止條件及資料保存範圍。
