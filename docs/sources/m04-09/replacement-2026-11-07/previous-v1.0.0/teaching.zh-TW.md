# CEH M04-09｜其他列舉：NTP、IPsec、VoIP、IPv6、BGP 白話文教學

這一課看起來有很多網路協定，但其實只要學會一個核心觀念，其他內容就很容易串起來：

「一台設備願意回答你的問題，不代表你能登入它，更不代表你能控制它。」

我們要學習的不是單純記住連接埠，而是理解：每一種網路服務負責什麼工作、會告訴我們什麼資訊，以及這些資訊能證明到什麼程度。

## 一、先把整個網路想像成一棟大型辦公大樓

NTP：大樓的標準時鐘

負責讓所有人的時間一致。

IPsec／IKE：大樓的安全通道

協商身分和加密方式，建立受保護連線。

VoIP／SIP：電話總機

負責接通電話、轉接及掛斷。

IPv6：辦公室的地址系統

讓設備識別鄰居及尋找路由器。

BGP：跨城市的道路資訊

告訴網路有哪些目的地可以到達。

Telnet／TFTP：舊式管理室與文件櫃

提供遠端終端機或簡單檔案傳輸。

這些都是網路的一部分，但負責的工作不同。

例如，你去問大樓的時鐘現在幾點，得到回答後，不能因此認為你已經獲得大樓的門禁卡。

這就是 Enumeration（列舉）最重要的判讀原則。

## 三、NTP：為什麼網路上的電腦需要對時？

NTP（Network Time Protocol）是網路時間協定。

你可以把 NTP 伺服器想像成學校的標準鐘。所有教室都要照同一個時間上課，否則鐘聲響了，有些教室卻認為還沒到時間。

電腦為什麼也需要對時？

假設公司的三台電腦記錄同一個事件：

| 設備    | 紀錄時間     |
| ----- | -------- |
| 防火牆   | 10:00:02 |
| 網頁伺服器 | 09:57:12 |
| 資料庫   | 10:03:30 |

如果時間不一致，資安人員調查入侵事件時，就可能誤判事件先後順序。

所以 NTP 不只是為了讓電腦右上角的時鐘正確，還關係到日誌分析、驗證機制與系統協作。

常見連接埠：UDP 123。

### 那麼 Stratum 是什麼？

Stratum 是時間同步的階層，可以理解成「這台時鐘的時間是從哪一層傳下來的」。

{{figure:stratum}}

參考時鐘可以服務多台第一層伺服器，往下也可以配置多個上游候選與同層對等關係。圖中的 Stratum 3、4 延伸這個概念；每台設備依實際選定的同步來源決定自身階層，不是每條設定連線都會同時成為有效上游。

{{figure:ntp-network}}

如果你發現某台 NTP 伺服器回答「Stratum 2」，代表它宣告自己位於第二層同步階層。

但這不表示它一定準確、安全，或者你已經知道它所有的上游伺服器。

對 CEH 而言，還有一個重要區別：正常取得時間與取得管理資訊是不同的服務能力。

伺服器可能願意告訴你現在幾點，卻不願意告訴你它的版本、設定或其他連線資訊。這是合理的安全設計。

## 四、IPsec／IKE：VPN 是怎麼建立安全通道的？

假設你在家工作，想連進公司的內部網路。

公司不會因為有人發出連線要求，就直接允許對方進入內網。

VPN 可以使用 IPsec 來保護資料，而 IKE 負責建立保護所需的協商與驗證。

{{figure:ike}}

圖中採 IKEv2。IKE_SA_INIT 與 IKE_AUTH 是訊息交換名稱，不是 IKEv1 的 Phase 1／Phase 2。第一組 CHILD_SA 通常在 IKE_AUTH 中協商；「確認資料通道可用」是後續驗證工作，不是固定另有第三種交換。安全關聯（SA）是雙方約定的保護參數與狀態；還要核對路由及存取政策。

這裡最容易犯的錯誤是：

> 我收到 IKE_SA_INIT 回應了，所以我成功登入公司 VPN！

不對。這只能證明對方回應了該次初始協商，並不能證明身分驗證成功。

而且，就算成功建立 VPN，也可能只被允許存取公司的一小部分系統。

常見的相關編號：

| 編號             | 用途              |
| -------------- | --------------- |
| UDP 500        | IKE 協商          |
| UDP 4500       | 常見的 NAT 穿越、封裝傳輸 |
| IP Protocol 50 | ESP，保護 IPsec 資料 |
| IP Protocol 51 | AH，提供封包完整性等保護   |

注意：IP Protocol 50、51 不是 TCP 或 UDP 的 Port 50、51。

這是網路基礎知識中特別值得分清楚的地方。

## 五、VoIP／SIP：為什麼電話加密了，聲音還可能沒加密？

VoIP 就是利用 IP 網路通話。

例如，企業內部的網路電話、客服中心、電話總機，都可能使用 VoIP 技術。

這裡要學會分辨兩件事：

SIP 負責建立通話，RTP 通常負責傳送聲音。

想像你要打電話給同事。

第一步，系統得先找到對方、讓對方電話響起、確認接通。這是 SIP 主要負責的工作。

第二步，接通之後，你說話的聲音才需要被持續傳送。這通常是 RTP 的工作。

{{figure:sip}}

如果 SIP 使用 TLS 加密，就像你把「電話接線指令」放進保密信封。

但你真正說話的聲音，是另外一條資料流程。如果媒體只用一般 RTP，而沒有適當保護，聲音不一定是加密的。

使用 SRTP，才是常見的媒體保護方式之一；還要確認金鑰協商及實際連線都正確。

常見連接埠是 SIP 的 UDP／TCP 5060，以及經常用於 SIP over TLS 的 TCP 5061，但不能光看 Port 5061 就斷言連線受到正確保護。

在 CEH 列舉時： 如果 SIP 服務願意回答支援哪些功能，這只是取得電話服務的能力資訊，並不表示取得分機帳號權限，也不代表可以打電話。

## 六、IPv6：為什麼查到兩台鄰居，不等於網路只有兩台設備？

IPv6 是新的 IP 位址架構，位址長度為 128 bits。

你可能在電腦中看到類似：

`fe80::1234:abcd:5678:9abc`

這是 IPv6 位址的一種形式。

### Neighbor Discovery 是什麼？

想像你搬進新社區，想知道附近有誰、路口怎麼走。

IPv6 中的 Neighbor Discovery（ND，鄰居探索）負責處理類似問題。

例如：

- NS：詢問某個 IPv6 位址對應哪個鄰居。
- NA：回應或公告鄰居資訊。
- RS：詢問有哪些路由器。
- RA：路由器公告網路設定相關資訊。

這些功能使用 ICMPv6 訊息，而不是 IPv6 專用的 TCP/UDP 連接埠。

### 為什麼鄰居清單不完整？

假設你的電腦目前有這樣的鄰居快取：

| 本機鄰居快取 | 目前紀錄 |
| --- | --- |
| 紀錄 1 | 路由器的 IPv6 位址 |
| 紀錄 2 | 某個鄰近設備的 IPv6 位址 |

你可以說：「目前快取有兩筆紀錄。」

但不能說：「這個網路只有兩台設備。」

因為其他設備可能尚未與你通訊，紀錄可能已過期，部分設備不在同一條鏈路，而且同一台設備可以有多個 IPv6 位址。

還有一個重要的資安觀念：IPv6 防火牆不能把全部 ICMPv6 都封鎖。

因為某些 ICMPv6 訊息是正常連線不可缺少的，包括鄰居探索和路徑 MTU 探索。

## 七、BGP：為什麼網際網路知道資料該往哪個方向走？

想像你在台灣，想把包裹送到美國。

台灣的物流公司不必知道美國每一條巷子的詳細地址，但要知道包裹應該交給哪個國際物流網路。

BGP 就像不同大型網路之間交換的「路線資訊」。

在網際網路中，許多網路由不同單位管理。這些在共同路由政策下管理的網路，可以用 AS（Autonomous System，自治系統）的概念來理解。

每個 AS 有自己的 ASN（自治系統編號）。

BGP 用來交換「哪些 IP 位址前綴可以經由哪些網路到達」的路由資訊。

常見連接埠：TCP 179。

{{figure:bgp}}

圖中保留雙上游、轉送網路與末端網路的關係，以文件示例 ASN 取代參考圖的 AS 100／200／400／500／600。標出的路徑是本例選定路徑；實際 BGP 選路受政策與屬性影響，不能光數線段就宣稱一定是最佳路徑。線條表示 BGP 對等關係，並非纜線位置或完整實體拓樸。

### 那 AS_PATH 是什麼？

可以先把它理解成一份路由資訊中記載的 AS 路徑。

例如某個觀測點看到：

`AS 64500 → AS 64497 → AS 64496`

這是使用文件示例範圍編號的假想路由。

它不能直接告訴你資料包實際經過哪幾台實體路由器，也無法完整重建公司的內部網路。

你可能透過公開的 Looking Glass 查到這些路由資訊，但這只代表你透過一個特定觀測點讀到資料，不代表你有權限去更改路由器設定。

BGP 的安全還會涉及前綴過濾、鄰居控制及 RPKI。

RPKI 可以幫助檢查某個來源 AS 是否被授權宣告特定 IP 前綴，但不能單靠它證明整條 AS_PATH 都正確。

## 九、一張表統整七種網路列舉

| 協定        | 常見埠或協定編號     | 你可能取得什麼資訊 | 不能直接推論什麼   |
| --------- | ------------ | --------- | ---------- |
| NTP       | UDP 123      | 時間、同步層級   | 取得所有管理資訊   |
| IPsec／IKE | UDP 500／4500 | 協商相關資訊    | VPN 登入成功   |
| SIP／VoIP  | UDP／TCP 5060；TCP 5061 | 電話服務能力    | 可撥電話、聲音已加密 |
| IPv6／ND   | ICMPv6       | 鄰居、路由器線索  | 完整設備數量     |
| BGP       | TCP 179      | 前綴、路由路徑   | 可修改路由器     |
| Telnet    | TCP 23       | 登入提示、服務線索 | 已取得終端機權限   |
| TFTP      | UDP 69 起始    | 特定檔案傳輸結果  | 可讀寫所有檔案    |

這些都是常見值，不是用連接埠就能百分之百確認協定。埠號可以更改，實際服務必須靠協定內容及設定來確認。

## 十、從 CEH 角度，怎麼把這一課應用在資安查核？

在 CEH（Certified Ethical Hacker）的學習路線裡，Enumeration 是理解目標服務所提供資訊的重要階段。

但真正專業的資安分析，不能把「工具有輸出」就當成「找到漏洞」。

例如在取得授權的測試環境中，你看到：

{{figure:case}}

這就是一份專業報告應該採取的基本邏輯：

{{figure:report}}

例如發現 NTP 的 UDP 123 正常提供時間，這可能完全符合預期用途，而不是漏洞。

真正值得調查的是：它有沒有不必要的管理資訊暴露？有沒有不符合政策的設定？必要的服務是否仍正常運作？

這樣才能分清楚正常功能、資訊揭露、設定弱點和真正可利用的安全問題。

## 十一、理解檢核：你能分清楚證據的界線嗎？

4 題情境選擇題。先選出答案，再展開各題的參考解析；這裡不儲存作答或計算學習進度。

### 1. 某台 VPN 伺服器回應 IKE_SA_INIT，代表什麼？

A. 已成功登入公司 VPN

B. 伺服器回應了初始協商，但還沒證明登入成功

C. 已取得公司內網最高管理權限

{{answer:1}}

### 2. 某間公司的 SIP 服務使用 TLS，你可以確定什麼？

A. 所有通話聲音一定加密

B. 任何人都能撥打電話

C. 該段 SIP 訊令可受到 TLS 保護，媒體仍需另外檢查

{{answer:2}}

### 3. 你的 IPv6 鄰居快取只有兩筆資料，正確的判讀是？

A. 整個網路只有兩台設備

B. 目前本機保有兩筆鄰居紀錄，不能代表完整資產

C. 其他設備一定故意隱藏自己

{{answer:3}}

### 4. 你透過公開 Looking Glass 看到 BGP 路由資訊，代表？

A. 可以更改路由器設定

B. 已經取得網路管理權限

C. 能觀察特定觀測點的路由資料，不代表有管理權限

{{answer:4}}

這一課真正要帶走的是：列舉的目的不是把看到的所有資訊都稱為漏洞，而是用有限的回應，作出有證據支持、範圍清楚的判斷。 這也正是下一課 M04-10「列舉防護」的基礎。
