問題一：兩筆 A 紀錄只表示這次 DNS 回覆提供兩個 IPv4 位址；可能是 CDN、負載平衡或已過時的配置，不能推論兩台實體主機或兩個正常網站。依授權逐層確認連線、TLS 與 HTTP 功能。

問題二：目前只能說這次沒有取得 AAAA 答案；NODATA、轉介及精簡不存在證明等情境須搭配 AUTHORITY、DNSSEC 資料、別名鏈、回覆端點及查詢條件判讀。不能由此斷言名稱存在或整個網域沒有 IPv6。

問題三：MX 提供郵件路由及優先值，不證明郵件服務健康。先確認測試範圍、來源及允許的操作，再解析 MX 目標，查核設定，依授權驗證相應的郵件協定及接收功能；不得因 MX 公開而自行寄送測試郵件或測試轉送。

問題四：REFUSED 只證明本次端點對本次來源及要求回覆拒絕。還須檢查各權威端點、DNS 視圖、允許來源、傳送存取控制與 TSIG、遞迴權限、不必要公開紀錄及日誌；一次拒絕不能代表整體 DNS 安全。
