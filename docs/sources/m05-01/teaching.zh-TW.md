# CEH M05-01｜弱點評估與滲透測試：白話文完整教學

先記住這一課最重要的觀念：

弱點評估（Vulnerability Assessment, VA）是找出安全問題、判斷風險與安排修復；滲透測試（Penetration Testing, PT）則是在授權範圍內，實際驗證攻擊者可能做到什麼程度。

兩者都在檢查資安，但回答的問題不同。

- VA：哪裡可能有問題？問題有多嚴重？先修什麼？
- PT：這些問題能不能被利用？利用後會造成什麼影響？

## 一、先用「檢查房屋安全」來理解

假設你買了一間房子，擔心小偷闖入。


第一位：弱點評估人員（VA）

他檢查門鎖、窗戶、監視器和警報器，發現後門的鎖已經老舊，可能容易被打開。

他會告訴你：「後門鎖有安全疑慮，建議優先更換。」


第二位：滲透測試人員（PT）

你明確授權他在不破壞門鎖的條件下，測試後門是否真的容易被繞過。

他成功打開門，證明「這個缺陷在特定條件下可以被利用」。

這裡有一個重要差別：

VA 發現「門鎖可能不安全」，不等於有人真的開得了門。

PT 成功開門，也不代表以前已經有小偷闖入。

這就是資安工作中非常重要的原則：可能有漏洞、漏洞可被利用、系統已遭攻擊，是三種不同的結論。

## 二、六個資安名詞，一次搞懂

現在我們把房屋換成一個購物網站。

網站有 10,000 名會員，每個會員只能查看自己的訂單。

{{figure:terms}}

這是一張概念關係圖，並不是說所有弱點必然經歷每個階段。即使攻擊尚未發生，系統也可能已經存在風險。

特別注意 Risk（風險）不等於 Vulnerability（弱點）。

假設兩台電腦存在完全相同的漏洞：

第一台是與網際網路直接連接、儲存大量客戶資料的正式伺服器。第二台是完全隔離、沒有真實資料的實驗機。

漏洞可能相同，但兩者的暴露程度、攻擊可能性與損害可能非常不同，因此修復優先順序也可能不同。

## 三、弱點掃描、弱點評估、滲透測試有什麼差別？

這是 CEH 考試與實務最容易混淆的地方。

| 名稱                            | 白話理解           | 主要回答的問題     |
| ----------------------------- | -------------- | ----------- |
| Vulnerability Scanning 弱點掃描   | 用工具找可疑的地方      | 有哪些疑似問題？    |
| Vulnerability Assessment 弱點評估 | 核對問題、判斷風險、安排修復 | 哪些是真的？先修什麼？ |
| Penetration Testing 滲透測試      | 在授權範圍內驗證攻擊路徑   | 實際可能造成什麼影響？ |

想像看醫生：掃描像是健康檢查儀器出現異常數值；弱點評估像是醫師結合檢查結果、病史與其他證據做判斷；滲透測試則是針對特定疑慮，安排受控的進一步驗證。

但這只是類比，不代表 VA 一定不能做實際測試，或 PT 一定不使用掃描工具。真正的差別在於工作目的、證據要求與授權範圍。

## 四、實際案例：掃描器說有高危漏洞，你應該怎麼辦？

假設你負責醫院內部的一套 AI 影像分析系統。

系統提供 Web 介面，供授權的醫療人員登入、上傳測試影像和查看分析結果。

某天，你用經過授權的弱點掃描器檢查系統，得到：

{{figure:scan}}

這個時候你能直接說「醫院 AI 系統有高危漏洞」嗎？

還不能直接當成已確認的結論。

### 第一步：確認工具有沒有看錯

掃描器可能只是讀取伺服器回傳的版本資訊。例如它看到 `2.4`，就推測這個版本可能有問題。

但事實上，系統可能早已套用安全修補程式，只是對外顯示的版本字串沒有改變。

因此，你需要確認實際套件、修補紀錄、受影響的功能及漏洞成立條件。

這是在排除 False Positive（誤報）。

### 第二步：確認漏洞有沒有實際風險

假設漏洞真的存在，接下來還需要問：

漏洞需要先登入嗎？外部網路接觸得到嗎？需要特殊權限嗎？成功利用會影響哪些資料？

掃描器的高嚴重度警告值得關注，但不等於每個部署環境都具有相同風險。

### 第三步：必要時進行授權滲透測試

如果醫院需要知道權限漏洞是否真的能導致越權存取，就要先確認測試授權。

例如僅在測試環境中建立兩個帳號：

{{figure:access}}

如果帳號 A 真的成功讀取 B 的測試資料，你就獲得了比版本警告更強的證據：在這次測試條件下，確實發生了越權存取。

這類問題在 Web 安全中稱為 Broken Access Control（存取控制失效），可能涉及 IDOR（Insecure Direct Object Reference，不安全的直接物件參照）。

但它仍不能證明過去有人入侵，也不能直接證明所有資料都能讀取。

### 第四步：修補之後，還要複測

修補不是只看工程師說「已經改好」。

需要重新驗證：A 能不能正常看 A001？A 是否已無法讀取 B001？其他合法功能是否仍正常？

這稱為 Retesting（複測）。前者驗證功能沒有被修壞，後者驗證權限問題確實得到改善。

其中最重要的文件之一叫做 ROE（Rules of Engagement，交戰規則）。

你可以把它想成測試人員與系統所有者簽訂的工作界線：允許測什麼、不准碰什麼、遇到異常要通知誰，以及什麼情況必須停止。

即使你已經找到一個可能的漏洞，也不代表你可以自行擴大測試範圍。

## 六、CEH 最需要建立的三種判斷能力

第一，學會區分觀察與推論。

「掃描器顯示版本 2.4」是觀察；「這個版本可能存在漏洞」是推論；「系統已經被駭客入侵」則需要完全不同的事件證據。

第二，不要把高嚴重度直接當成最高修復優先順序。

除了漏洞本身嚴重程度，也要考慮系統暴露情況、利用條件、資產價值、既有防護與業務影響。例如一個可從網際網路接觸、已知容易被利用的漏洞，往往需要比隔離系統中難以觸發的缺陷更緊急處理。

第三，理解資安的目的不只是找到漏洞，而是降低風險。

只發現 100 個警告，但沒有驗證、修補或降低風險，並不能直接代表防護變好。

一份有價值的資安報告，應讓負責人知道哪些問題已確認、證據有哪些、應先處理什麼，以及修補後如何確認有效。

## 七、理解檢核：用 CEH 分析師的角度思考

假設你檢查一套公司內部系統，弱點掃描器指出一項高嚴重度漏洞。你尚未確認修補狀態，也沒有進一步執行滲透測試的授權。

問題一：最合理的下一步是什麼？

A. 直接執行漏洞利用程式，確認能不能成功。

B. 告訴主管系統已被駭客入侵。

C. 先確認產品、修補狀態與漏洞成立條件，再決定是否申請進一步測試。

D. 沒看到資料外洩，就忽略警告。

問題二：用自己的話回答

假設滲透測試成功讀取一筆不屬於測試帳號的合成資料，這個結果可以證明什麼？又有哪些事情還不能證明？

這一課的核心能力，就是把「發現疑似漏洞」、「確認存在漏洞」、「證明可被利用」與「證明曾遭入侵」清楚分開。這不只是 CEH 考試觀念，也是實際撰寫資安評估報告時不可混淆的證據層級。
