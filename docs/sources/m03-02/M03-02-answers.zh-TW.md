# CEH M03-02｜參考解答

## answer-arp-timeout｜小檢核一

參考答案：「在指定時間與本地測試位置，收到該 IPv4 位址的 ARP Reply；本次 ICMP Echo 在設定等待期間逾時。」接著核對設備歸屬、是否有代理 ARP、ICMP 政策與路徑。ARP 回覆與 Echo 逾時各自保留，必要時由核准的服務檢查補充。

## answer-next-hop｜小檢核二

參考答案：查詢閘道的 MAC。路由表決定這一段先把訊框交給預設閘道，因此本地目的 MAC 是閘道介面；IP 封包的目的地仍是遠端目標。閘道收到後再依路由往下一站轉送。

## answer-cache-time｜小檢核三

參考答案：既有快取記錄「讀取快取的時間」，以及系統可提供的建立／更新時間或狀態；未知時間如實列待核。新收到的 ARP Reply 記實際接收時間、來源、目標及回應內容。兩者分開保存，方便理解對應關係的時效。

## answer-service-check｜小檢核四

參考答案：補做任務允許的網站服務檢查，例如核對 HTTP／HTTPS 連線與回應、TLS 憑證及預定頁面功能。依任務再檢查登入與授權。保存服務網址、方法、時間與實際結果，讓 Echo 往返與應用可用性各有證據。

## answer-nas-dsm｜理解檢核 5

兩者可以同時成立。四次 Echo Reply 證明本次 ICMP 往返通訊成功；DSM 是另一個應用服務，可能停止、設定錯誤或受存取政策限制。記錄來源、目標、時間與兩種結果，再查核授權範圍內的 DSM 連線與服務狀態。

## answer-printer-policy｜理解檢核 6

可能是政策限制 Echo、封包遺失或回程異常，仍需查核，不能直接認定原因。記錄「在指定時間與來源，以所列參數送出四次 Echo 探測，未收到預期 Echo Reply；另有同時段成功列印的觀察」。兩種證據分別描述 ICMP 與列印服務，後續對照 ICMP 政策與設備紀錄。

## answer-remote-frame｜理解檢核 7

A. IP 目的地為 203.0.113.20。B. 第一段訊框的目的 MAC 是閘道 192.168.1.1 對應的 MAC。C. 路由已選擇閘道作為本地下一站，ARP 只需解析這個下一站；一般 ARP 廣播不跨路由器。取得閘道 MAC 不能單獨證明遠端可達。

## answer-arp-lab-timeout｜整合情境 8：逾時的證據

不能只憑 ping 逾時認定 B 已關機。記錄來源、目標、時間、參數與未收到預期 Echo Reply 的結果；再查印表機實際列印／管理紀錄、ICMP 政策、路由與鏈路狀態。聲稱對應 B 的 ARP Reply 是另一筆本地位址資訊，還要核對來源與設備歸屬。

## answer-arp-lab-reply｜整合情境 9：ARP 與 Echo 分別判讀

ARP 處理本地 IPv4／MAC 解析，ICMP Echo 是 IP 診斷訊息；政策或設備行為可能允許 ARP 卻不回覆 Echo。兩者同時出現並不矛盾。Proxy ARP 或偽造回覆也可能提供聲稱對應 B 的資訊，因此仍要查核交換器、資產與代理設定，不能只靠回覆確認 B 的身分。

## answer-arp-lab-route｜整合情境 10：先看選到哪條路由

題目已指定送往 C 的路由選到 192.168.10.1，所以需要解析的是 192.168.10.1 的 MAC；有可用快取時可能直接重用。C（10.20.30.40）在遠端，一般 ARP 廣播不會跨路由器去問 C。若實際路由選擇不同，就應依該結果重新判斷，不能固定套用預設閘道。

## answer-arp-lab-frame｜整合情境 11：兩層目的地與交付證據

IP 目的地是 C 的 10.20.30.40；第一段訊框目的 MAC 屬於路由選到的閘道本地介面，也就是 192.168.10.1 的對應 MAC。這些資訊足以描述如何封裝第一段，但不能證明 C 已收到資料。路由器會繼續選路並依下一段鏈路重新封裝，遠端到達與服務成功仍需各自的觀察證據。
