**CEH M05-02｜資產盤點與評估範圍**

先記住一句：**先知道要保護什麼，再確認這次可以檢查什麼，最後才選工具。**

上一課區分弱點評估和滲透測試。假設主管說「幫公司做弱點評估」，你不能立刻掃描所有看得到的設備：公司有哪些資產，和這次獲准測哪些資產，是兩件不同的事。

**一、用房屋檢查理解**

請技師檢查漏水，先弄清楚有哪些房間、水管和設備，是「盤點」。再說清楚這次只查廚房與浴室、不拆牆、不進鄰居家，是「範圍」。看得到隔壁水管不代表可以拆；沒進某個房間，也不能說整棟都沒有漏水。

**二、資產不只是一台電腦**

Asset 是「資產」，指需要保護、具有價值的東西。Asset inventory 是「資產清冊」，記下資產、用途、負責人與狀態。

可以分成設備（筆電、伺服器、交換器）、軟體與服務（網站、資料庫、雲端服務）、資料（訂單或設計文件），以及管理身分和服務依賴。測試機若放了真實訂單，只看「測試機」這個名字，就可能低估影響。

[CIS Control 1](https://www.cisecurity.org/controls/inventory-and-control-of-enterprise-assets)強調設備盤點需涵蓋實體、虛擬、遠端與雲端環境。軟體、資料與帳號也需要相應清冊，不能只靠設備表包辦。

**三、有用的清冊應該寫什麼？**

以合成的測試網站為例，可記錄：
- 穩定資產編號：WEB-TEST-01。
- 名稱、位置及環境：測試訂購網站。
- 負責角色：網站維護組。
- 軟體與版本：由管理員核對。
- 用途與資料：以合成訂單做功能測試。
- 連線及依賴：使用測試資料庫。
- 資料來源及查核時間：方便辨別是否過時。

**IP 位址是線索，不是永久身分。**一台設備可能有多個位址，同一位址也可能在不同時間分配給不同設備。要綜合資產編號、主機名稱、雲端資源 ID 和查核時間，不能只憑 IP 合併紀錄。

**四、評估範圍是本次工作的邊界**

Assessment scope（評估範圍）要說清楚這次評估哪些對象、哪些問題，以及哪些操作不包含在內。只寫「測試公司網站」還不夠，應確認：

- 哪個網站、環境與介面？哪些主機或第三方服務排除？
- 可以用什麼測試身分？只讀檢查，還是允許修改資料？
- 從哪裡、在什麼時段執行？
- 發現服務異常、意外接觸敏感資料或遇到不明目標時，何時停止、通知誰？
- 證據保存什麼、放哪裡、由誰存取？

這些通常寫進評估計畫及 Rules of Engagement，簡稱 ROE，也就是測試執行規則。[NIST SP 800-115](https://csrc.nist.gov/pubs/sp/800/115/final)討論授權目標、排除項目、允許活動、資料處理及事件應對。第三方環境也要處理對方的同意和限制。

**資產在公司清冊裡，不代表這次可以測；掃描器看得到，也不代表獲准測。**

**五、完整走一次合成案例**

公司有測試網站 A、正式資料庫 B、外部金流 C。這次只授權檢查 A 的安全設定與版本。你在 A 的設定中看到它連向 B，網頁也導向 C。

正確做法：把 B、C 記成依賴；對照授權確認兩者不在範圍內；只檢查獲准的 A；必要時向負責人提議另行評估 B、C。報告寫「A 的指定項目已檢查，B、C 未測」，而不是「整個訂購系統安全」。

觀察是「A 的設定提到 B」；推論是「B 可能影響整體風險」；是否獲得測 B 的授權，是另一件事。

**六、沒有發現，不等於不存在**

清冊可能漏掉已離線的筆電、臨時建立的雲端主機，或只在特定網段可見的服務。某次掃描沒找到，不代表不存在。

可交叉比對管理清冊、雲端資源清單、軟體管理紀錄和獲准蒐集的網路資訊。資料衝突就標「待確認」。保留誰確認歸屬、何時核對版本、哪些已納入及哪些未評估的證據，才能避免誇大覆蓋率。

**五分鐘紙上練習**

列出合成的測試網站、正式資料庫與外部付款服務，替各自寫用途、負責角色、資料類型和來源。圈出唯一獲准測試的網站，再寫兩個排除目標與停止條件。這只是紙上練習，不是真實授權文件，也不需連線任何系統。

**小檢核**

你在獲准測試的網站中看到另一台資料庫的位址，但它不在授權範圍。你會怎麼記錄，下一步做什麼？

核心是能回答：**我測的是誰、憑什麼可以測、結果能代表多大範圍。**接著我會給你 M05-03。
