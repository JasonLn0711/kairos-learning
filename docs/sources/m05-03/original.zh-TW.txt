# CEH M05-03｜弱點分類與評估類型：白話文完整教學

這一課最重要的觀念是：

「系統哪裡有問題」、「要從哪裡檢查」與「有沒有證據證明問題存在」，是三件不同的事。

你可以把弱點評估想成醫生替病人健康檢查。

醫生不能只看病人有沒有發燒，就宣布他完全健康。同樣地，資安工程師也不能只跑一次弱點掃描，就宣布系統沒有安全問題。

## 一、先理解：什麼是弱點（Vulnerability）？

假設你經營一間銀行。

銀行裡有金庫、監視器、保全、門禁系統及員工。

某天發現銀行有安全問題，可能是以下五種原因：

1\. 設計缺陷（Design Flaw）

銀行最初設計時，就沒有規定誰能進入金庫。

問題出在「制度或系統規則一開始就沒設計好」。

2\. 實作缺陷（Implementation Flaw）

銀行規定只有經理能進入金庫，但工程師寫門禁程式時，忘記檢查身分。

問題出在「規則正確，程式卻寫錯」。

3\. 設定錯誤（Misconfiguration）

門禁系統本來有身分驗證功能，但管理員把它設成所有人都能進入。

問題出在「功能正常，設定卻不安全」。

4\. 尚未修補的已知缺陷（Unpatched Vulnerability）

門禁廠商發現某個版本有安全漏洞，已經發布更新，但銀行還沒安裝。

問題出在「已經有修補方法，卻還沒完成修補」。

5\. 管理與流程缺口（Process Weakness）

某位經理已經離職，但銀行沒有註銷他的門禁權限。

問題出在「人員管理或維護流程不完善」。

這五種問題都可能讓未經授權的人進入金庫，但是修正的方法完全不同。

這就是為什麼要做「弱點分類」。

弱點分類的目的，不是背五個英文名詞，而是找到真正原因，決定應該由誰修正。 而且分類可能重疊，例如軟體沒更新，也可能同時代表維護流程失效。

## 二、弱點評估類型：我們究竟要檢查什麼？

接著把銀行換成一套公司的資訊系統。

這個系統可能同時具有伺服器、網路、網站、資料庫、Wi-Fi 與雲端儲存。

不同位置要採取不同的檢查方式。

概念示意：同一套系統可以從多個層級進行安全評估，這些檢查彼此互補。

| 評估類型             | 白話文       | 主要檢查什麼               |
| ---------------- | --------- | -------------------- |
| Host-based       | 檢查電腦本身    | 作業系統、更新、權限、設定        |
| Network-based    | 檢查網路出入口   | 開放的連接埠、服務、暴露範圍       |
| Application      | 檢查網站及程式   | 登入、身分驗證、授權、程式邏輯      |
| Database         | 檢查資料庫     | 帳號、資料存取權限、安全設定       |
| Cloud / Wireless | 檢查雲端與無線環境 | 雲端資源權限、Wi-Fi 保護、網路隔離 |

例如：

你掃描一台 Web Server，發現作業系統已經更新到最新版本。

這能代表網站一定安全嗎？

不能。

因為作業系統的漏洞與網站程式的漏洞，是不同的事情。

即使伺服器完全更新，網站工程師仍可能把授權邏輯寫錯，讓 A 使用者看見 B 使用者的資料。

所以，Host-based Assessment 沒發現問題，不代表 Application Assessment 也不會發現問題。

Internal Assessment

內部評估

在取得授權後進入大樓，檢查內部門禁、區域隔離與權限。

換成資安情境：

外部評估可能是在授權條件下，從 Internet 觀察公司的網站、VPN 或其他對外服務。

內部評估則可能從公司內部的指定網段，檢查內部伺服器與服務的存取限制。

重要的推理是：

外部看不到某台資料庫，只能代表「這次外部檢查沒觀察到它」，不能代表資料庫不存在，更不能證明它安全。

另外，Internal / External 說的是測試位置，並不是檢查者是不是公司員工。

## 四、Active 與 Passive：怎麼檢查？

這裡最容易混淆。

假設你想知道一間房子有沒有人在裡面。

Active 主動式

你主動敲門、按門鈴，看看是否有人回應。

Passive 被動式

你觀察現有的監視畫面或進出紀錄，不主動敲門。

在資訊系統中：

- Active Scanning：工具主動向目標發送測試請求，根據回應判斷服務、版本或可能的弱點。
- Passive Assessment：分析既有網路封包、日誌或其他觀察資料，不透過主動探測取得回應。

兩者各有侷限。

主動式可能獲得更多直接證據，但也可能增加系統負載，甚至影響老舊服務。

被動式通常不會因為探測請求增加目標負載，但如果相關事件沒有發生、沒有被記錄，或不在觀察範圍內，就可能完全看不到。

而且被動觀察也可能涉及敏感資料，並不是不需要授權。

## 五、還有兩組很重要的分類

Authenticated / Unauthenticated（是否使用帳號驗證）

假設你檢查一間飯店。

Unauthenticated 就像沒有房卡的訪客，只能看到公開大廳。

Authenticated 則像持有獲准房卡的人，可以檢查授權範圍內的房間與設施。

在資安評估中，具身分驗證的掃描通常能取得更多系統內部資訊，例如已安裝套件與設定。但具備帳號，不代表擁有所有存取權限。

Automated / Manual（由工具還是人來檢查）

Automated 像自動體檢機器，適合大量、重複且可規則化的檢查。

Manual 像醫生親自問診，適合需要理解情境、業務邏輯及判斷例外的問題。

實務上通常兩者搭配。

## 六、所有分類其實是不同的維度

這是一個很重要的整合觀念。

假設主管要求你檢查公司內部的 Linux 伺服器，並提供獲准的掃描帳號。

你可能同時選擇：

同一場弱點評估的五個維度

1

檢查對象

Host-based

Linux 伺服器

2

檢查位置

Internal

從內部網路檢查

3

取得證據

Active

主動發送探測與檢查請求

4

驗證身分

Authenticated

使用核准的掃描帳號

5

執行方式

Automated

先以工具執行重複檢查

這五種標籤完全不衝突，因為每一種都在回答不同問題。

也就是說，評估類型不是單選題，而是可以組合的檢查策略。

## 七、實際案例：掃描器說有問題，代表一定能入侵嗎？

假設某套公司訂單系統出現以下結果。

| 發現             | 目前知道什麼      | 還需要確認什麼              |
| -------------- | ----------- | -------------------- |
| A：套件版本偏舊       | 可能有已知漏洞     | 實際版本、修補狀態、是否符合漏洞成立條件 |
| B：資料夾允許匿名讀取    | 某項設定可能不符合政策 | 哪些資料可讀、預期權限、實際影響     |
| C：A 帳號讀到 B 的訂單 | 有跨帳號存取的具體現象 | 是否違反原定授權規則、影響範圍      |

我們可以把弱點評估理解為逐步累積證據的過程：

發現線索

工具回報套件可能有漏洞

核對成立條件

確認版本、設定、影響條件及政策

授權範圍內驗證

必要時進行受控測試並記錄結果

評估影響、修正與複驗

確認缺陷是否修正，正常功能是否保留

要特別分清楚：

- 發現可能的弱點，不等於證明弱點可被利用。
- 證明存在可利用的弱點，不等於證明系統已經遭人入侵。
- 修正一個弱點，也不等於整套系統已經安全。

另外，Severity（嚴重程度）不等於 Priority（處理優先順序）。前者關注可能造成多大傷害；後者還要衡量暴露情況、資產重要性、現有防護和修正急迫性。

例如，一個能直接讓外部訪客讀取敏感資料的設定錯誤，可能比只在特定內部條件下才會觸發的高分漏洞，更需要優先處理。

## 八、最後用一句話串起 M05-01、M05-02、M05-03

| 課程               | 核心問題                 |
| ---------------- | -------------------- |
| M05-01 弱點評估與滲透測試 | 我們要找出問題，還是進一步證明實際影響？ |
| M05-02 資產盤點與評估範圍 | 有哪些資產？這次獲准檢查哪些？      |
| M05-03 弱點分類與評估類型 | 問題可能出在哪裡？應該用什麼角度檢查？  |

因此，一次專業的弱點評估，不是「開啟掃描器、按下開始、拿到報告」就結束。

而是先確定資產與授權範圍，再選擇適合的評估方式，辨認問題成因、核對證據，最後提出修正與驗證方法。

## 九、理解檢核：用一個案例測試是否真正學會

1\. 某公司網站的作業系統完全更新，但使用者 A 可以讀取使用者 B 的私人訂單。這比較可能是哪一種弱點？

A. 設定錯誤

B. 設計或實作上的授權缺陷

C. 未修補的作業系統漏洞

2\. 你使用經過授權的帳號，從內部網路透過工具主動檢查 Linux 主機。這同時符合哪些分類？

A. External、Passive、Unauthenticated

B. Internal、Active、Authenticated、Automated

C. Internal、Passive、Unauthenticated

3\. 掃描器沒有找到已知版本漏洞，是否可以宣布系統安全？

A. 可以，代表沒有弱點

B. 不行，因為設定、權限與應用程式邏輯仍可能有問題

C. 可以，只要掃描器是最新版本

提交答案並查看解析

這三題涵蓋本課最核心的能力：辨識弱點原因、組合評估方式，以及判斷安全證據的限制。
