## 原理與教學界線

- M04-01：[SIGCHI](https://sigchi.org/about/) 的跨學科研究與實務、[NN/G UX 定義](https://www.nngroup.com/articles/definition-user-experience/) 的整體經驗與 UI 區別，以及[易用性原則](https://www.nngroup.com/articles/ten-usability-heuristics/)。三種觀點可重疊，並非互斥職稱或固定階段；美觀、程式通過與任務改善保留不同證據範圍。
- M04-02：[NN/G Task Analysis](https://www.nngroup.com/articles/task-analysis/) 支持目標、資料蒐集／分析、子任務條件及實際情境。圖示是分析者走讀順序，不冒稱完整 HTA，也不把子任務列表當成所有人必經的錯誤流程。沒有蒐集真人時間或認知負擔數值。
- M04-03：[NN/G IA 與導覽](https://www.nngroup.com/articles/ia-vs-navigation/)、[W3C 標籤](https://www.w3.org/WAI/tutorials/forms/labels/)與[Meaningful Sequence](https://www.w3.org/WAI/WCAG22/Understanding/meaningful-sequence.html)。資訊分組、導覽外觀、視覺優先序與程式閱讀順序分開；標籤的視覺鄰近不等於程式關聯，獨立卡片也未必只有唯一順序。
- M04-04：[GOV.UK 原型指南](https://www.gov.uk/service-manual/design/making-prototypes) 區分草圖與可操作原型。本課沿既有 CEH 閱讀版型，不採用 GOV.UK 的外觀或工具。四狀態是替代情境，處理中僅對真實等待適用；下載 SVG 是繁中靜態參考，不建立檢核、鍵盤、響應式或輔助科技行為。
- M04-05：NN/G 原則只作檢查方向。漸進揭露依目前決策安排次要資訊，缺漏、失敗與必要狀態直接顯示；不加入假等待。輸入修改後使結果失效或匯出時重驗，仍要落到規格與處理程式，不能只隱藏按鈕。
- M04-06：[W3C 表單通知](https://www.w3.org/WAI/tutorials/forms/notifications/)、標籤、[Keyboard](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html)、[Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)及[Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)。資料缺漏、技術失敗、過期結果分開復原；動態通知依實作及急迫性測試。保留鍵盤路徑例外的適用條件，不以 Tab 可達、ARIA 字樣或截圖宣稱完整 WCAG 驗收。
