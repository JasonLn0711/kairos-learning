# M02-01｜Token、Transformer 與 Attention：AI 到底是怎麼讀懂文字、產生回答的？

這一課要解決一個很重要的問題：

為什麼 AI 可以回答得非常流暢，甚至能寫程式、分析文件，卻仍然可能一本正經地說錯話？

答案要從 AI 如何處理文字開始理解。

先記住一個核心觀念：AI 不是直接拿人類的文字來思考，而是把文字轉換成數字，透過大量數學運算，產生接下來的內容。

## 一、先看完整流程：AI 收到一句話後，發生什麼事？

假設你對 AI 說：

> 請幫我檢查這份申請資料，有沒有缺少必填欄位。

整個處理流程可以簡化成：

你輸入文字

「請檢查申請資料」

Tokenizer

① 切成 Token

把文字分成模型能處理的單位，再轉為編號

② 轉成向量，加上位置資訊

讓文字成為可運算的數字表示

③ Transformer 運算

Attention、其他神經網路層反覆處理資訊

④ 預測下一個 Token

算出各種可能輸出的機率，依生成策略選擇

⑤ 形成回答

「這份資料缺少文件類型。」

注意：最後這句回答可能是對的，也可能是錯的。流程本身沒有保證 AI 已經按照你的業務規則完成驗證。

接下來逐一拆解。

## 二、Token 是什麼？把它想成 AI 使用的文字零件

人類看到：

「申請資料不完整」

通常會直接理解它的意思。

但 AI 模型不能直接拿中文字進行矩陣運算，必須先把文字換成可計算的表示。

第一步就是 Tokenization（Token 化）。

想像你在玩樂高。

一個完整的城堡不是單一零件，而是由許多小積木組成。同樣地，文字也會先依照分詞器的規則，轉成較小的單位。

每個 Token 都會對應一個 ID，就像每個積木都有自己的編號。

有三個觀念很重要：

- 一個中文字不一定是一個 Token。
- 一個 Token 也可能包含多個字，或是部分字元的位元組序列。
- 不同 AI 模型使用的 Tokenizer 可能不同，因此同一句話的 Token 數量也可能不同。

這為什麼重要？

因為 AI 的輸入長度限制（Context Window）及許多 API 費用計算，都和 Token 數量有關。

## 三、向量（Vector）是什麼？為什麼要把文字變成一串數字？

假設模型已經把「文件」轉成一個 Token ID。

但光有編號還不夠。

例如你的身分證號碼是一串數字，但光看那個號碼，並不能直接知道你的工作或喜好。

所以模型還會把 Token ID 轉成一組數字，稱為 Embedding（嵌入向量）。

想像每個文字零件都被賦予一張有很多欄位的數字卡片。

「文件」的假設性向量

### 0.2

### −0.7

### 1.1

### 0.4

實際模型的向量通常有更多維度。這些數字僅用於教學，不表示真實的 Token 向量。

這些數字是模型用來運算的表示，不是人類預先訂好的欄位，例如「重要性＝0.2」。

而且，文字的順序也非常重要。

「主管把文件交給承辦人」和「承辦人把文件交給主管」，雖然使用幾乎相同的字，意思卻不同。

因此模型需要 Position Information（位置資訊），才能區別文字排列及其關係。不同 Transformer 架構會用不同方式加入位置資訊。

## 四、Attention 是什麼？為什麼 AI 要參考其他文字？

這是今天最重要的部分。

想像你是一位承辦人，看見以下資料：

> 申請編號：SYN-001
>
> 申請人：DEMO-A
>
> 文件類型：沒有填寫

有人問你：「這份申請資料完整嗎？」

你不能只看見「申請編號」與「申請人」都填了，就回答完整。

你必須把「文件類型」與「沒有填寫」連在一起理解，再對照必填規則。

Attention 的作用，就是在計算某個位置的資訊時，讓模型可以參考其他可見位置的資訊，並決定如何加權組合。

不過要注意：Attention 並不是人類的注意力，也不保證模型真正理解你的業務規則。

### Query、Key、Value 是什麼？

可以先用圖書館查資料的方式理解。

# Q

Query：我要找什麼？

像讀者拿著查詢需求，準備比對線索。

# K

Key：有哪些可以比對的線索？

像每本書的索引資訊，用來判斷匹配程度。

# V

Value：要取回什麼資訊？

像根據匹配程度，從各本書取得並組合內容。

在真正的 Transformer 裡，Q、K、V 都是模型透過數學運算產生的向量。

流程是：

1. 使用 Query 和 Key 計算匹配分數。
2. 經過 Softmax，轉換為加總等於 1 的權重。
3. 使用權重，對 Value 做加權組合。
4. 得到新的資訊表示，交給後續神經網路處理。

這就是 Self-Attention 的核心機制。Self-Attention 指的是序列內的位置彼此參考，而不一定是參考外部資料。

你會發現：

- A 的分數比較高時，結果會比較靠近 2。
- B 的分數比較高時，結果會比較靠近 6。
- A 和 B 分數相同時，兩邊各占 50%，結果就是 4。

特別注意：分數是 0，不代表權重就是 0。 Softmax 比較的是相對分數。

真實模型的 Value 是向量，而不是這裡的單一數字；這個小實驗只是讓你看懂加權組合。

## 六、Transformer 是什麼？Attention 是其中一個重要零件

現在我們知道 Token、向量和 Attention 了。

那 Transformer 又是什麼？

可以把 Transformer 想成一整座資訊處理工廠，Attention 是其中一種重要的處理設備。

除了 Attention，典型的 Transformer 還有：

- Feed-Forward Network（前饋網路）：對每個位置的表示做更複雜的非線性轉換。
- Residual Connection（殘差連接）：讓資訊與梯度更容易通過多層網路。
- Normalization（正規化）：幫助維持數值與訓練穩定性。
- Multi-Head Attention（多頭注意力）：讓不同注意力頭各自學習不同的資訊關係。

模型會經過多層計算，逐步形成適合後續預測的表示。

不是所有 Transformer 都一模一樣。像 GPT 類的文字生成模型，通常使用 Decoder-only Transformer；其他模型也可能採用 Encoder-only 或 Encoder–Decoder 架構。

### 那 AI 為什麼是一個字、一個字慢慢回答？

更精確地說，它通常是一個 Token 接著一個 Token 地產生。

例如生成：

「這份資料缺少文件類型。」

模型在每一步，都根據目前可見的內容計算下一個 Token 的機率分布，再依照生成策略選擇。

接著把新 Token 加進上下文，繼續計算。

這稱為 Autoregressive Generation（自回歸生成）。

你可能會問：既然只是預測下一個 Token，為什麼還可以做推理或寫程式？

因為模型在大量訓練中，不只是學到相鄰文字，也可能學到語法、知識關聯、程式結構及複雜的問題解決模式。不過，具備這些能力仍不代表每次輸出都可靠。

## 七、最重要的觀念：AI 很會回答，不等於回答是真的

這裡要分清楚三件完全不同的事情。

| 概念           | 它回答什麼問題？                | 能否直接證明正確？ |
| ------------ | ----------------------- | --------- |
| Attention 權重 | 這次運算如何組合其他位置資訊？         | 不能        |
| Token 生成機率   | 在目前上下文下，哪些 Token 較可能產生？ | 不能        |
| 結果驗證         | 輸出是否符合真實資料、規則與證據？       | 需要另外檢查    |

回到收件資料的例子：

申請編號有填，申請人代號有填，但「文件類型」是空白。

AI 可能產生很流暢的回答：

> 這份資料已全部填寫完成，符合審核要求。

句子看起來專業、沒有文法問題，卻可能同時犯了兩個錯誤：

第一，它沒有正確指出必填欄位缺漏。

第二，它把資料完整性和正式審核通過混為一談。

這就是為什麼開發 AI 協作系統時，不能把模型的文字輸出直接等同於業務事實。

如果你要設計可靠的收件系統，必填欄位判斷最好由可測試的程式規則執行，而不是只依靠 AI 自行判斷。 AI 可以負責解釋缺漏、協助整理或提供修正建議。

例如：

原始申請資料

程式規則驗證

檢查申請編號、申請人代號及文件類型是否都已填寫

驗證結果：缺少文件類型

AI 協助使用者理解

「目前無法標記為完整，請補上文件類型。」

這也連接到 M01 學過的觀念：人負責定義規則與驗收條件，AI 可以協助執行部分工作，但完成與否必須有證據。

## 八、今天真正需要記住的六句話

1. Token：AI 處理文字的基本單位，不一定等於一個字。
2. Embedding：把 Token 轉成可供神經網路運算的向量。
3. Position：讓模型能區分文字的順序。
4. Attention：計算不同位置資訊如何加權組合。
5. Transformer：整合 Attention、前饋網路及其他組件的神經網路架構。
6. Verification：AI 產生的答案仍需要透過規格、資料或外部證據驗證。

如果只能記住一個觀念，就是：

Token 是處理單位，Transformer 是運算架構，Attention 是其中的資訊組合機制；但它們都不能取代事實查證。
