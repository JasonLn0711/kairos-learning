## 原理與課堂應用

- M03-01：[NN/G 易用性原則](https://www.nngroup.com/articles/ten-usability-heuristics/) 支持狀態與錯誤預防的檢查，不替代使用者研究。問題陳述、漏水類比及三欄位案例為原課程的合成設計；觀察、推論、行動及未確認假設各自保留。
- M03-02：[GOV.UK 訪談](https://www.gov.uk/service-manual/user-research/using-in-depth-interviews) 建議開放中立問題、故事與追問；[研究規劃](https://www.gov.uk/service-manual/user-research/plan-user-research-for-your-service) 建議把未有依據的觀點改成問題，再選角色及方法。五角色表與 SYN-I01 全是合成教具，沒有真人訪談；角色盤點不授予資料權限，規則衝突交由適當角色確認。
- M03-03：[discovery 指南](https://www.gov.uk/service-manual/agile-delivery/how-the-discovery-phase-works) 支持理解更大流程及相關團隊；[experience map 指南](https://www.gov.uk/service-manual/user-research/creating-an-experience-map) 以使用者經驗形成跨步驟／角色圖。本課主流程、分支表與四張事件卡是紙上設計，不冒稱組織 SOP、真人旅程研究或架構實作。
- M03-04：[alpha 指南](https://www.gov.uk/service-manual/agile-delivery/how-the-alpha-phase-works) 著重以原型測試高風險假設，discovery 允許依證據決定停止。課程只採這些方法，不把英國行政階段、時間或審查要求移植成臺灣課程規定。第一版／延後／本版不做是課程分類；十人共用、正式受理及對外通知均保留獨立啟動條件。
- M03-05：[GOV.UK 指標指南](https://www.gov.uk/service-manual/measuring-success/how-to-set-performance-metrics-for-your-service) 支持由服務目的與假設選量測、交代基準及情境，搭配研究。四筆缺漏、三筆阻擋的 3/4 = 75%、兩位合成參與者的一次無提示完成，以及零分母都是紙上算例，不是程式測試、真人研究或因果改善證據。

逐節對照原主張、數字、條件、角色與答案。五份 Markdown 範本沿既有 code 欄位逐位元保留繁中；英文前文與區塊說明逐項解釋用途及紀錄內容，讓英文讀者能自行形成對應 problem.md。沒有變更課程欄位、共用版型、工作坊 ZIP、SVG 或指定工具。
