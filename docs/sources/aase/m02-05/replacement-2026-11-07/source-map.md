## 編輯決策及界線

1. 六面向保留舊版「本課規劃」教學框架限定，不宣稱通用產業標準或六套獨立程式。
2. 原文「六種完全不同的故障來源」改為六個檢查入口，保留後文多因性，避免與 Tools／Security 交叉案例矛盾。
3. 最後一句改為模型提供理解、推理、生成能力，Harness 影響可靠、可控、可驗證的工作；不將聰明程度歸因於單一因素。
4. 原稿邀請即時逐題評估改為先自行回答再展開參考答案，符合靜態網站能力。三題仍是開放題，沒有新增選項、評分或送出。新 Q04～Q06 避免沿用舊 Q01～Q03 的不同語意。
5. 參考答案是編輯補充，並非使用者供稿或學員答案；第一題接受有證據的替代診斷。實作保留 architecture.md 設計練習，情境同步改為週末第三科；未執行實際 Agent 或網站維修。
6. 來源查核 2026-11-07：[MCP Tools 2025-06-18](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)支持工具描述、呼叫、錯誤及實作安全責任；[Building effective agents](https://www.anthropic.com/research/building-effective-agents)支持工具／流程分工、環境回饋與停止條件。引用固定文章與規格版本，未將其稱為最新產品能力。
