# M04-06 供稿抽換來源紀錄

本次目標：以使用者完整供稿抽換 AI 協作軟體工程 M04-06「錯誤復原、可近用與易用性」，並依五張附圖製作隨文圖解。

## 保存與採用狀態

- `source.zh.txt`：逐位元組保存原供稿，包含原連結、格式逸出與對話結尾。
- `image-1.png` 至 `image-5.png`：依附件順序保存五張原圖。
- `prior-lesson.json`：修改前的正式資料 v1.0.2、revision 3；原發布日 2026-11-05。
- `SHA256SUMS`：以上七份檔案的 SHA-256。雜湊只證明保存一致。
- 目前狀態：source preserved、正文與五圖 adopted、validated、published；本機驗收與正式發布證據見[回執](../../../../releases/2026-11-11-aase-m04-06-replacement.md)。

正本由 kairos-learning 持有；本次稀缺資源為逐小節編輯與圖意／瀏覽器驗收時間。Planning 僅在狀態或下一步改變時承接定位、驗證與發布回執，不複製供稿與圖檔。既有其他課次與共用元件的未提交修改保留，發布時需隔離本次範圍。

## 圖解設計與原圖關係

| 附圖 | 關係與必留訊息 | 採用位置與驗證重點 |
| --- | --- | --- |

| 2 | 未上傳收入證明；其他資料保留；補件後重新檢查 | 第一節同情境正例；保留示範訊息標示 |

| 4 | CMS 頁首摘要、欄位連結、就地錯誤與保留值；數字為圖上註記 | 可近用性顏色小節；重製教學示意需署來源，不能把姓氏字數或美式日期說成通用規則；不把示意控制項冒充實際送出服務 |
| 5 | 輸入→處理→判斷；缺漏／技術失敗與成功為兩個分支；修改輸入後重新驗證 | 第四節；手機保留分支與條件，不排成「失敗→成功」的必經序列；輸入版本失效另明示 |

## 查核與編輯界線

2026-11-11 回讀 CMS error-validation、W3C WCAG 2.2 Use of Color／Keyboard，以及 WAI Labeling Controls 官方頁。已確認這些頁面可讀；正式採用時仍需逐項連結到正文的技術主張。

- [CMS 表單錯誤](https://design.cms.gov/patterns/Forms/error-validation/)
- [WCAG 色彩](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)
- [WCAG 鍵盤](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html)
- [WAI 標籤](https://www.w3.org/WAI/tutorials/forms/labels/)

原稿的 favicon／搜尋介面殘留不作正文插圖；保留在原檔以供追溯。`\*\*資料一致性…` 的格式逸出需在採用稿正規化。原稿結尾「你回答後，我會逐項評估」屬對話承諾，正式頁改採原生參考解析，不建立虛構評分服務。郵遞區號、CMS 姓氏及日期格式須依實際服務規則，不能宣稱所有地區通用。醫療與銀行情境為合成教學案例，不建立臨床或金融建議。
