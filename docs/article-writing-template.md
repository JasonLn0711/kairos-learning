## 逐章逐小節對照

有供稿的抽換、補充或完整修訂，沿用來源紀錄填寫；已有對照檔可在此連結，不必重複建立。列到實際教學小節與情境分支，不能僅列章名。每列的「核對結果」須根據正文閱讀與比對，不以標題數或關鍵字代填通過。

| 原文章／小節及來源位置 | 成稿位置／錨點（雙語適用時列兩語） | 保留的解釋、案例、步驟與其他內容 | 實質修正／合併理由與依據 | 核對結果／漏項 |
|---|---|---|---|---|
| | | | | 尚待核對 |

另記錄原文到成稿、成稿到建置頁、正式頁回讀各自的證據。自由改寫核對意義與教學深度；逐字採用核對全文及明列修正。相同來源檔不免除使用者更正要求後的重新驗收。

依序記錄 320、390、768、1280 CSS px、無 JavaScript、鍵盤及 200% 文字放大。程式測試、視覺閱讀、實體裝置與正式部署分開記錄。私人材料留在忽略的本機目錄。

圖解交付補充：依 [FIG-04／05](diagram-design-system.md)記錄參考圖的節點、資料格、線型與分層；選擇受審核版型，附桌面／手機對照、SVG 邊界及鍵盤下載結果。可執行範例填入實測平台、命令、輸出、錯誤碼與清理。

M02-06 模式檢核：依[網路圖解與互動準則](diagram-design-system.md#m02-06-網路圖解與互動準則)記錄手機重排後的平行／方向／條件語意、雙語及 HTML／搜尋／SVG 一致性；互動另附邊界與非法輸入測試、結果核對和靜態預設畫面。既有測試入口可復用，驗收結果填本次實測。

## 同頁補充與最終驗收工作表

依[WRITE-12–15、FIG-07、CODE-01、PUB-01–02](article-standards.md#contextual-supplement)填寫；已有逐節採用／驗收檔時在欄位連結即可。適用範圍外填「不適用＋理由」，未實測填「尚待檢查」，不以範本預填通過。

| 項目 | 本次填寫與證據位置 |
| --- | --- |
| 目標文章／穩定URL／語言／原版號 | |
| 實收來源／原圖／前版／缺件 | 區分實際附件與供稿聲稱另附的資料；雜湊及原稿位置 |
| 讀者語氣與完整教學 | 先備知識與目標；公開措辭調整；原理、案例、步驟、條件與限制是否保留 |
| 相應內容正下方的位置 | 原定義／段落 → 新錨點；原清單若拆分，原項目與閱讀順序核對 |

完成後回到上方「逐章逐小節對照」及「交付紀錄」，核對來源 → 模型 → 建置 → 正式站的證據是否逐層成立。純規範更新則驗文件、連結與Git發布，記錄未變更教學頁面；不用文書盤點代替實際文章驗收。
